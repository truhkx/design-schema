# Package conventions — DesignSchema (SwiftUI, iOS)

Read this instead of the whole package. Open at most two files if a detail is missing: `packages/swiftui/Sources/DesignSchema/Button.swift` (the reference component) and the one existing component closest to what you are writing.

- **Files.** `packages/swiftui/Sources/DesignSchema/<Name>.swift` declaring `public struct <Name>: View` plus its nested option enums, its `Overrides` type and `#Preview` blocks. One file per component; helpers go in `Support/` only when two components need them. The doc's `behavior` scenarios are **not** written by hand: `tools/behavior_tests.ts` derives `Tests/DesignSchemaTests/Generated/<Name>BehaviorTests.swift` from them, and those files are committed so the macOS gate can compile them.
- **The initializer is a contract the generated tests call.** `public init` takes the doc's props **in the doc's order**, each with the doc's default as its default argument, then the event closures in the doc's order, then `overrides: [Binding: TokenRef] = [:]`. Enum cases are the doc's values camel-cased (`icon-only` → `iconOnly`); a value that starts with digits moves them to the end, because nothing else is a Swift identifier (`2xl` → `xl2`); values that are quoted digits also accept `Int`. A prop whose doc entry narrows `platforms` away from `swiftui` is not a parameter at all.
- **Toolchain.** Latest stable Swift and Xcode (Swift 6.3 / Xcode 26.6 at the time of writing); strict concurrency; deployment target is the current iOS major minus one. SwiftUI and Foundation only — no third-party package may be added to `Package.swift`. UIKit is imported only inside `#if canImport(UIKit)` for what SwiftUI lacks (`UIPasteboard`).
- **Tokens.** `@Environment(\.dsTheme) private var theme` from `DesignSchemaTokens`. Keys are camelCase (`theme.colorActionPrimaryBackground`, `theme.spaceSm`, `theme.fontSizeMd`, `theme.radiusMd`, `theme.borderWidthFocus`, `theme.opacityDisabled`, `theme.motionDurationFast`); colors are `Color`, dimensions `CGFloat` (points), durations `TimeInterval`, easings `Animation`, weights `Font.Weight`, line heights unitless multipliers (`lineSpacing = fontSize × (lineHeight − 1)`). The theme resolves light/dark by `colorScheme`; never branch on the scheme in a component. Interpolated bindings use a lookup keyed by the enum (`private static let tone: [Tone: KeyPath<Theme, Color>]`). No literals for size/color/duration: `tools/lint_literals.ts` flags a bare number anywhere inside `.padding(`, `.frame(`, `.cornerRadius(`, `.lineSpacing(`, `.font(.system(size:`, `Color(`, `.opacity(`, `.animation(` or `.zIndex(`, on one line or spread over several. `0`, `1`, `2` and fractions (`0.5`) are allowed; anything else needs `// literal-ok: reason` on that line. `.font(theme.fontBody)` is the way to set type — reach for `.font(.system(size:))` only when a token supplies the size.
- **Overrides.** `overrides: [Binding: TokenRef] = [:]` where `Binding` is the component's own `enum Binding: String` listing only overridable bindings, and `TokenRef` is the generated token-name enum. `theme[ref]` resolves a `TokenRef` to a typed value (`theme[ref].color`, `.dimension`, `.duration`); use it in place of the binding's default. No `.modifier` or style parameter is accepted. Overrides change values, never presence: a prop that turns a part off makes that part's overrides no-ops.
- **Spacing between siblings** is never padding on a child: `Stack` spacing (`theme.layoutGap*`), `Box`/`Card` inset (`theme.layoutInset*`), `Container` gutters. A resolved token path ending in `.default` drops it (`theme.colorBackground`).
- **Layout.** `VStack`/`HStack`/`ZStack`/`Grid`/`LazyVGrid`/`ScrollView`; never `List`, `Form` (SwiftUI's) or `NavigationStack` inside a component — those belong to the app. "Collapses below the prose width" is a `ViewThatFits` or a `GeometryReader` against `theme.layoutMaxWidthProse`, never `UIScreen`. Dynamic Type: font-size tokens are read through `@ScaledMetric(relativeTo:)` so they scale.
- **Accessibility.** The root is one element where the doc's role says so (`.accessibilityElement(children: .combine)` for a button-like thing, `.contain` for a group, `.ignore` + own label for a drawn control). `.accessibilityLabel` from the doc's accessible-name rule; `.accessibilityValue` for ranges and states with no trait (expanded, mixed, "current step"); `.accessibilityHint` for the doc's hint text; traits: `.isButton`, `.isLink`, `.isHeader`, `.isSelected`, `.isModal`, `.isStaticText`, `.isImage`, `.updatesFrequently`, `.isSummaryElement`; `.accessibilityAddTraits`/`.accessibilityRemoveTraits` to switch them. Announcements: `AccessibilityNotification.Announcement(String(localized:)).post()`. Decorative glyphs: `.accessibilityHidden(true)`. Disabled: `.disabled(true)` (SwiftUI removes the control from the focus order — the doc's "focusable but disabled" rule is met with `.accessibilityRespondsToUserInteraction(false)` and a press guard instead, and `.opacity(theme.opacityDisabled)`). `.accessibilityIdentifier("<Name>")` on the root, `"<Name>.<part>"` on parts — anatomy names verbatim. This tree *is* the behavior gate: the generated `<Name>BehaviorTests.swift` finds parts by those identifiers (falling back to the root, since `.combine` folds parts into it), reads `then.state expanded` as `.accessibilityValue("expanded")`/`("collapsed")`, `selected` as the `.isSelected` trait, and `disabled` as an element the tree reports as not enabled.
- **Focus.** VoiceOver focus via `@AccessibilityFocusState`; hardware-keyboard focus via `@FocusState` and `.focusable()`. Return-focus and trap semantics (FocusScope) come from `Support/FocusScope.swift`. Focus ring: `.overlay` stroke of `theme.borderWidthFocus` in `theme.colorBorderFocus` drawn only when `@Environment(\.isFocused)`/`@FocusState` says so and the focus came from a keyboard (`.focusEffectDisabled()` on the native ring, then draw ours).
- **Keyboard.** The doc's `keyboard` table is implemented for iPadOS/Catalyst hardware keyboards with `.dsOnKeyPress(_:action:)` (`Support/Testing.swift` — it installs SwiftUI's own `.onKeyPress(keys:)` and registers the same handler where the behavior gate can reach it; nothing in a `swift test` process can synthesize a key event), `.onKeyPress(characters:)` for type-ahead, `.onExitCommand` for Escape, `.onMoveCommand` for arrows where the container is focusable, and `.focusSection()` to keep Tab inside a widget. Roving tabindex = one `.focusable()` container whose `@FocusState` index the arrows move. Touch equivalents are always present: what the keyboard table does, a visible control or an `.accessibilityAction`/`.accessibilityAdjustableAction` also does.
- **Overlays.** Dialog/AlertDialog: `.sheet`/`.fullScreenCover` (phones) or `.popover` (regular width) as the doc says, `.interactiveDismissDisabled` where the doc forbids scrim dismiss, `.presentationBackground(theme.colorOverlaySurface)`; BottomSheet: `.sheet` + `.presentationDetents` + `.presentationDragIndicator`; ActionSheet: `.confirmationDialog`; Menu: `Menu`/`.contextMenu` per the doc; Popover: `.popover(attachmentAnchor:arrowEdge:)`; Tooltip: `accessibilityHint` + long-press; Toast: `Support/Portal` overlay at `theme.layerToast`. The scrim, when custom, is `theme.colorOverlayScrim`.
- **Forms.** Fields register with `FormContext` (`@Environment(\.dsForm)`): `{ name, label, getValue, validate, focus }`; values `String | Bool | Double | [String] | ClosedRange<Double>`. Precedence `error` → `required` → `invalid`. Labels are the component's own `Text` above the field (no `LabeledContent`); `.accessibilityLabel` carries the label when hidden.
- **Motion.** `withAnimation(theme.motionEasingStandard.speed(...))` using the component's `transition` binding; nothing animates when `@Environment(\.accessibilityReduceMotion)` is true.
- **Composition.** Use `Button`, `Link`, `Text`, `Heading`, `Icon`, `Stack` from the package; never restyle a child (no `.foregroundStyle`/`.font` applied from outside; pass the child's own props or `overrides`). Icons come from `Icon(name:)` for every glyph; never draw a glyph inline or use SF Symbols (the glyph set must match the other platforms).
- **Icon glyphs come from `tools/icon-paths.json`**, the one table every platform draws from. `Sources/DesignSchema/Icon+Paths.swift` is generated from it by `pnpm icons` and must never be hand-edited (`pnpm icons:check` fails the build if it is); `Support/SVGPath.swift` turns a glyph's `d` into a `Path`. `Icon` looks its `Name`'s `rawValue` up in `IconPaths.table` and draws `IconPaths.shape(name)` — stroked at `theme.borderWidthFocus` with `.round` caps and joins, or `.fill(style: FillStyle(eoFill: true))` when the entry is `filled` — never a `Path { }` closure of its own. The shape scales to its frame and the stroke does not (`stroke(lineWidth:)` is in points on the already-scaled path), which is the web's `vector-effect: non-scaling-stroke`: line glyphs keep that thickness at every `size`, so pass the token straight through and never divide it by the size. `Tests/DesignSchemaTests/IconSnapshotTests.swift` renders every glyph through an `ImageRenderer` and compares it against the browser's own render of the same `d` (`tests/icon-snapshots/`), so a glyph drawn any other way fails the Mac gate.
- **Dev warnings** use `#if DEBUG` + `assertionFailure` for contract violations the docs name and `print("[DesignSchema] …")` for advisory warnings.
- **Previews / gallery.** `#Preview("Default")` plus one `#Preview("<Prop><Value>")` per enum value and notable state; the gallery app (`apps/ios-gallery`) renders `Gallery.entries` and never names a component. Each component ships `Sources/DesignSchema/Gallery+<Name>.swift` — `public extension Gallery { static var <name>Screen: GalleryEntry { GalleryEntry("<Name>") { … } } }` (`buttonScreen` for `Button`) — and `tools/generate.ts` rewrites `Support/Gallery+Generated.swift` from those files after every generation round; that one is never hand-edited.
- **Rows and options are data** (`[Row]`, `[Option]`), never child views, so `ForEach` renders them and accessibility can count them.
- **Parts and overrides.** An override for a composed child's binding is passed to that child's `overrides` (Fieldset → Stack `gap`, Divider → Text `fontSize`, Alert → Icon `color`/`size`); never resolve a token on the child's behalf.
