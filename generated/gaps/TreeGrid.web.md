# Gaps reported while generating TreeGrid for web

Each entry is a place the doc made the generator guess. Fix the doc, re-run parse, regenerate.

## 2026-09-10 14:22 — round 1

- TreeGrid's own copy block has no strings for the sort-button label, selection summary, row-count, empty-state, or edit-mode announcement that its behavior explicitly reuses 'as DataGrid'; borrowed DataGrid's exact copy text for these (kept in a separate BORROWED_COPY const) rather than inventing new user-facing strings.
- copy.level ('Level {level}') and copy.childCount ('{count} items') have no described use on the web platform — aria-level/aria-setsize/aria-posinset already carry that information natively, and only the RN platform notes explicitly compose an accessibilityLabel from them — so they're defined but unused here; using them as redundant visible/AT text would have been guessing.
- copy.expandAll / copy.collapseAll ('Expand all' / 'Collapse all') have no corresponding anatomy part (no expand-all control is listed), so they're defined but unused.
- The schema gives TreeGrid a `selectable`/`selectChildren`/`onSelectionChange` but no controlled `selected` prop (unlike DataGrid). Selection is implemented as internal state only; a consumer cannot drive selection from outside.
- The schema gives TreeGrid `sort` but no `defaultSort` (unlike DataGrid). Implemented `sort` as fully controlled: clicking a sortable header always calls `onSortChange`, and the visible order only changes once the caller reflects the new value back through `sort`.
- guideLine styling draws one continuous vertical segment per ancestor depth down every descendant row (VS Code-style indent guides) rather than elbow connectors that stop at a subtree's last child — the spec says a guide runs 'under each open parent' but doesn't specify termination/branching behavior.
- DataGridColumn's `pinned` and `resizable` fields (inherited through the reused `DataGridColumn[]` shape) are accepted by the type but not implemented — no sticky pinned columns, no column resizing — since the schema calls out sort explicitly as reused DataGrid behavior but says nothing about pinning/resizing for TreeGrid.
- Parent/descendant/sibling lookups used by `selectChildren` cascading, ArrowLeft-to-parent, and the `*` expand-siblings key walk the full `data` tree per call (O(n)) rather than a precomputed id map; only row rendering/virtualization is optimized for the 'hundred thousand leaf rows' scale the guidance calls out.
- The header is always sticky; DataGrid exposes a `stickyHeader` toggle but TreeGrid's schema has no such prop, so it's hard-coded on rather than configurable.
- Shift+Space row-range selection does not cascade into descendants even when `selectChildren` is true (only the visible rows in the range are selected) — the spec doesn't define how range-select and cascading selection should interact.

## 2026-09-16 12:04 — round 1

- TreeGrid: web guidance says 'build on DataGrid's implementation (a shared hook or base, not a copy)', but the task is scoped to TreeGrid files and DataGrid.tsx has no extractable hook; chose a self-contained implementation mirroring DataGrid's structure, importing only the DataGridColumn type.
- TreeGrid: the keyboard table lists only Tab, arrows, Home/End, Enter, *, F2, Escape, Space, Ctrl+A, Shift+Space and says 'nothing else'; DataGrid's PageUp/PageDown, type-to-edit, Delete/Backspace clearing and Shift+Arrow column resize are therefore omitted (Shift+Arrow explicitly keeps navigation meaning). Column resize is pointer-only, so onColumnResize has no keyboard path — likely an accessibility gap the doc should resolve.
- TreeGrid: Home/End with Ctrl says 'first / last visible row of the grid'; DataGrid's Ctrl+Home goes to the header row. Chose the first/last body row.
- TreeGrid: Enter on a row header 'toggles expansion (or activates a control inside it)' — the precedence for a leaf row header is unspecified; chose toggle for parents, and for leaves DataGrid's order (edit if editable, else activate a control).
- TreeGrid: onCellChange's value/previous are typed string | number | boolean with no undefined, but an editor can produce no value (cleared number input) and a cell can be empty; chose to coerce undefined/null to ''.
- TreeGrid: `defaultExpanded: ["*"]` 'expands every loaded row' — unclear whether lazy rows count; chose rows with non-empty loaded children only, so no onExpand fires without a user act. Also applied `*` in the controlled `expanded` prop (undocumented) and resolved it to concrete ids in onExpandChange payloads.
- TreeGrid: a row with `children: []` — chose leaf (no expand button, no aria-expanded).
- TreeGrid: `*` fires onExpand for each newly expanded lazy sibling and one onExpandChange; relative order of onExpand vs onExpandChange is unspecified — chose onExpand first (matching the scenario's listed order). No event fires when nothing new expands.
- TreeGrid: copy.selectedRows/rowCount `total` is 'how many rows the treegrid has' — chose every loaded row at every level, while aria-rowcount counts visible rows + header (per the aria-rowindex note). The two numbers differ once rows are collapsed.
- TreeGrid: selectChildren's derived state reads 'checked when all, indeterminate when some, else its own id' — chose: descendants all selected → checked even if the parent's own id is absent; row aria-selected mirrors the shown checked state (false when indeterminate). Toggling a shown-checked row clears own + descendants, otherwise sets them.
- TreeGrid: style binding `indent` has `part: indent` but the web notes say 'indent as padding on the row header'; chose a data-part="indent" spacer element at the start of the row header (width indent × (level − 1)), which is visually equivalent and gives the part a hook.
- TreeGrid: guide lines — guidance says a ::before on child rows; drawn as one ::before per nested row with a repeating gradient (one line per ancestor level) offset by the selection column + cell padding + half of expandButtonSize. They do not follow a pinned row-header column during horizontal scroll.
- TreeGrid: DataGrid bindings TreeGrid inherits 'as DataGrid' (cell padding, header weight/size/border, grid lines, fixedHeight, status bar, caption size/weight, fonts) are not in TreeGrid's styles block, so they are not overridable here; used DataGrid's default tokens as fixed values. `height: fixed` has no fixedHeight override (DataGrid's `overrides.fixedHeight`) and is fixed at space.20.
- TreeGrid: composition lists expandButton: Button (ghost, sm, iconOnly) but not its props beyond that; passed overrides paddingInline/paddingBlock space.0 so the button fits a compact row inside the size.target.min slot (as DataGrid does for the sort Button), plus label from copy.expand/collapse even though the button is aria-hidden. The chevron rotation is applied to a TreeGrid-owned wrapper span around Icon (not the Icon itself); in RTL the collapsed chevron is mirrored.
- TreeGrid: the lazy placeholder row needs aria-level/setsize/posinset ('on every row'); chose level+1, setsize 1, posinset 1, one gridcell spanning all columns. It is keyboard-reachable; ArrowLeft on it moves to the parent header.
- TreeGrid: Caption Heading receives overrides marginBlockEnd space.0 and size md (DataGrid's treatment) — not listed as composed props for TreeGrid's caption part.
- TreeGrid: the schema lists onEditStart as cancelable 'by returning false or calling preventDefault() on the event it receives', but its payload is (rowId, column) with no event; only `return false` is supported.
- TreeGrid: copy.level, childCount, expandAll, collapseAll are unused on web by design (per guidance); noted so the gate does not flag them.

## 2026-09-17 14:38 — round 1

- TreeGrid: "A lazy id listed explicitly stays collapsed until the user opens it" sits in the `defaultExpanded` description, and the doc only says `"*"` is honoured the same way in controlled `expanded` — it never says whether a lazy id in controlled `expanded` is also suppressed. Chose to suppress in both modes (tracking which lazy rows the user opened), which means a caller cannot expand a lazy row programmatically at all.
- TreeGrid: no `columnWidth` default is declared, and it is in neither the overridable nor the locked list, yet `columns[].width` is optional. Chose DataGrid's columnWidth default (`calc(space.20 * 2)`) as an internal, non-overridable custom property.
- TreeGrid: `copy.level`, `copy.childCount`, `copy.expandAll` and `copy.collapseAll` are in the Copy contract ("use every copy.* string verbatim") but the guidance says they are native-only with no web control. Chose to omit them from the web COPY table rather than ship four unused constants.
- TreeGrid: the keyboard table gives Enter on a parent row header as "toggles expansion" and names F2 as the edit path for an editable parent row header, but does not say what Enter does on a parent row header in a *non*-row-header editable column vs. the row header itself when both apply. Chose: Enter on the row header of a row with children always toggles, never edits.
- TreeGrid: the `*` rule does not say whether it opens `"lazy"` siblings. The onExpand description ("`*` fires one onExpand per newly opened lazy row") implies it does, so lazy siblings are opened and each fires onExpand; note this contradicts `defaultExpanded: ["*"]`, which never opens a lazy row.
- TreeGrid: no `rowCount` prop or `onRangeNeeded` event is declared, though virtualization is "as DataGrid" and DataGrid pages in from the server through them. Chose to omit server paging entirely — only the loaded `data` is virtualized, and `copy.rowCount`/`selectedRows` count loaded rows only.
- TreeGrid: `height: viewport` has no declared binding (only `fixedHeight` is listed). Chose DataGrid's `calc(100vh - 2 * layout.gap.section)` applied to the whole component with the scroll region flexing, so the caption and status bar stay visible.
- TreeGrid: `onCellChange.value`/`previous` are typed `string | number | boolean | undefined` with `undefined` meaning cleared, but the doc does not say what a cell holding a non-primitive (a value the column `render`s) reports. Chose DataGrid's `String(value)` coercion, `undefined` only for null/undefined.
- TreeGrid: the guide line is specified as "drawn inside the row header cell (so they move with it)" but must also span the full height of every descendant row. Drew it as a `::before` on the row, offset by the selection column width — equivalent only because the schema requires the `isRowHeader` column to come first; if that column were pinned or reordered the lines would detach from it.
- TreeGrid: the platform note says the chevron rotation goes "on a span TreeGrid owns around the Button", but that same span is the `expandButton` part hook and the pointer target, so the rotation transforms the whole Button box rather than only the glyph. Harmless for a square icon-only Button, but the doc does not say whether a separate, unhooked wrapper was intended.
- TreeGrid: `copy.selectedRows.total` and `copy.rowCount` count every loaded row at every level while `aria-rowcount` counts visible rows plus the header, so the status bar routinely reports a larger number than the grid's own row count. Implemented as written; the doc does not flag the discrepancy as intentional.

## 2026-09-21 21:38 — round 1

- TreeGrid: the web platform notes say the `expandButton` span carries aria-hidden="true" to hide the Button as a descendant, which directly contradicts the package rule that aria-hidden never wraps a focusable control (the rule names TreeGrid's expand control as its example) and contradicts the doc's own RN notes ('it is not hidden from accessibility here, because a focusable control inside an aria-hidden wrapper is an axe failure'). I left the Button exposed under copy.expand/collapse. The web note needs to be corrected to match RN, or the rule needs an explicit TreeGrid exception. Note axe reports this as `incomplete`, not a violation, with tabindex=-1, so no gate enforces either choice.
- TreeGrid: the keyboard block says Shift+Space with a no-longer-visible anchor is 'a plain, non-cascading toggle of the focused row', but the `selectChildren` prop description says 'Space, Enter on the select cell, a click on its Checkbox and Ctrl/Cmd+click are all the row's own toggle and cascade'. For the Shift+Space fallback these disagree; I implemented the keyboard block (non-cascading). The selectChildren description should state the exception.
- TreeGrid: anatomy and composition declare `statusBar: Text`, but the bar also needs a wrapper holding the row-count / selection-count / scroll-hint / position Texts, and the doc never says which element carries data-part="statusBar". I put it on the live status Text and left the bar itself unparted, as DataGrid does.
- TreeGrid: copy.position defines row as 'the active cell's row number among the visible rows (the active row + 1), so it agrees with aria-rowindex'. These cannot both hold: with the header at aria-rowindex 1, visible data row i has aria-rowindex i+2 but position i+1. I implemented the literal '(the active row + 1)'. Confirm which is intended.
- TreeGrid: the guideLine binding says the lines are 'Drawn inside the row header cell (so they move with it)', but `.ds-tree-grid__cell` sets `overflow: hidden` and the row-header column may be pinned, which clips them. I draw them as a ::before on the row element with an inline offset that accounts for the selection column. The binding's description should say the row, not the cell.
- TreeGrid: the lazy placeholder is specified as a navigable row 'with copy.loading in the row-header column and the other cells empty', which implies one cell per column. I render a single gridcell spanning all columns (aria-colindex=1, grid-column 1/-1), which is simpler but leaves the row's cell count inconsistent with aria-colcount. Confirm whether N real empty cells are required.
- TreeGrid: the RN notes state that pressing a row header with children toggles it and never selects the cell, `selectable: "cell"` included, but no web rule covers a pointer click on a row header with children. On web, Enter toggles while a click currently selects the cell without toggling, so the platforms diverge. The web notes should say what a click on a parent row header does.
- TreeGrid: `numericFont` is one of the bindings the doc says 'applies at DataGrid's own default token', but the doc never says whether DataGrid's *condition* for it (raw value is a number and the column has no `render`) carries over too. I matched DataGrid's condition; the prior build keyed it off `align: end`, which is a visible difference for a text column aligned end.

## 2026-09-23 13:55 — round 1

- TreeGrid: 'A click on a row header of a row with children toggles it and never selects the cell' does not say whether Ctrl/Cmd+click or Shift+click on that row header still toggle or extend the row selection in `row` mode (selectChildren says Ctrl/Cmd+click is the row's own toggle). Chose: any press on a parent's row header only expands or collapses, with no selection of any kind; leaf row headers and other cells keep DataGrid's Ctrl/Shift+click selection.
- TreeGrid: when the user collapses a lazy row they had opened, the spec doesn't say whether a controlled caller that keeps the id in `expanded` should see it open again. Chose: the row stays marked as user-opened for the component's lifetime, so the controlled `expanded` prop decides alone.
- TreeGrid: the placeholder row's select-column cell is not described. Chose: an empty, pinned gridcell with no data-part and no Checkbox, since the placeholder is not selectable.
- TreeGrid: platforms.web says the caption part is 'a span TreeGrid owns around' a Heading, which puts an h2–h4 inside a span (phrasing content). Kept the span to match DataGrid, with display:block.
- TreeGrid: onEditStart is `cancelable` but its payload is positional (rowId, column) with no event object, so the 'calls preventDefault() on the event it receives' path has no event to call it on. Supported returning false only.
- TreeGrid: expandButton is a wrapper around the composed Button, and the React convention says a press on a part wrapper is forwarded to the Button with button.click(). Here the row-header cell's own click toggles the row (the spec's 'click on a row header toggles it'), so forwarding would toggle twice. Chose: no forwarding; the cell's click handler covers both the wrapper and the Button.
