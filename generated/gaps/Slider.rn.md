# Gaps reported while generating Slider for rn

Each entry is a place the doc made the generator guess. Fix the doc, re-run parse, regenerate.

## 2026-09-10 18:53 — round 1

- Slider: the schema's `snapToMarks`, `required`, and `invalid` props were absent from the pre-existing implementation (drag-to-marks was inferred from `step` being left `undefined`, a workaround not in the schema). Added the real `snapToMarks` boolean (step now defaults to 1 per spec, keys always use `step`, drag/click snap to marks only when `snapToMarks` is set), plus `required`/`invalid` with the schema's `error` → `required` → `invalid` precedence and `copy.required`/`copy.invalid`.
- Slider: `invalid`/`required` have no dedicated visual token in the schema's `styles` block (unlike Input's border-color treatment), so a failed slider looks identical to a valid one until `errorMessage` renders — chose not to invent an unlisted color rather than reuse a locked binding.
- Slider: no `copy.*` entry defines a visible '(required)' label suffix (only the required/invalid *messages* are specified), so — unlike Input's convention — the label text is left unmodified when `required` is set.
- Slider: PageUp/PageDown/Home/End from the keyboard table have no native gesture equivalent; exposed them as custom `accessibilityActions` ('pageup'/'pagedown'/'home'/'end') alongside `increment`/`decrement`. Only increment/decrement get the native VoiceOver swipe / TalkBack volume-key binding — the other four surface in the platform's generic 'Actions' menu, a platform ceiling rather than an implementation gap.
- Slider: mapped the Forms doc's `validate: blur` (defined explicitly only for toggles) onto a drag/interaction's end (`onSlidingComplete`) as the closest analogue to blur for a pointer-driven control; this interpretation isn't spelled out for Slider specifically.
- Slider: the Keyboard story previously combined a plain slider with a range slider (3 thumbs); corrected it to render only the range form per the doc text ('The Keyboard story renders the range form... the three-focusable rule does not apply').

## 2026-09-16 09:19 — round 1

- Slider: the Home/End/PageUp/PageDown custom accessibility actions need a label for the platform Actions menu, but copy has no strings for them; I used the key names 'Home', 'End', 'Page Up', 'Page Down' (unlocalised, not from copy). increment/decrement take no label.
- Slider: `marks` says 'Values snap to marks when `step` is omitted' but `step` has default 1, so omission only shows as the prop being undefined; I snap drag (and page by mark) when snapToMarks is true or step is undefined, and keys still move by step (1).
- Slider: the tests start from the Default story args, which set step: 1 explicitly, so the step-omitted mark snapping is never exercised by a scenario.
- Slider: `invalid` description says copy.invalid shows 'when no error', and the invalid-renders-the-invalid-copy scenario needs it to render outside a Form; `required` only shows its copy after Form validation. I display: error prop → Form's error → copy.invalid when invalid. The doc doesn't say whether required copy should also render standalone.
- Slider: the `errorText` binding is overridable, but the composed Text's tone=danger colour is locked; I apply the override by rendering the message at tone default inside TextForegroundContext with the resolved colour. The doc names no child forward for errorText (nor for valueSize on the bubble, which I forwarded as the bubble Text's fontSize).
- Slider: bubble padding, the distance of the bubble above the thumb, and the gap within the label row have no binding; I used space.1 block / space.2 inline padding, the bubble sitting size.target.comfortable above the thumb centre line, and partGap for the row gap.
- Slider: the focus ring's geometry isn't specified; I draw focusRingWidth in focusRing as a circular border on the 44px hit area (minTarget), transparent when unfocused.
- Slider: 'the track click moves the nearest thumb' (web notes, Behavior) has no RN counterpart in the rn notes (PanResponder per thumb only); I did not implement tap-on-track on native.
- Slider: the Form contract's FormFieldValue has no number variant, so a single value registers as its string and a range as a [low, high] string pair, despite valueType number-range.
- Slider: `disabled` is described as 'readable and focusable but inert'; the generic rule 'disabled sets accessibilityState in addition to disabled' doesn't apply to a View thumb, so the thumb stays focusable with accessibilityState.disabled and the gesture and actions are ignored.
- Slider: example stories must render 'exactly its given', but the meta args (label Volume, defaultValue 40, step 1) would leak into an args-only story, so the four example stories use render functions with exactly their given props.
- Slider: all behavior scenarios with interactions are web/lit only, so no RN test covers onValueChange/onSlidingComplete via accessibility actions or the range no-cross clamp; the 7 RN scenarios are render/copy/name checks only.

## 2026-09-21 15:37 — round 1

- Slider: props.name says the form value types "have no number" so a value registers as String(value) and a range as two strings — but the rn FormContext's own FormFieldValue documents `number` ("NumberInput, Slider") and `[number, number]` ("a range Slider or DatePicker") as members. Followed the doc and registered strings; the FormContext JSDoc is now stale for Slider and one of the two must move.
- Slider: onChangeEnd is specified as "pointer up, key released", but native has neither for an accessibility action, which is an atomic change with no separate end. Chose to treat each increment/decrement/pageUp/pageDown/home/end action as a complete interaction: onValueChange then onSlidingComplete, both only if the value changed.
- Slider: showValue `hover` is defined as "pressed or focused" and "any focus counts", but a core RN View emits onFocus/onBlur only on react-native-web and TV — on a phone the bubble is press-only. Tracked focus state anyway so the web-rendered Storybook behaves per spec; on device the focused half of the rule is unreachable.
- Slider: thumbActiveScale is described as a halo on "the pressed thumb", but native has no hover and no press state distinct from a drag. Chose to show the halo while a gesture owns that thumb (including a track press that grabbed it) and not on focus alone.
- Slider: the mark label row says each label is "centred under its mark" but never says what happens when two labels collide or when the first/last label overflows the track ends. Chose absolute positioning with a -50% translate (mirrored in RTL), no collision handling and no edge clamping, so labels at min/max hang past the track.
- Slider: trackPaddingBlock (space.3) around a space.1 rail makes the track area shorter than minTarget (size.target.comfortable), so the thumb's hit View overflows the track area vertically. The doc says trackPaddingBlock exists so "the touch target reaches the comfortable size" but not whether the row should reserve the full target height. Left the hit area overflowing (RN does not clip) rather than growing the row.
- Slider: both the thumb and the track area need a PanResponder, and the doc does not say which wins when a press lands on a thumb. Chose the thumb's (it is a child and claims the gesture first), so a press on a thumb drags from its current value instead of jumping to the press position; only presses outside a thumb use nearest-thumb-jumps-here.
- Slider: `required` for a range says "a value other than the default", without saying whether moving one thumb is enough. Chose: any difference in either component of the pair satisfies it.
- Slider: Home/End on a range thumb — copy.homeAction/endAction say "minimum"/"maximum" but not whether that is the scale's bound or the live constraint from the other thumb. Chose the live constraint, so the actions can never cross the thumbs.
- Slider: the rn notes name the labels for the page/home/end custom actions but not their `accessibilityActions` action names. Chose `pageUp`, `pageDown`, `home`, `end` alongside the standard `increment`/`decrement`; a consumer or test matching on action names has nothing in the doc to match against.
- Slider: with accessibilityHint carrying the error/description onto each thumb, the visible description and errorMessage Texts are still in the reading order, so a screen reader hears each twice (once as the thumb's hint, once as text). The doc does not say to hide either; left both readable.

## 2026-09-23 14:39 — round 1

- Slider: the bubble must size to its content on one line and may overflow the thumb's hit area, but Yoga and react-native-web size an absolutely positioned child within its parent's width (the 44px hit area), so multi-word values wrap. Text exposes no nowrap/numberOfLines without ellipsis. I placed the bubble in an invisible strip five hit areas wide (start/end: -200%); a formatted value wider than that still wraps.
- Slider: focusRing shows 'only while the thumb has keyboard focus', but RN has no focus-visible and react-native-web focuses the thumb on pointer press. I treat a focus that arrives after the thumb's responder start as pointer focus (no ring) and reset that on blur; the doc does not say how RN tells keyboard focus from pointer focus.
- Slider: 'when both range thumbs share a value, a press before it moves the low thumb, after it the high thumb' is written for track presses, but at a shared value the upper thumb paints on top and its PanResponder claims the press first, so the low thumb could never be dragged away from max. I applied the same before/after/on rule to presses inside the stacked thumb's hit area, measured from the knob centre (mirrored in RTL).
- Slider: aria-invalid, aria-required, aria-describedby and aria-orientation have no React Native prop spelling. They are passed as a web-only attribute record (Platform.OS === 'web'), following Listbox; natively, error identification rests on the hint and the live error region. The doc says 'error identification is asserted on aria-invalid on the thumb' without saying how that applies on native.
- Slider: a single thumb is named both by accessibilityLabel/aria-label (the digest's 'both spellings' rule) and by aria-labelledby pointing at the label's nativeID (the web a11y note). The doc does not say whether RN should carry both; aria-labelledby wins on web, and the name is identical.
- Slider: the doc says the label row and mark label row 'take any press that lands on them', but the thumb's 44px minTarget also overflows into the description/error rows when there are no mark labels (track area is 28px, gap 4px). I gave those rows zIndex 1 too, so they take the press as well; the doc does not cover them.
- Slider: the Constants and examples contract says each example story has 'exactly its given as args', but CSF3 merges story args over meta args. I reduced meta.args to the two required props (label, name) so the merge adds nothing; the doc could say that the Default story's args must be only the required props.
- Slider: the value Text beside the label is hidden from accessibility (the thumb's valuetext already announces it) as before; the doc hides the bubble explicitly but says nothing about the always-shown valueText, so I kept it hidden to avoid a duplicate announcement.
