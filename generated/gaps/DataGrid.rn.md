# Gaps reported while generating DataGrid for rn

Each entry is a place the doc made the generator guess. Fix the doc, re-run parse, regenerate.

## 2026-09-10 14:05 — round 1

- DataGrid: `selectable: 'range'` has no touch or hardware-keyboard equivalent on native (no drag-rectangle gesture, no Shift+Arrow); it degrades to `'row'` with a `__DEV__` warning, per the platform notes' own guidance. `rangeOverlay`, `rangeBackground`/`rangeBorder`/`rangeBorderWidth` bindings and `copy.selectedRange` are consequently unreachable on this platform.
- DataGrid: Ctrl+C copy-as-TSV has no implementation — core React Native ships no clipboard API and the package permits no extra dependency (only react-native-svg). `copy.copied` is defined for API/copy parity but never surfaces.
- DataGrid: the `date` editor has no package `DatePicker` to compose (the rn package doesn't have one, unlike the schema's Related list), so it falls back to a plain `TextInput` like the `text` editor — same as `select` would if Listbox didn't exist. Flagged since the doc implies a distinct date-picking UI.
- DataGrid: the full APG keyboard model (Tab as single stop with roving/activedescendant focus, Arrow/Home/End/PageUp/PageDown cell navigation, Space row toggle, Ctrl+A) has no hardware-keyboard listener wired on native Views — only Enter/Escape are caught, and only inside the inline text/number editor (via TextInput's onKeyPress, which is the sole RN element that reliably receives key events, and mainly on react-native-web per the platform notes). Touch equivalents are substituted instead: tap a cell to select/edit it, tap the select-all checkbox for Ctrl+A-row, sort by tapping the header button. `copy.position` (the aria-activedescendant announcement) is consequently unused.
- DataGrid: `aria-rowcount`/`aria-colcount`/`aria-rowindex`/`aria-colindex`/`aria-sort`/`aria-multiselectable`/`aria-readonly` from the web attribute list have no RN equivalents; per-cell/-row position is only implied by `accessibilityLabel` content, not announced numerically.
- DataGrid: pinned columns do not truly stay put during horizontal scroll — RN has no `position: sticky` and the package forbids a gesture-handler/reanimated dependency for a second synced FlatList (the schema's own suggested approach), so pinned columns scroll with the rest and only gain `pinnedShadow` once scrolled, the same approximation Table already uses for its sticky row-header column.
- DataGrid: the schema's `platforms.rn.props` lists `accessibilityRole=grid`, but RN's `AccessibilityRole` type has no `'grid'` member (a TS error). Used the newer ARIA-aligned `role` prop instead (`role="grid"`/`"row"`/`"rowgroup"`/`"columnheader"`/`"rowheader"`), per the package convention to prefer `role` where a web semantic exists; RN's `Role` union also has no `'gridcell'`, so plain cells use `role="cell"`.
- DataGrid: column resize is implemented via core `PanResponder` (drag) since gesture-handler is disallowed; there's no accessibility-action or arrow-key equivalent for adjusting a resizable column non-visually, only the visible drag handle.
