## 2026-09-10 02:53 — round 1

- Popover: RN's `Modal` always intercepts touch behind it, so `modal=false`'s spec requirement that "the page stays interactive" cannot be reproduced — only "tapping outside closes it" is implemented (backdrop is transparent, not tinted, but still blocks the underlying screen). Same limit this package's Menu already accepts.
- Popover: the panel's accessible name (a11y `accessible-name`, web's `aria-labelledby` the heading or the trigger's rendered text) has no RN equivalent for reading arbitrary trigger content, so it falls back to the trigger element's `label` string prop when present (works for this package's own Button/Link) and is otherwise undefined — a dev warning fires, but a non-Button trigger with no `heading` renders a panel with no accessible name.
- Popover: 'moves focus to the first control (or the heading, if there are none)' cannot be implemented literally — RN has no descendant walker to find a real first focusable control or to detect that the body has none (the same limit Dialog's `initialFocus` and FocusScope document), so focus always lands on the body wrapper via `AccessibilityInfo.setAccessibilityFocus`; the heading fallback is unreachable.
- Popover: `accessibilityState={{ expanded: isOpen }}` cloned onto the trigger has no effect when the trigger is this package's own `Button`, since `Button` does not forward unrecognized props onto its underlying `Pressable` (documented limit already acknowledged by Menu). `aria-controls` has no native analogue and is not attempted.
- Popover: Tab / Shift+Tab (`tab-out` reason, and the modal Tab-wrap) has no implementation — RN's `Pressable` exposes no generic hardware key-event API to detect Tab, and the modal case is inherited from `FocusScope`'s own documented 'no Tab order to confine' limit. `onOpenChange` can never fire with reason `tab-out` on this platform.
- Popover: per the RN platform notes phones should get a `BottomSheet` (height=content) instead of an anchored panel, but this package has no `BottomSheet` component yet, so this generator always renders the tablet/react-native-web anchored-panel variant regardless of form factor — the same acknowledged gap Menu's doc records for its own (missing) ActionSheet fallback.
- Popover: 'repositions on scroll and resize while open' is only handled for resize indirectly (the panel is measured once per open via `measureInWindow`); there is no generic native scroll-position listener to re-measure against, matching Menu's own dropdown, which has the identical limitation though its doc doesn't call it out.
- Popover: the optional arrow (`showArrow`) is centered on the panel's measured edge rather than re-aligned to the trigger's own center once the panel has been shifted to stay on-screen — a cosmetic simplification, not a spec requirement broken outright since the schema doesn't specify arrow alignment precision.
- Popover: `dismissible` is implemented as an all-or-nothing render gate on the close button (hidden when `false`) rather than Dialog's disabled-but-present pattern, since the schema's own wording ('Show the close button') reads as a visibility toggle rather than Dialog's stricter 'must be answered' semantics; flagging the interpretation in case the intended behavior was closer to Dialog's.

## 2026-09-21 08:35 — round 1

- Popover: the rn platform note says the root testID `Popover` sits on the panel View, but the package convention says the root view carries it and anatomy lists `panel` as its own part. Both cannot hold `Popover` (getByTestId would throw on two matches). Chose the note: the panel carries `Popover`, the outer anchor View carries no testID, and there is no `Popover.panel`. Consequence the doc does not address: at phone widths (BottomSheet) nothing carries `Popover` at all, and a closed popover is unfindable by testID.
- Popover: the ref target is contradictory — the generation rules say `ref` attaches to the root, the rn note says 'The Modal exposes no ref; callers ref their trigger'. Chose the outer anchor View that wraps the trigger, which is neither the panel nor the trigger itself.
- Popover: the generated behavior test queries `getByRole('dialog', { name })`, but the panel wraps focusable controls, so making it `accessible` would collapse the close button and the body's form controls into one VoiceOver element on iOS. Left it unset (matching Dialog and BottomSheet) and asserted on props in the hand-written test. packages/rn/jest.config.cjs already tracks this as '24 generated suites failing on has-accessible-name'; the doc should say which side gives.
- Popover: forwarding Popover's resolved `enter` to BottomSheet means the phone sheet enters over motion.duration.fast, where a plain BottomSheet uses motion.duration.base — the sheet's rise gets visibly quicker purely because a Popover produced it. The note's 'passing Popover's resolved value ... for each' is explicit, so it was implemented, but the intent reads accidental for the two duration bindings.
- Popover: the trigger-name fallback is specified as `accessibleName` then the string `label`, skipping `accessibilityLabel`, which Button itself honours between the two (`accessibleName ?? accessibilityLabel ?? label`). - Popover: with `dismissible: false` and no `heading`, the header row has no content. The partGap note covers 'no heading' (close button still at the inline end) but not 'neither'. Chose to render no header row, so `partGap` applies to nothing and the body meets the panel inset directly.
- Popover: `offset` is defined only as the trigger-to-panel gap; nothing names the margin the flip/shift collision handling should keep from the window edge. Reused `offset` as that margin rather than introduce a token, so a caller overriding `offset` also changes the viewport padding.
- Popover: the arrow spec says 'edged with `border` ... on its two outer sides' without naming them per edge. Derived them from a 45° clockwise rotation (facing edge top → borderTop+borderLeft, bottom → borderBottom+borderRight, left → borderLeft+borderBottom, right → borderTop+borderRight). 'Drawn above the panel' was implemented as paint order (rendered after the surface) rather than a zIndex, which would need a literal-ok escape.
- Popover: the web notes call a corner-placement arrow 'an approximation' because it centers on the panel edge, not the trigger; the rn notes repeat the centering rule without that caveat. Kept the same approximation, so with `bottom-start` on a narrow trigger the arrow can point past the trigger entirely.
- Popover: nothing says what to position against on the first frame, before measureInWindow and onLayout have both reported. Chose `maxWidth` as the assumed panel width and 0 as its height, holding the panel at opacity 0 until both are known — so the entry animation is gated on measurement rather than starting at a guessed position.
- Popover: `accessibilityViewIsModal` is set to `modal`, but the note also says Modal intercepts every touch regardless, so a non-modal popover is touch-modal while not claiming the VoiceOver rotor. The doc does not say which of the two should win for screen-reader users.
- Popover: the guidance says example stories 'start from blank args, never from Default's or meta args', which Storybook cannot do — meta.args always merge into a story. Reset `heading` and `placement` explicitly in each example that does not name them, and trimmed the redundant default-valued props out of meta.args; a doc-level rule that examples must restate every prop they rely on would be more robust.
- Popover: `headingLevel` has no target when `heading` is absent (no Heading is rendered), and the package's Heading accepts levels 1-6 while Popover's enum is 2-4. Passed through unchanged; the doc does not say whether an inert headingLevel should warn.
