Reduce example overload on component pages per Tony's review, 2026-09-15: some components' example `Tabs` (job 507, rendered by `apps/website/src/components/Examples.tsx`) carry enough entries that the tab strip itself becomes the thing a reader has to parse.

1. **Group related examples behind a disclosure.** In `Examples.tsx`, when `generated/examples/<Name>.json` has more than a threshold worth looking at directly (pick a number that reads right once a few dense components — Button, Select, DataGrid — are checked against it; do not hard-code an arbitrary cutoff without looking), split the tab strip into a small set of always-visible primary examples (Default, and whichever ones the component's own doc marks as most illustrative) plus the rest behind an `Accordion`/`Disclosure` section labeled something like "More examples". Keep every example reachable — this hides volume, it does not remove content.
2. **Small-multiple grid for prop-sweep examples.** Some components' examples are really one prop swept across its whole enum (Heading's `level`, Text's `size`) rather than distinct scenarios. For those, replace the tab-per-value pattern with one grid showing all values at once, each cell rendering the component at that value plus a caption line with the resolved pixel/rem value and the token it reads from (e.g. Heading level 2 → "24px / 1.5rem — `font.size.xl`"). This needs the resolved value, not just the token name: pull it from `packages/tokens/dist/<theme>/` (the built CSS/JS output already has the numbers) rather than hand-computing it, so it stays correct across theme/density changes. Scope this to components where the examples are genuinely a single-prop sweep — most components have real scenario variety and should keep tabs.

Decide the "is this a prop-sweep" classification in data, not by hand per page: either a field on the component doc (a `docs.exampleLayout: sweep | scenarios` hint) or a heuristic in `tools/docs_examples.ts` (all examples vary exactly one prop, and that prop is an enum) computed at generation time and written into `generated/examples/<Name>.json` alongside the existing fields, so `Examples.tsx` renders the right layout without re-deriving it in the browser.
