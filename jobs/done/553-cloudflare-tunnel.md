Serve the public website from Tony's home machine through a Cloudflare Tunnel, per the self-hosting setup already in apps/website (Dockerfile, compose.yaml, Caddyfile, README "Self-hosting"). Read those four files first.

What exists: a two-stage image (Node 24 build of every derived input → `caddy:2-alpine` serving `/srv`), and a compose file that publishes 8080/8443 on all interfaces and, with `SITE_ADDRESS=example.com`, has Caddy obtain Let's Encrypt certificates — which needs inbound 80/443 forwarded on the home router. The tunnel replaces all of that: `cloudflared` makes an **outbound** connection to Cloudflare, Cloudflare terminates TLS on the public hostname, and traffic reaches Caddy over the compose network as plain HTTP. No router ports, no certificates on the box, the home IP is not in DNS.

Human prerequisites (Tony does these; the job must not attempt them and must not need them to pass its gate): a domain on Cloudflare DNS; Zero Trust → Networks → Tunnels → Create a tunnel (Cloudflared) → copy the token; add a public hostname (e.g. `designschema.example.com`) whose service is `http://website:80`.

1. **Secrets never reach git.** Add `apps/website/.env` (and `.env` generally, keeping any existing negations) to .gitignore *before* anything else, and add `apps/website/.env.example` with every variable, placeholder values, and one comment line each: `TUNNEL_TOKEN=` (from the dashboard), `HTTP_PORT=8080` (local check port). Remove `SITE_ADDRESS`/`HTTPS_PORT` from the example: under the tunnel Caddy stays on `:80`. Confirm with `git check-ignore apps/website/.env`.
2. **Compose.** In apps/website/compose.yaml:
   - `website`: publish only `127.0.0.1:${HTTP_PORT:-8080}:80` (local verification; nothing listens on the LAN or the internet). Drop the 443 and 443/udp mappings and the `caddy_data`/`caddy_config` volumes' use for certificates — keep the volumes only if Caddy needs `/data` for anything else; say which. Add a healthcheck (`wget -qO- http://127.0.0.1/ >/dev/null`, caddy:alpine has busybox wget). `read_only: true` with a tmpfs for whatever Caddy writes, `cap_drop: [ALL]` plus `NET_BIND_SERVICE`, `security_opt: [no-new-privileges:true]`.
   - `tunnel`: `image: cloudflare/cloudflared:<pin a current version tag, not latest>`, `command: tunnel --no-autoupdate run`, `environment: TUNNEL_TOKEN: ${TUNNEL_TOKEN:?set TUNNEL_TOKEN in apps/website/.env}`, `depends_on: website: condition: service_healthy`, `restart: unless-stopped`, no ports. Put it under a Compose profile `tunnel` so `docker compose up` without the profile still works for local-only use.
   - Keep the existing Let's Encrypt mode available but documented as the alternative (a second profile or a comment block), not the default.
3. **Caddy behind the tunnel.** The request arrives as HTTP on :80 with `Host` = the public hostname; the Caddyfile's `{$SITE_ADDRESS::80}` already serves any host on :80 — confirm no redirect to HTTPS happens (it must not; Cloudflare already did TLS). Add `Strict-Transport-Security "max-age=31536000"` only if Tony's hostname is HTTPS-only at Cloudflare (it is by default with "Always Use HTTPS"); leave it as a commented line otherwise and say so.
4. **Scripts.** Add `apps/website/deploy.ps1` (Tony is on Windows with Docker Desktop): checks `.env` exists and has a non-empty `TUNNEL_TOKEN`, runs `pnpm check` first (the image fails on a tree that does not parse — README already warns not to build mid-job-queue; make the script refuse if `jobs/` has a job file newer than the last commit, with a `-Force` switch), then `docker compose -f apps/website/compose.yaml --profile tunnel up -d --build`, then waits for `website` to be healthy and prints `docker compose ps` and the last 20 lines of the tunnel's log (a registered connection line is the success signal).
5. **Always on.** README "Self-hosting" gains a "Cloudflare Tunnel (home hosting)" section: the prerequisites above, the `.env`, the one command, how to update (re-run deploy.ps1), how to take it offline (`docker compose --profile tunnel down`), and the Windows settings that keep it up — Docker Desktop "Start when you sign in", the power plan never sleeping while plugged in, and that containers restart on their own (`unless-stopped`) once Docker is up. Mention optional Cloudflare Access for a private preview hostname, and that Cloudflare caches `/_astro/*` (immutable) while HTML revalidates, so a deploy shows on next load without a purge.
6. **Astro `site`.** Set `site` in apps/website/astro.config.mjs from an env var (`PUBLIC_SITE_URL`, default unset) so canonical URLs and the sitemap (if any) use the public hostname; pass it as a build arg in compose from `.env`. Unset must build exactly as today.
