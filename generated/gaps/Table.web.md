# Gaps reported while generating Table for web

Each entry is a place the doc made the generator guess. Fix the doc, re-run parse, regenerate.

## 2026-09-10 13:29 — round 1

- anatomy.caption composition names Heading, but props/platform-notes describe a plain `<caption>` with no `headingLevel` prop. Followed the sibling Lit implementation's precedent: caption renders `<Heading level={2} size="md">`, with a fixed, non-configurable level — worth adding a `captionHeadingLevel`-style prop (or dropping the Heading composition) if this is load-bearing for page outlines.
- anatomy lists a `footer` part with no prop or content contract in `props`. Added a `footer?: ReactNode` prop (rendered as `<div class="ds-table__footer" data-part="footer">`) for parity with the Lit sibling's `slot="footer"`, but the schema never specifies what belongs there or how it should be styled.
- `onRowPress` interactivity: enabled only when `rowHeaderColumn` exists AND has no custom `render` (mirroring the Lit implementation), since a custom render may already contain interactive content (a Link) that a wrapping Button would conflict with. If a consumer passes `onRowPress` with a rendered row-header column, the row silently stays non-interactive rather than erroring — not stated explicitly in the doc.
- Row-header text used in `copy.selectRow`/`onRowPress`'s Button label falls back to the raw underlying value (`String(row[key])`) when the row-header column has a custom `render`, since a ReactNode can't be reduced to plain text for an aria-label/Button label.
- Sortable header Button's visible label is the full `copy.sortAscending`/`sortDescending` phrase ("Sort by Amount, ascending") rather than the plain column name, since `Button` cannot have a distinct accessible name from its visible text (its `aria-label` prop is not exposed to consumers) and both `sortAscending`/`sortDescending` copy strings had to be used verbatim somewhere. The plain column header text is not shown at all on sortable columns.
- `maxHeight: viewport` formula ("viewport height minus the section rhythm") implemented as `calc(100vh - var(--layout-gap-section) * 2)`, matching the sibling Lit component's exact choice; the doc doesn't spell out the multiplier.
- Horizontal scroll-step distance for ArrowLeft/ArrowRight in the `scroll` region is a fixed, undocumented `40` (px, unitless in `scrollBy`) — the doc doesn't specify a magnitude, and this was chosen to match the sibling Lit implementation's `SCROLL_STEP_PX`.
- The scroll-region edge fade (`scrollFade`) is a static `mask-image` gradient always applied at both edges, rather than dynamically hiding at the very start/end of the scrollable content — a reasonable simplification also present in the Lit sibling.
- `stickyColumnShadow` is toggled globally on the scroll region once `scrollLeft > 0`, rather than only while the row-header column is actually still off the left edge (the difference is only observable if the table's total width barely exceeds the viewport).

## 2026-09-12 06:45 — job 506 (the component docs page)

- Table: a `<caption>` holding a `Heading` fails axe's `aria-required-children` on every instance — "Element has children which are not allowed: h2". The component sets an explicit `role="table"`, so axe stops applying the native-table allowances and reads the composed caption Heading as an owned child of the table, where ARIA permits only `row`/`rowgroup` (and, from 1.3, `caption` itself). The Heading is not a generation choice: `anatomy.caption`'s composition names Heading, and the round-1 note above records the generator being corrected for leaving `captionLevel` out. It fires with `hideCaption` set too, since that only visually hides the caption. Nothing a consumer passes can avoid it — `caption` is required and `captionLevel` only picks which heading level it is — so the docs site's axe gate holds every other rule to zero and lets this one through by name (`tests/website/axe.ts`), narrowed to Table's own element. The fix belongs in the doc: either give the caption its accessible name without a heading element (a styled span plus the `aria-labelledby` the component already wires), or drop `role="table"` from the web platform notes and let the native table semantics carry it. Until then every page that puts a Table in front of axe inherits this — the docs site is the first one to, which is why it surfaced here and not in the component's own gate.

## 2026-09-16 11:08 — round 1

- Table: Button always sets its own data-part="container" after spreading rest, so the anatomy parts sortButton (and the row-header Button) can't carry data-part hooks. Tests find the sort button as `[data-part=columnHeader] button`.
- Table: stack mode says thead is visually hidden, but it holds the select-all Checkbox and the sort Buttons, which would stay focusable while invisible. Below the prose width I keep select-all and sortable headers visible as a wrapping row and visually hide only the plain column headers.
- Table: selectable: single has no select-all, and the spec doesn't say what goes in the header's first column. An empty columnheader has no name, so I render an empty role=cell td with no data-part.
- Table: loading with existing rows says 'the body shows copy.loading', but there's nowhere in tbody to put it without adding a fake row. I render it as muted Text below the table, above the footer; with no rows it replaces the empty message inside the empty cell.
- Table: scroll mode wraps the table in an overflow-x:auto region, which also becomes the scroll container for sticky positioning. So stickyHeader only sticks there when maxHeight: viewport makes the region scroll vertically; against the page scroll it can't stick. The spec doesn't address this.
- Table: maxHeight: viewport doesn't say which element scrolls. I cap and scroll a frame div around the table (the scroll region in scroll mode), use 100vh minus 2 × layout.gap.section, and point the header-shadow IntersectionObserver at that frame.
- Table: hideBelow — the prop description says it drops a column below a layout width, but Behavior says scrolling tables keep every column. I apply hideBelow in stack mode only, with container queries at 572px (prose) and 960px (content).
- Table: no locale prop exists for copy.rowCount's Intl.PluralRules. I use document.documentElement.lang, falling back to the runtime default.
- Table: copy.cellLabel and copy.sortToolbarLabel have no use on web (stacked labels come from ::before, and there's no sort toolbar), so neither is rendered.
- Table: the stacked ::before label is 'aria-hidden', but CSS can't set aria-hidden. I use `content: attr(data-label) / ''` (empty alt text) with a plain fallback; browsers without the alt syntax will read the label twice.
- Table: the row header gets no data-label or ::before in stack mode, since the spec calls it the row's name; the spec only mentions labels on td.
- Table: onRowPress on web — only the row-header Button is described as activating the row. I also let a pointer click anywhere on the row (not on a control) fire onRowPress; keyboard and assistive tech use the Button.
- Table: numericFont says tabular figures, falling back to mono where the body font lacks them. CSS can't detect that, so end-aligned body cells always use font-variant-numeric: tabular-nums with the numericFont family.
- Table: cellGap covers both the gap in the actions cell and the sort button's label-to-arrow gap. The arrow is inside Button, so a cellGap override is passed to the Button's iconGap; the default is left to Button.
- Table: selection uses the composed Checkbox, which carries data-ds-field and registers with FormContext. Inside a Form the row checkboxes would be found and submitted as fields; neither the spec nor Checkbox offers a way to opt out.
- Table: the transition binding also covers 'sort-arrow changes', but the arrow is an Icon inside Button and can't be styled from outside, so only the row hover background transitions.
- Table: the selected-row start-edge bar is an inset box-shadow on the first cell (on the row itself when stacked), mirrored with :dir(rtl). The spec doesn't say how to draw it; a border would shift the layout.
- Table: the actions column header 'Actions' is visually hidden with no part named; it uses columnHeader.

## 2026-09-21 19:18 — round 1

- Table: the parts table declares selectCell/selectAllCell as component `Checkbox` and sortButton as component `Button`, but the web note says Button writes its own data-part so sortButton has no hook — it never says where selectCell/selectAllCell's hooks go. I put them on the <td>/<th> (as the note's 'Checkbox in the first cell' implies). The generated behavior harness clicks [data-part="sortButton"] (absent, so it falls back to the root) and [data-part="selectCell"]/[data-part="selectAllCell"] (the cell, so the click misses the input): 3 of its 20 cases fail, identically at HEAD. The doc should state which element carries each of these three hooks on web.
- Table: scrollFade now says 'The mask covers the scrolling content only, never the region's own focus ring' — but on web a mask clips everything its element paints, and the region must be both the overflow-x scroller and the tabindex=0 focusable. I added an unmasked wrapper div around the scroll region that draws the ring with :has(> .scroll-region:focus-visible), with `outline: none` on the region itself. That wrapper is not a part and the doc doesn't mention it; other platforms need their own answer.
- Table: 'the select-all header and sortable headers stay visible as a row that wraps on stackedRowGap and keeps the header cell styling' doesn't say how far 'header cell styling' goes once the cells wrap. I kept headerSurface/headerSize/headerWeight/headerColor on the cells but moved headerBorder and the scrolled-under headerShadow to the row (per-cell borders and shadows stripe a wrapped flex row), and put headerSurface on the row too so the wrap gaps are filled.
- Table: stickyHeader says 'Stacked, what sticks is the whole header row' but not that thead must stop being a flex container for that to work — as a flex parent it makes the row a flex item sized to its content, so the sticky band stops mid-table. I set the stacked thead to `display: block` and made only the row the flex container.
- Table: hideCaption 'sends space.0 in place of captionGap', and the forward does reach Heading's overrides, but the visually-hidden clip pattern's `margin: -1px` then wins over the Heading's own margin rule, so -1px and not space.0 is the used value. Same outcome (no gap above the header); the doc should say the clip is what takes effect.
- Table: copy.sortToolbarLabel and copy.cellLabel are in the copy table, and the generator rule says every copy.* string is used verbatim, but the Behavior section says web and Lit render neither. I left both out of the web COPY constant (as the prior generation did). Worth stating in the copy entries themselves which platforms render them, so the rule and the prose stop disagreeing.
- Table: the arrow-scroll step is now specified as space.10 'read from the built token (px and rem both parsed)', but calm-precise builds px (--space-10: 40px), so nothing in this repo exercises the rem branch — it is written but untested by any gate here.
