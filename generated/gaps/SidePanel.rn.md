## 2026-09-10 03:17 — round 1

- SidePanel: copy.openLabel ('Open menu') has no described consumption point — the trigger is entirely caller-supplied content, not a built-in button the component renders. I use it as a fallback accessibilityLabel on the cloned trigger only when the trigger element has no string `label` prop of its own, so the toggle always has an accessible name of last resort; the schema doesn't confirm this is the intended use.
- SidePanel: the guidance text says the trigger is 'usually iconOnly with the menu Icon', but this package's Icon glyph set (paths.ts) has no `menu` (hamburger) name — only chevrons, close, plus/minus, status glyphs, external, ellipsis, search, arrows, calendar. Used a plain labeled (non-iconOnly) Button in the stories instead of inventing a glyph; a `menu` icon is a gap for whoever owns the Icon component.
- SidePanel: 'Escape ... request close. When false, only the trigger and footer actions close it' contradicts this package's own Dialog/BottomSheet precedent, where Escape/the Android back button always reports regardless of `dismissible` (the consumer decides). I followed SidePanel's own explicit wording and gated Escape/onRequestClose by `dismissible`, diverging from the Dialog convention — flagging in case the intent was actually to match Dialog.
- SidePanel: non-modal 'the page stays live' (touches behind the panel work) cannot be reproduced natively — RN's `Modal` intercepts every touch behind it regardless of transparency, the same acknowledged limit Popover's own doc records. Only 'a tap outside closes it' is implementable; scroll-lock and `inert` background have no native equivalent either (same acknowledged gap as Dialog/BottomSheet).
- SidePanel: `useSidePanelEdgeSwipe`'s `onOpen` callback has no wiring to a specific SidePanel instance's internal state — for an uncontrolled panel (no `open` prop) there is no imperative handle besides the rendered `trigger`, so edge-swipe-to-open only works if the consumer also controls `open` themselves. Also, the 'edge zone' width a swipe must start within has no token in the schema; I used `sizeTargetComfortable` as the nearest existing token, a guess.
- SidePanel: `navigation` is kept on the `SidePanelCloseReason` type for parity with the web/Lit docs (a followed Link closes the panel there via a client router) but is never emitted by this native component — there's no router hook to observe a followed Link, same as `action` for Dialog/BottomSheet.
- SidePanel: persistent-mode accessibility role — the platforms.rn notes explicitly say 'a sibling View with accessibilityRole="none" and a label', which I followed verbatim, even though the general package convention elsewhere favors `role` (RN ≥0.74) for landmark parity with the web `complementary`/`navigation` role; RN has no such landmark role value, so `none`+label is the documented fallback.
- No SidePanel.test.tsx was written — this generation task's Output section only asked for the .tsx (plus stories); none of the package's other overlay components (BottomSheet, Popover, ActionSheet) has a sibling .test.tsx either, so behavior-scenario tests were left to whatever separate pass covers that (per the project's ongoing behavior-scenarios rollout).

Followed the platform note and removed the `ref` prop the previous generation shipped — an API removal for any existing consumer. The note is presumably reasoning about the overlay (a Modal is its own window), but persistent mode renders a plain in-tree View where a ref would be meaningful and harmless.
- SidePanel: `focusScope` is in the anatomy and `partGap`'s part, but the rn note says FocusScope wraps the surface from outside and "takes no testID", leaving the styled column unaddressable. - SidePanel: persistent mode renders no FocusScope, so the `partGap` part (`focusScope`) does not exist there, yet the spacing between header, body and footer still has to come from somewhere. - SidePanel: `edgeZone` says the edge-swipe-to-open "uses the same dragSlop, dismissDistance and dismissVelocity rules toward the content", but `dismissDistance` is a fraction of the panel width and `useSidePanelEdgeSwipe` is deliberately decoupled from the panel (its options are side/enabled/onOpen only, no `width`). Measured the open threshold against the window width instead — within a gutter of the panel's real width on a phone, wrong on a tablet below the persistent breakpoint. A `width` option would make it exact but is not in the schema.
- SidePanel: the `exit` binding describes a swipe release entirely in terms of "the consumer's next render", which assumes a controlled panel, but `open` is optional here and uncontrolled is the documented default. Routed both through one release counter: uncontrolled flips internally in the same batch, so the held offset is always followed by the exit and the spring-back branch is unreachable.
- SidePanel: `hideHeading` says "the hidden title moves to the top of the surface" when the header is not rendered. There is no native equivalent — the hidden title is the surface's `accessibilityLabel`, which has no position in the view tree — so nothing is rendered and the label carries it. Same for the visually-hidden clip pattern, which does not apply.
- SidePanel: `trigger` is typed `content` on rn, but the panel must clone it to attach the toggle and the expanded state, so a fragment or a bare string silently never opens the panel. Added a `__DEV__` warning and render it as given. The doc states the single-element rule only for web ("it is cloned"); rn should say the same.
- SidePanel: the keyboard block's Escape rule targets `surface` and expects `focus-trigger`, but native has no Escape key. Mapped it to `onRequestClose` (the Android back button, which the notes do sanction) and additionally to `onAccessibilityEscape` on the surface for the VoiceOver two-finger-Z, which the doc never mentions for this component although BottomSheet does the same. Focus returns to the trigger on unmount, i.e. after the exit animation, not at the moment of the request.
- SidePanel: the rn note requires the parts column to sit inside a core `SafeAreaView`, but React Native 0.87 deprecates it in favour of `react-native-safe-area-context`, which the dependency rule forbids. Kept core SafeAreaView, so every render logs a deprecation warning (BottomSheet has the same problem). The doc should say which side of that conflict wins before RN removes the component.
- SidePanel: `edgeGutter` is described as the strip left beside "a phone-width panel", without saying whether `narrow` is also capped. Applied `min(width, window - edgeGutter)` to all three width values, so a narrow panel on a very small screen still leaves the gutter.
