# Gaps reported while generating Toast for lit

Each entry is a place the doc made the generator guess. Fix the doc, re-run parse, regenerate.

## 2026-09-10 02:43 — round 1

- The spec's OverridableBinding list is flat across the whole component, but `region`/`toast` are two separate custom elements here (`ds-toast`, `ds-toast-region`). I put `stackGap`/`regionInset`/`layer` on `ds-toast-region`'s own `overrides` (exported as `ToastRegionOverridableBinding`) and everything else on `ds-toast`'s `overrides` (`ToastOverridableBinding`), since those three are structural to the shared region, not any one toast.
- `actionColor` (color.inverse.link) and `dismissColor` (color.inverse.foreground) are specified as distinct locked tokens, but the existing `<ds-button>` `inverse` prop (already built in Button.ts with a comment naming Toast) only implements one on-inverse ghost treatment (link-colored) with no way to select the other without restyling Button's shadow tree or adding a new Button prop — out of scope for this task. Both the action and dismiss buttons use `variant="ghost" inverse` unchanged, so the dismiss (close) button ends up link-colored rather than foreground-colored.
- The schema's `id` prop (stable identity for replace-instead-of-stack) collides with `HTMLElement.id`. Rather than adding a shadowing `@property() id`, I mapped it directly to the native `id` attribute/property (set by `toast()`, read back via `#id` selector) — `ds-toast` has no custom `id` property.
- `dismissible` defaults to `true` per the schema, which conflicts with the package's general boolean-attribute convention ("a boolean attribute cannot express false, so defaults are false"); the schema's explicit default wins, but that means `dismissible="false"` can't be expressed as a static HTML attribute — only by setting the JS property (fine given the component is only ever created imperatively by `toast()`).
- `ToastDismissReason` has no `'escape'` value, so Escape (a required keyboard interaction) dismisses with reason `'dismiss-button'` as the closest existing fit — flagging in case a distinct reason was intended.
- `has-accessible-name` is satisfied via a literal `aria-label` attribute set on the host from `message`, not `ElementInternals.ariaLabel` (the package's stated convention for live-region hosts, also used for `role`). `dom-accessibility-api` (used by the test suite's `toHaveAccessibleName`) does not read ARIAMixin values set through ElementInternals, only real attributes; real assistive tech reads either, so this only affects testability, not production behavior.
- The doc's Web platform notes describe one shared `<div role="region">` with a single `aria-live="polite"`, while individual toasts are `role="status"`/`"alert"`; for Lit I kept that per-toast role split but set the region's own `role`/`aria-label`/`aria-live` via plain attributes (not `ElementInternals`) for the same testability reason as above.
- No design token or breakpoint is named for the toast region's wide-vs-phone layout switch (bottom-start vs bottom-center); I used a `min-width: 572px` media query (the resolved px value of `layout.maxWidth.prose`), matching the `literal-ok` breakpoint convention already used in `Container.ts` for `layout.maxWidth.content`/`page`.
- `toast()` returns `Promise<ToastResult>` (resolving with `{ reason }` on dismissal) since the lit platform note says composed `dismiss`/`action` events "bubble to the region for the imperative API's promise" but doesn't specify the promise's shape — I inferred a dismissal-reason result from context.

## 2026-09-10 17:55 — round 1

- Toast: schema lists `toastId` as a component prop (explicitly named to avoid colliding with the DOM `id`), but it was missing as a `@property` on `<ds-toast>` — added `toastId` (attribute `toast-id`) and switched the imperative `toast()` replace/evict logic from hijacking the native `id` to comparing `toastId`.
- Toast: `dismissible` defaults to `true` (named in the package's own boolean-default-true rule alongside `stickyHeader`/`showValue`) but was implemented as a plain reflected `dismissible` boolean attribute, which cannot express `false` from HTML — fixed to the established negated-attribute convention (`no-dismiss` + `NEGATED_BOOLEAN_CONVERTER`, matching `ProgressBar.showValue`/`hide-value`).
- Toast: duration timers read `--motion-duration-loop` via `getComputedStyle` on each `<ds-toast>` at its own connect, whereas the doc says the short/long durations are 'computed at region mount' (implying a single read cached on `<ds-toast-region>` and reused). Functionally equivalent since the token inherits identically to the toast and the region, but left as-is rather than restructuring the mount-time caching, since no scenario or test exercises the distinction — flagging in case the doc intends true region-level caching for performance.
- Toast: `MAX_TOASTS` eviction counts the just-replaced (soon-to-close) toast when a `toastId` match triggers a replace, since `requestDismiss` only starts the exit transition rather than removing the element synchronously — pre-existing behavior, not touched, but could over-evict by one in the rare case a same-`toastId` replace coincides with an already-full region.

## 2026-09-16 06:09 — round 1

- Toast: the Overrides list names stackGap, regionInset and layer as overridable, but stackGap's description says those three belong to the region and are overridable on it, not on a toast; I put them in DsToastRegion's `overrides` (ToastRegionOverridableBinding) and left them out of ToastOverridableBinding.
- Toast: Parts says a composed part receives exactly the listed props (variant ghost, inverse true), but the buttons also need a label (actionLabel / copy.dismissLabel) and the dismiss button must be icon-only with a close Icon (Web platform notes: `iconOnly`, `Icon name="close"`); I passed label and icon-only anyway and dropped the `size="sm"` the web/RN notes mention. The composition block should list label, iconOnly and size per button.
- Toast: the dismiss button's glyph (`close`) and the tone icon's glyph name (the tone value) are only in platform prose, not in `composition`; I used `name=${tone}` and `name="close"`.
- Toast: the `text` binding (color.inverse.foreground) is locked on Toast, but Text has no inverse tone and its color is locked, so the message can't get the color without styling the child; I re-scoped `--color-foreground` on the message part. Text's schema likely needs an `inverse` tone.
- Toast: `duration` defaults to `short`, so on Lit a danger or action toast can't tell an explicit `duration` from the default; the 'dev warning notes the override' fires whenever duration isn't `persistent`, including when it was never set.
- Toast: the Guidance says durations are never under five seconds, and the prop says the loop-based times keep themes without motion sensible, but a theme whose motion.duration.loop resolves to 0 would give a 0ms timer; I treat an unresolvable or non-positive loop as persistent. The doc should say what to do (a floor, or persistent).
- Toast: the Escape rule says it 'returns focus' but doesn't say where when focus wasn't brought in by F6 (a user can Tab into the region); I restore focus to the element saved on F6 and otherwise let focus fall to the document.
- Toast: onDismiss is 'after-change' and the Lit notes say dismiss bubbles to the region, but it isn't stated whether it fires before or after the exit transition, or before or after the element is removed; I dispatch after the transition and just before removal so it still bubbles.
- Toast: the Lit notes say the region sets role/aria-live via ElementInternals, but the package convention says names and roles tests read must be plain attributes; I set both on the region, and a plain `role` attribute on each toast.
- Toast: the Guidance's `toast({ message, tone, actionLabel, onAction })` includes `onAction`, and the Behavior section mentions `id`, but ToastOptions isn't part of the schema; I added `onAction` and used `toastId`, not `id`.
- Toast: the region position ('bottom-start on wide screens, bottom center on phones') has no breakpoint token; I kept the existing `min-width: 572px` media query (layout.maxWidth.prose's value) with a literal-ok comment, since custom properties can't be used in media queries.

## 2026-09-21 05:54 — round 1

- Toast: onDismiss's timing is unimplementable against the generated behavior harness. The doc says dismiss 'fires after the exit transition ends and just before the toast is removed', but tools/behavior_tests.ts emits a synchronous `expect(s.events.onDismiss).toHaveBeenCalled()`, and the Lit behavior gate runs in real Chromium with the token stylesheet loaded, so `--ds-toast-exit` resolves (motion.duration.fast) and the event lands ~120ms later: the-dismiss-button-fires-on-dismiss and escape-dismisses-the-focused-toast fail. React passes only because jsdom cannot resolve the custom property, so the same contract is untested there. I implemented the doc (my own Toast.test.ts polls). Resolve by either saying onDismiss fires when the toast *begins* to leave — the package's own precedent, Popover fires its event at the state change and uses transitionend only to delay the unmount, and the event still bubbles to the region because the toast is still connected — or by having the behavior harness await events.
- Toast: the doc/conventions say the role and accessible name tests read go on the host as plain attributes, but the generated tests require the opposite on Lit: generated/behavior/Toast.lit.test.ts asserts `el.shadowRoot.querySelector('[role="alert"]')` and names `deep(shadowRoot, '[role="status"]')`, and generated/keyboard/Toast.lit.spec.ts walks `root.querySelectorAll('*')` for shadow hosts without ever entering the root's *own* shadow root — with role on the host it finds zero focusables and all three keyboard rules fail. I moved `role` and `aria-label` onto the `toast` part inside the shadow root (the host keeps only `data-ds`), which makes both gates green and keeps `aria-label` off a roleless generic element for axe. The doc should state which element carries the role and name on Lit.
- Toast: the doc never says the toast itself is focusable, but the escape scenario is expressed on Lit as `el.focus()` then Escape, which needs `delegatesFocus`. I set `shadowRootOptions.delegatesFocus = true`. Side effect the doc should sanction or forbid: clicking anywhere on the toast (the message, the padding) now focuses the action button and so pauses the auto-dismiss timer.
- Toast: `duration` defaults to `short`, so 'the default never warns' requires tracking assignment; I use a getter/setter pair (`durationAssigned` set in the setter, the constructor pre-seeding the reflected default). This also forced a story change: the generated behavior test copies `meta.args` onto every element, so keeping `duration: 'short'` in the Lit meta args marked every toast as explicitly assigned and made the danger scenario emit the dev warning. The Lit meta args now match React's (message, tone, dismissible only) — the doc should say the examples and stories must leave `duration` unset unless it is meaningful.
- Toast: the Overrides list is flat, but stackGap/regionInset/layer are the region's (per stackGap's own description) and there are two custom elements here. I keep them on `<ds-toast-region>`'s `overrides` (ToastRegionOverridableBinding) with the toast-prefixed hook names the doc gives (`--ds-toast-stack-gap`, `--ds-toast-region-inset`, `--ds-toast-layer`), not the `--ds-toast-region-*` the naming rule would derive from the region's tag. Unchanged from earlier rounds; still worth fixing in the doc.
- Toast: the doc gives `enter`, `enterOffset` and `exit` but not how a toast inserted by markup (a declarative `<ds-toast>`, as the Keyboard story and every behavior test use) should start. I made the resting state the entered state and put the offset in `@starting-style`, so anything that reads the element before the first frame sees it settled; the alternative (React's: start hidden, add a class on rAF) would leave a toast at opacity 0 whenever that frame never runs.
- Toast: minTarget (size.target.min) is locked but has no `part`. I applied it as `min-block-size` on the `toast` row (matching React's CSS), on the reading that the buttons' own targets are Button's concern.
- Toast: the region's wide-vs-phone switch still has no breakpoint token; kept `@media (min-width: 960px)` (the resolved px of layout.maxWidth.content) with a literal-ok comment, since custom properties cannot be used in media queries.
- Toast: the web notes say an auto-mounted region waits one animation frame before its first toast; the Lit notes do not, but the announcement reason applies identically, so I did the same. Consequence the doc should acknowledge: `dismiss()` called in the same tick as the first `toast()` (a story or test cleanup) cannot see that toast, because it is not in the region yet.
- Toast: 'returns focus' is undefined when focus was never brought into the region from outside (a toast dismissed by timeout, replacement or `dismiss()` while it happens to hold focus). I restore to the recorded origin when there is one, otherwise to the first focusable after the region and the last one before it, using FocusScope's walker.
- Toast: story parity with React's `Keyboard` cannot be literal — React's renders `<ToastRegion/>` and calls `toast()` in an effect, while a Lit story render must be one inline `html` template for tools/docs_snippets.ts. Mine declares `<ds-toast-region>` with the same two toasts (neutral Undo, danger Retry), adds a focusable button on each side so F6 has an origin and Tab a way out, and inlines `position: static` on the region so the toasts render in flow in the docs. The doc should say what the Keyboard story is required to contain.

## 2026-09-23 14:25 — round 1

- Toast: the replaced-toast focus restore runs 'only while focus is still inside the toast or has already fallen to the body' — read literally, replacing a toast nobody ever focused while focus sits on <body> would move focus onto a page element, contradicting 'Focus never moves to a toast on its own'. Chose: 'fallen to the body' counts only when this toast had focus (tracked by focusin) and focus is now on body.
- Toast: the dev warning fires when a change 'enters that case, including when the case already held and duration changes' — unclear whether a tone or actionLabel change while the case already held (e.g. actionLabel set, tone success→danger) warns again. Chose: no; only entering the case or a duration change while in it warns.
- Toast: nothing says whether a toast in its exit transition stays focusable/clickable. Chose: the toast part gets `inert` while closing (focus has already been restored), so Tab and pointer can't reach a leaving toast.
- Toast: 'the origin is one per document… with two regions on a page the last entry wins', but each region binds its own document-level F6 handler and the doc doesn't say which region one press goes to. Chose: the first region whose handler acts calls preventDefault, and the others ignore a defaultPrevented F6.
- Toast: the Keyboard story is meant to render 'a trigger button plus two persistent action toasts', but on Lit there is nothing for a trigger to trigger, since the toasts are declarative. Chose: plain 'Before'/'After' buttons around a static <ds-toast-region>, so F6 has an origin and Tab has a way out (five focus stops).
- Toast: the region is fixed-positioned by default; the Keyboard story overrides that with an inline `position: static` so the region sits in the story's flow. The doc doesn't say how a story should place a region that is normally viewport-fixed.

## 2026-09-23 14:26 — round 2
