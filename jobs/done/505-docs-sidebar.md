Build the docs section's navigation per website-plan.md ("Docs section").

1. `apps/website/src/components/DocsSidebar.astro`: desktop (≥ `layout.breakpoint.md`) — `Landmark(role="navigation", accessibleName="Component docs")` containing one `Disclosure` per phase group from `generated/nav.json`'s `docs` list (open by default), each holding `Link`s to `/docs/components/<slug>`. Foundations and Patterns get top-level `Link`s above the phase groups.
2. Below the breakpoint, replace the sidebar with a single `Select`, options grouped the same way as the phase groups (use `Select`'s existing grouped-options support), `onChange` navigating via `window.location.assign` to the chosen component's route — this is cross-page navigation, not in-page state, so it's a plain assignment rather than client-side routing.
3. `apps/website/src/layouts/DocsLayout.astro`: wraps `DocsSidebar` + a content slot, swapping between the two nav renderings at the breakpoint (CSS, not a client-side check — both markups can exist and be shown/hidden by media query if that's simpler than server-side UA sniffing, since Astro output is otherwise static).
Gate: at a mobile viewport width, the sidebar `Landmark` is not present in the accessibility tree and the `Select` is; choosing an option navigates to the matching component's page. Do not modify `packages/*/src` or `generated/*.json` (only reads `generated/nav.json`).
