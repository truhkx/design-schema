# Package conventions — @design-schema/lit (web components)

Read this instead of the whole package. Open at most two files if a detail is missing: `packages/lit/src/index.ts` (exports) and the one existing element closest to what you are writing.

- **Files.** `packages/lit/src/<Name>.ts` defines `class Ds<Name> extends LitElement`, registered with `@customElement('<platforms.lit.tag>')`; `<Name>.stories.ts`. `index.ts` gets a side-effect `import './<Name>.js';`, `export { Ds<Name> } from './<Name>.js';` and type exports, in the existing style. Imports use `.js` extensions.
- **Decorators.** `@property({ type: String, reflect: true })` for reflected enum/string attributes listed under `platforms.lit.reflect`; `@property({ type: Boolean, reflect: true })` for booleans (attribute present = true; a boolean attribute cannot express false, so defaults are false). Arrays/objects: `@property({ attribute: false })`. Numbers: `type: Number`. Internal state `@state()`. Use untyped `PropertyValues` in lifecycle methods (`PropertyValues<this>` cannot name private fields). `tsconfig` has `experimentalDecorators` and `useDefineForClassFields: false`.
- **Shadow DOM.** `static shadowRootOptions = { ...LitElement.shadowRootOptions, delegatesFocus: true }` for anything focusable. `static styles = css\`…\`` using `var(--token)` only; `:host` display rules; `:host([hidden]) { display: none }`. No hex/px/ms/font literals (`tools/lint_literals.py`); the visually-hidden clip pattern and `color-mix()` of tokens are exempt; otherwise `/* literal-ok: reason */`.
- **Overrides.** Every style binding is a hook on `:host`, `--ds-<tag-without-ds>-<binding>`, defaulting to its token; rules read the hook (per reflected attribute for interpolated bindings). `@property({ attribute: false }) overrides?: Partial<Record<OverridableBinding, TokenRef>>` sets hooks with `style.setProperty(hook, cssVar(ref))` (`TokenRef`, `cssVar` from `@design-schema/tokens`). No `::part` for styling. Locked bindings excluded.
- **Spacing between siblings** is never a margin: `<ds-stack gap>` (`layout.gap.*`), `<ds-box inset>` / `<ds-card inset>` (`layout.inset.*`), `<ds-container>` gutters. A resolved token path ending in `.default` drops it.
- **Events.** Composed, bubbling `CustomEvent`s named per `platforms.lit` (`press`, `change`, `toggle`, `dismiss`, `navigate`) with a typed `detail` (`export type <Name><Event>Detail`). Never dispatch a CustomEvent with a native event's name (`click`, `focus`, `blur`) — native events retarget through the shadow root already. Re-dispatch the internal input's non-composed `change` as a composed one. Stop an inner `ds-button`'s `press` when the composite dispatches its own event.
- **Forms.** Form fields are form-associated (`static formAssociated = true`, `ElementInternals`, `setFormValue`, `setValidity`, `checkValidity()`, `reportValidity()`, `formResetCallback`) and implement the `DsFormField` interface exported from `Form.ts`: `name, label, required, disabled, error, currentValue (string | boolean | null), id, focus(), checkValidity(), validationMessage`. Validation is synchronous (setting `error` updates `invalid` and validity at once). `validationMessage` is the field's own copy string. `ds-form` collects by tag and `focusout`.
- **Roles on the host** (landmarks, live regions) go through `this.attachInternals().role` / `ariaLabel`, so they live in the light DOM tree. A property named after a native `HTMLElement` member (`role`, `title`) must use another name (`landmark`, `heading`) with the attribute mapped.
- **Composition.** Compose `<ds-button>`, `<ds-link>`, `<ds-text>`, `<ds-icon>` inside the shadow root (side-effect import their modules); never restyle a child (no `::part` overrides). Icons via `<ds-icon name>` or a `leading-icon` slot.
- **Dev warnings** use `import.meta.env.DEV` (`vite/client` types are configured).
- **Stories.** CSF3, `import type { Meta, StoryObj } from '@storybook/web-components'`, `html` from `lit`, `title: '<Name>/Lit'`, `Default` plus one story per enum value named `<Prop><Value>`, plus notable states; register events in `parameters.actions.handles`. Demos in `packages/lit/demo/` with `title: 'Demo/<Name>/Lit'`.
- **Theming** is external: the token stylesheet is loaded once at the root and custom properties inherit through shadow roots; `data-mode="dark"` on `<html>`.
- **Testability hook.** The host element carries `data-ds="<Name>"` (set in `connectedCallback`). Older components lack it; add it to any file you touch.
- **Parts and props.** `part` and `data-part` values are the anatomy names verbatim; a part drawn as a pseudo-element has no hook. An override for a composed child's binding is forwarded to the child's `overrides` property (or its documented `--ds-<child>-*` hook set from the parent's hook), never by styling the child's shadow tree.
- **Booleans that default to true.** A boolean attribute cannot express false, so a prop whose doc default is `true` (`dismissible`, `stickyHeader`, `showValue`) keeps its name as a property and is exposed as the negated attribute (`no-dismiss`, `no-sticky-header`, `hide-value`); reflect the negated form. Never change the doc's prop name.
- **Names tests can read.** Set `role` and `aria-label` that the accessible-name tests must observe as plain attributes on the host; `ElementInternals.ariaLabel`/`role` are not read by dom-accessibility-api. Use ElementInternals for form association and for ariaLabelledByElements only.
- **Native member collisions.** A doc prop that collides with an HTMLElement member is a doc bug — report it as a gap rather than renaming locally. Docs avoid `title`, `id`, `hidden`, `draggable`, `style`, `class`, `role` as prop names (overlays use `heading`, Toast uses `toastId`, BottomSheet uses `dragToDismiss`).
- **Form fields.** Every field component's root carries `data-ds-field` (plus `data-ds`); Form discovers fields by that attribute, never by a tag or component list. A field's label is a native `<label for>` styled from the field's label bindings; description and error text are Text.
