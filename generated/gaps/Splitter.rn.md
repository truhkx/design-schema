# Gaps reported while generating Splitter for rn

Each entry is a place the doc made the generator guess. Fix the doc, re-run parse, regenerate.

## 2026-09-10 16:38 — round 1

- minSize's description references a `collapseThreshold` that isn't a declared prop anywhere in the schema; I treated `minSize` itself as the collapse trigger (drag/step below minSize collapses when `collapsible`).
- persistKey: the spec calls for 'AsyncStorage when available, else memory', but AsyncStorage is a third-party native module and the package conventions permit only react-native-svg as a runtime dependency, so I implemented persistence as a module-scoped in-memory Map only — it survives a remount but not an app restart, unlike the spec's intent.
- The separator must be a plain View carrying a PanResponder directly (the same constraint documented on Slider's thumb: spreading panHandlers onto Pressable fights its own gesture responder), and a bare View has no onFocus/onBlur in this RN version's types, so the separator itself cannot show a keyboard focus-visible ring — acknowledged platform limit, same as SliderThumb. The composed collapse Button still gets full focus-visible treatment.
- Keyboard model rows for Home/End and the separator's own Enter-to-collapse have no hardware-key equivalent reachable from a bare View; I exposed them as custom accessibilityActions (setMinimum/setMaximum/activate) rather than physical key handlers. F6 pane-cycling has no native/accessibility-action equivalent at all and is not implemented.
- The RN platform notes only describe stacking 'below the prose max' (i.e. the stackBelow default); I generalized this to honor all three stackBelow enum values (prose/content/never) per the schema's prop table, mapping content to layout.maxWidth.content and never to no stacking, which the RN notes don't explicitly confirm.
- handleSize (overridable) and minTarget (locked) both describe the separator's touch footprint without stating how they compose; I implemented the effective hit area as max(handleSize, minTarget) so the locked floor can never be overridden away.
- collapseButtonOffset's anchor/direction isn't specified; I anchored the button to one edge along the drag axis and centered it on the cross axis using a translate of half of Button's known minimum target size (its actual rendered size isn't known ahead of layout).
- separatorHover (locked) has no meaning on a touch-only platform (no pointer hover); left unused — only separatorActive (colorControlSelectedBackground) is applied while dragging.

## 2026-09-16 12:53 — round 1

- Splitter: the rn guidance says 'persistKey via AsyncStorage when the package is present', but the persistKey prop and the package rule forbid any storage dependency; chose the module-level memory map.
- Splitter: the rn guidance says 'Stack below the prose width' as if fixed, but the stackBelow prop says all three values apply on every platform; chose prose/content/never from layoutMaxWidthProse/layoutMaxWidthContent, measured with onLayout on the splitter's own width. Before the first layout (and in the Jest renderer) it renders side by side.
- Splitter: the spec doesn't say whether onSizeChangeEnd fires when a drag collapses the pane past minSize; chose to fire only onCollapseChange and ignore the rest of that drag, with no end event.
- Splitter: the minSize prop says 'stepping below it collapses', but the Home action sets minSize and doesn't collapse; chose: decrement below minSize collapses when collapsible, setMinimum clamps to minSize.
- Splitter: separatorActive is described as 'while dragging or focused', but the rn separator is a plain View with no focus events; it applies only while dragging.
- Splitter: the transition binding covers the separator colour on web; on native the colour switches instantly (only collapse and restore animate). The spec doesn't say whether native should animate the colour.
- Splitter: the grip is a 'rounded bar', but no radius binding is given; used t.radiusFull.
- Splitter: the collapse Button's Icon names and colour are not specified; chose chevron-left/right (horizontal) and chevron-up/down (vertical) by collapsed state, coloured t.colorActionGhostForeground.
- Splitter: 'centered across the separator and overlaps both panes' can't be done inside the thin separator View on Android (touches outside a parent's bounds are dropped); the Button is a positioned sibling placed from the measured separator position and Button size.
- Splitter: handle size uses hitSlop on native, but react-native-web ignores hitSlop on View; added an absolutely positioned handle child that overflows the separator so the grab area works on web too. The spec doesn't say how RN should render the handle part.
- Splitter: accessibilityActions increment/decrement/setMinimum/setMaximum have no copy for their labels; left them unlabelled (the system supplies names for increment/decrement) and labelled activate with copy.collapse/expand.
- Splitter: keyboard rules say hardware Enter should activate on native, but the rn notes expose Enter, Home and End only as accessibility actions, and RN 0.87 View has no typed key handler; hardware arrow/Home/End/Enter keys on react-native-web do nothing.
- Splitter: paneMinTarget on native is applied as minWidth/minHeight on both panes on the drag axis (dropped for the primary pane while collapsed); the CSS minmax() wording has no RN mapping stated.
- Splitter: example stories pass plain strings as primary/secondary, which crash on native outside Text; the component wraps string/number pane content in Text (as Disclosure does). The spec doesn't say how content props should handle strings.
- Splitter: copy.sizeText's percent param is not specified as rounded; passed the size value as-is (drag produces fractional percents, e.g. '37.4812%').

## 2026-09-17 16:14 — round 1

- Splitter: a11y.role is `separator`, which React Native has no role for, while platforms.rn prescribes accessibilityRole="adjustable". The derived `has-accessible-name` scenario therefore generates `getByRole('separator')` in generated/behavior/Splitter.rn.test.tsx, which can never match on RN; the hand-written test queries `adjustable`. The doc needs an explicit role mapping for rn.
- Splitter: minSize's clamp-then-collapse rule ('an arrow step that would cross it from above clamps to minSize first, and the next shrink step from minSize collapses; Home sets minSize and never collapses') is written for keys, and rn has none. I mapped it onto the decrement accessibility action and let setMinimum never collapse.
- Splitter: 'a key press at a bound (End at maxSize, Home at minSize) fires nothing' is stated only for keys. I applied the same rule to increment/decrement/setMinimum/setMaximum: no onSizeChange/onSizeChangeEnd when the clamped target equals the current size.
- Splitter: onSizeChangeEnd says 'a drag always fires it once on release'. I fire it on every PanResponder release, including a tap on the separator that never moved (so a stray tap emits an end event with an unchanged size), and not on PanResponderTerminate — the doc does not say whether a cancelled gesture counts as a release.
- Splitter: the handle's hit area is specified as max(handleSize, minTarget) delivered as an absolutely positioned overflowing child because react-native-web ignores hitSlop; the doc does not say whether native should also get hitSlop. I set both, so native has the wider grab area too.
- Splitter: collapseButtonOffset while collapsed says the button 'aligns to the secondary pane's start edge' but gives no measurement. I place its cross-axis start at separatorOffset + separatorSize (no centring), since centring would put half the button outside the container.
- Splitter: the locked bindings separatorHover, focusRing and focusRingWidth have no rn expression — the separator is a plain View with a PanResponder, so it has neither hover nor focus events. They are unused on this platform; only separatorActive (dragging) applies. The doc acknowledges the focus-ring limit but still lists focusRing/focusRingWidth as bindings for every platform.
- Splitter: paneMinTarget is required on both panes, but the secondary pane is `flex: 1`, so on a narrow container the two floors plus the separator can exceed the container — the web note allows this ('a very narrow container can therefore show the pane wider than its percent') but the rn note does not say which pane wins. I let flexbox shrink the secondary.
- Splitter: persistKey's memory map is not specified for controlled use. I restore from it on mount (over defaultSize/defaultCollapsed) and write on every change even when `size`/`collapsed` are controlled; the doc does not say whether a controlled instance should participate at all, nor whether the stored size or the incoming default wins.
- Splitter: stacking and collapsing can overlap and the doc does not resolve it. I render both panes in full while stacked and keep the collapsed state latent (no hiding, no collapse Button), restoring it when the splitter grows past the breakpoint.
- Splitter: copy.sizeText is 'rounded to a whole number (as is aria-valuenow)' while onSizeChange is explicitly unrounded — I report Math.round to accessibilityValue and the unrounded value to the events. The doc also gives valuemin 0 while collapsed but says nothing about valuemax, which I leave at maxSize.
- Splitter: gripLength and gripRadius carry no `part`, unlike the other bindings. I treat them as part of the grip mark inside the separator (no separate testID); the anatomy list has no `grip` entry even though the grip binding exists.
- Splitter: the Keyboard story is required for every component with a keyboard block, but every keyboard rule is web/lit on this platform. I ship it (four focusable children plus the collapse Button) documenting that hardware keys do nothing on an RN View, which makes it a visual/axe fixture rather than a keyboard fixture.

## 2026-09-21 23:06 — round 1

- Splitter: onSizeChangeEnd says "a press that never moved the separator is not a drag", but native pan responders emit move events with a zero delta, so "moved" is undefined on RN. Chose: the first non-zero delta on the drag axis (cross-axis movement alone does not start a drag).
- Splitter: the spec forbids no-op size events only for the key/accessibility actions, saying drags fire "continuously". Chose: no dedupe on drag, so holding the pointer past maxSize re-fires onSizeChange with the same clamped value on every move.
- Splitter: paneMinTarget says "the secondary pane gives way first" when the container is too narrow for both floors plus the separator, but a RN minWidth/minHeight is a hard floor, not a preference — the secondary shrinks to its floor and then the container overflows rather than dropping below it. Chose: hard floors on both panes, flexShrink 0 on the primary, dropped on the primary while collapsed.
- Splitter: the rn notes list the `activate` accessibility action unconditionally, but the behavior scenario enter-does-nothing-when-the-pane-cannot-collapse says activation must do nothing without `collapsible`. Chose: register `activate` only when `collapsible`, so assistive tech is never offered a no-op action.
- Splitter: the collapse Button is "placed from its measured position", but nothing says where it sits before the first onLayout of the separator and the Button. Chose: offsets of 0, so it renders at the container's start edge for one frame, then settles.
- Splitter: "collapsed content is inert" has no RN equivalent, and the package convention forbids accessibilityElementsHidden on a View containing a Pressable (aria-hidden-focus). Chose: accessibilityElementsHidden + importantForAccessibility="no-hide-descendants" + pointerEvents="none" together on the collapsed primary pane, so nothing hidden stays tappable; the convention's hazard does not apply. Never applied while stacked.
- Splitter: `transition` says collapse and restore animate on native but not which property. Chose: an Animated.Value interpolated to the primary pane's flexBasis percentage (useNativeDriver false, since react-native-web has no native driver); the separator colour switches instantly, per the binding.
- Splitter: stackBelow's enum description maps only `content` (layout.maxWidth.content) and `never`. Assumed `prose` = layout.maxWidth.prose by the same rule.
- Splitter: the RTL arrow/chevron mirroring is specified for web and Lit only. Chose: no I18nManager.isRTL consultation at all on RN — the drag maps raw dx and the chevron is chevron-left expanded / chevron-right collapsed regardless of layout direction.
- Splitter: nothing says whether a controlled `size` outside minSize..maxSize is clamped for display. Chose: clamp it (the events still report the caller's own value back unchanged, since a controlled component only re-renders from its prop).
- Splitter: the separator has no `focusable` guidance for react-native-web, where the spec only rules out a focus ring. Chose: focusable on the separator View so it stays a tab stop (matching the web Tab rule) even though it cannot show a ring.
- Splitter: persistKey is "remembered per user" in a module-level map, with no eviction, key namespacing or bound on the map's size specified. Chose: an unbounded Map keyed by the raw persistKey.
