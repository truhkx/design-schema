Show visitors where they are: mark the current page in the docs sidebar and header, and scroll it into view, per site/src/content/docs/process/website-audit-2.md, section "Current location". Read that section first.

Today apps/website/src/components/DocsSidebar.astro computes `current` from `Astro.url.pathname` and DocsNav.tsx passes `aria-current="page"` through `...rest` on the matching Link — so the state exists for assistive technology, but measured on 2026-09-24 the current link is visually identical to every other (same colour, weight 400, no background, no indicator), and on a page far down the list (BottomSheet: link at y≈1224 in an 876px-tall sidebar) the sidebar opens scrolled to the top, so the current entry is not on screen at all. The header's Docs / About links carry no current state either. The Link component's own doc (components/link.md, `current`) says marking a current link visually "is that container's to say" — so this is the site's job, not Link's.

1. **Use the prop.** DocsNav.tsx and HeaderNav.tsx pass Link's `current` prop (not a raw `aria-current` through rest). The header marks Docs current on every `/docs/*` route and About on `/about`; the docs sidebar marks the exact route. Normalise trailing slashes on both sides of the comparison in one helper in apps/website/src/nav.ts so `/docs/components/menu/` and `/docs/components/menu` match.
2. **Style it.** In docs-sidebar.css, `.ds-docs-nav__sidebar [aria-current="page"]`: `font-weight` from the medium weight token, colour `color.foreground.strong`, a `border.width.focus`-wide inline-start indicator in `color.action.primary.background` (or the theme's accent token if one exists — read the token sheet), and `color.background.subtle` behind it with `radius.sm`. Not colour alone (WCAG 1.4.1): the weight and the bar carry it. Header: the current link gets the same weight and an underline that stays (the hover-only underline rule from job 530 must not remove it). Tokens only; check light and dark in both themes with the contrast walker (text 4.5:1, indicator 3:1 against its background).
3. **Open the group.** The phase Disclosure containing the current page is open on load even if the visitor collapsed it on another page (the groups are `defaultOpen` today; keep that, but make sure a future collapsed-by-default change cannot hide the current page).
4. **Scroll into view.** On load, scroll *the sidebar's own scroller* (`.ds-docs-nav__sidebar`), not the window, so the current link sits in the upper third of the box: set `scrollTop` from the link's offset within the scroller; never call `scrollIntoView` (it scrolls the page too). Respect `prefers-reduced-motion` (instant), do it before first paint where possible (an inline script in DocsSidebar.astro keyed on the `aria-current` element avoids a visible jump after hydration), and do not move focus. The mobile Select already shows the current page; leave it.
5. **Guard.** A Playwright spec: at 1280×900, on `/docs/components/bottomsheet/`, `/docs/components/treegrid/` (last in the list) and `/docs/components/icon/` (first), the current link is inside the sidebar's visible box, carries `aria-current="page"`, has a computed font-weight greater than its siblings', and the window's `scrollY` is 0. On `/docs/foundations/`, the header's Docs link is current. Run it in both themes and both modes.
