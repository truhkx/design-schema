# Gaps reported while generating DatePicker for web

Each entry is a place the doc made the generator guess. Fix the doc, re-run parse, regenerate.

## 2026-09-10 11:48 — round 1

- DatePicker: composition requires monthSelect/yearSelect to be Select, but Select always renders a visible block label above its trigger (no visually-hidden-label option) and has no `size` prop despite the platform notes saying 'size: sm' — the header is denser than a typical '‹ September 2026 ›' calendar header, and `size` was simply omitted since Select doesn't support it.
- DatePicker: styles.monthTitleSize/monthTitleWeight have no matching anatomy part — the visible month/year text lives inside the composed, never-restyled Select (no 'monthTitle' element exists), so these two override hooks are defined on the root for API-contract completeness but currently have no visual effect. Docs should either add a monthTitle anatomy part or drop the two tokens.
- DatePicker: yearSelect's option range isn't specified anywhere in the schema; defaulted to (current year − 100) … (current year + 50) when min/max are absent, clamped to min/max's year when given.
- DatePicker: wrapped the composed calendar content (Today/Clear/prev/next Buttons, month/year Selects) in `<FormContext.Provider value={null}>` so they don't auto-register as spurious fields or double-inherit `disabled` from an ambient enclosing Form — not called out anywhere in the spec but necessary given how FormContext propagates through composition.
- DatePicker: the range keyboard model registers the field with the Form twice (`name` and `${name}-end`), mirroring the Lit platform note ('two entries for a range, name and name-end'), since the web FormContext's FormFieldValue type has no way to carry a `{start,end}` object.
- DatePicker: Escape's 'returns focus to the calendar button' (expect: focus-trigger) is delegated entirely to the composed Popover + FocusScope's generic restore-to-previously-focused-element behavior. That matches exactly when the calendar was opened by clicking the button, but when opened via ArrowDown from the input, focus restores to the input instead — Popover's cloneElement(trigger) claims the sole ref slot and doesn't expose the trigger node back to the composing component, so DatePicker has no way to pre-focus the button before opening.
- DatePicker: onChange is only fired once a value is complete (any single-date pick, or both ends of a range) or on an explicit Clear — picking just a range's start, or typing a partial/incomplete date, updates state silently. The spec's 'fired when a complete valid date...is typed or picked' doesn't state what happens on in-progress picks, so this was the most literal reading.
- DatePicker: anatomy omits a 'weekNumber' part even though `showWeekNumbers`/`copy.weekNumber` clearly imply one; added `data-part="weekNumber"`/a week-number header cell anyway.
- DatePicker: when the locale's first day of week isn't Monday, a visual grid row spans two different ISO 8601 weeks; the week-number column shows the ISO week of the row's first (leftmost) visible day rather than resolving both.
- DatePicker: typed-date parsing is a best-effort lenient parser (digit groups split on non-digit runs, or one unbroken digit run sliced positionally by the locale pattern's field order) rather than a fully specified grammar; unusual locale separator/order combinations may not parse perfectly.
- DatePicker: no schema binding exists for the gap between label/description/field/error, or between the input(s) and the calendar button within the field row (unlike Input's `partGap`); used direct `space.1`/`space.2` tokens rather than an overridable hook.
- DatePicker: `calendarSurface` has no separate surface to paint on web — the calendar renders inside the composed Popover's own (locked) panel background, so this binding is realized by Popover's surface rather than DatePicker's own CSS.
- DatePicker.stories: there is no controlled `open` prop in the schema (unlike Popover/Menu), so the `Keyboard` story force-opens the calendar with a mount-time programmatic click on the trigger button inside a small render-function wrapper, instead of an `open` arg.

## 2026-09-10 19:08 — round 1

- DatePicker (existing implementation) was missing the `size` (sm/md), `hideLabel`, and `open` (controlled) props, the `data-ds-field` field-discovery hook, and the `paddingBlockSm`/`paddingInlineSm`/`fieldGap`/`minTargetSm`/`partGap` overridable bindings entirely — added all of these to match the schema; also the month/year Selects were rendered with a visible label instead of the spec's `hideLabel size="sm"`, now fixed.
- styles.monthTitleWeight says it 'forwards to the Selects as `overrides.fontWeight`', but Select's SelectOverridableBinding has no `fontWeight` entry (only `labelWeight`, which targets Select's own label Text, not its value text). I forward `monthTitleSize` to the Select's `fontSize` override as specified, but `monthTitleWeight` has no matching Select API to forward into, so it only sets the (currently unused) root CSS hook — Select needs a `fontWeight` override binding added to its own schema for this to be realized as documented.
- keyboard model requests 'Tab cycles within the calendar: month/year controls, the grid (one tab stop, roving over days), Today, Clear' — this is native tab order through the composed Select/Button/day-grid elements as rendered, not custom-trapped; I did not add an explicit focus trap beyond what Popover already provides for a non-modal popup, since DatePicker's a11y.role is `none` (not `dialog`) and the spec doesn't list `focus-trap`/`inert-background` in `a11y.requires` for this component.
