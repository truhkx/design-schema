# Gaps reported while generating Combobox for lit

Each entry is a place the doc made the generator guess. Fix the doc, re-run parse, regenerate.

## 2026-09-10 10:09 — round 1

- Combobox: the behavior prose says typing 'opens the list with no active option,' but the `filter: none` prop description says typing 'only moves the active option' (a typeahead-like behavior) — implemented the general no-active-option rule for startsWith/contains/async, and a first-match-startsWith typeahead activation (without filtering `options`) only for `filter: none`.
- Combobox: the dedicated `Alt+ArrowDown` key rule ('opens the list without moving the active option') contradicts the inline mention inside the `Home`/`End` rule's action text ('Alt+ArrowDown/Up jump the list to first/last'). Implemented only the literal, dedicated `Alt+ArrowDown` entry; no `Alt+ArrowUp` handling was added since it has no rule of its own and the keyboard section says to implement exactly what is listed and nothing else.
- Combobox: `allowCustom`'s prop description says 'Enter or a separator (comma) commits it,' but the `keyboard` block — which the instructions say to implement exactly and nothing else — only lists Enter as a commit key. Implemented Enter only; comma-as-commit was not added.
- Combobox: `aria-activedescendant` on the `<input>` cannot resolve as a plain id string across the shadow-root boundary between `<ds-combobox>` and the internally-rendered `<ds-listbox>` option elements (two separate shadow trees). Implemented via the cross-root `ariaActiveDescendantElement` IDL reflection where the browser supports it, with the id string set as a best-effort fallback attribute; Select.ts's existing combobox-style trigger has the same architecture and does not set activedescendant at all.
- Combobox: `DsFormField.currentValue` is typed `string | boolean | null`, but a `multiple` combobox's value is `string[]` — the same caveat Listbox documents for itself; `<ds-form>` does not currently discover `ds-combobox` by tag.
- Combobox: the ~500ms debounce for the `status` live region is specified only in the Web/React platform notes as `motion.duration.base × 2`; Lit's own platform notes give no value, so a plain (non-token) timing constant was used, following the precedent Listbox sets for its own typeahead-reset timer.
- Combobox: diacritic-insensitive filtering is called out only in the Web platform notes ('Filtering is case- and diacritic-insensitive'), not in Lit's; implemented case-insensitive matching only.
- Combobox: 'Clicking the toggle button opens the full list' was interpreted as showing `options` unfiltered by any currently-typed query for that opening (reset on the next keystroke), since the schema does not say what happens to already-typed text at that moment.
- Combobox: no prop exposes the popup's open/closed boolean state (as with Select and Menu), so the `Keyboard` story opens it imperatively in `play` by clicking the composed toggle button's inner native button, matching the Select generator's precedent.
- Combobox: what a controlled `inputValue` should become after a commit (Enter, option click, clear) is undocumented — left to the consumer to update from `change`/`input-change`; only the uncontrolled `internalText` is set by the component itself.

## 2026-09-16 08:49 — round 1

Like ds-select, the input gets no aria-activedescendant; the active option's label (copy.activeOption) is in a polite live span linked by aria-describedby. The doc should say which mechanism Lit uses, or Listbox needs a way to render its options into the host's tree.
- Combobox: nothing says which option is active when the list opens other than by typing (typing: none; ArrowDown: first match). Following React: opening via the toggle button, ArrowDown or the `open` prop makes the selected option active, else the first; ArrowUp takes the selected option, else the last; Alt+ArrowDown takes the selected option only. The enter-commits-the-active-option scenario (given open: true, no typing) only passes because of this choice.
- Combobox: onInputChange says 'every keystroke', but the text also changes on commit (single shows the label, multiple clears), on Escape-to-clear and from the clear button. input-change fires on every text change caused by the user, as React does; the doc should say whether async consumers should see those non-keystroke changes.
- Combobox: `open` is listed under platforms.lit.reflect but has no default (undefined = uncontrolled). Reflecting it only reflects the controlled property, so an uncontrolled open list has no `open` attribute on the host; no style binding reads it. Doc should say whether the attribute should mirror the effective state.
- Combobox: `clearable` defaults to true, so the attribute is the negated `no-clear` (reflected). The doc doesn't name the attribute.
- Combobox: the Keyboard section excludes ArrowDown/ArrowUp/Enter/Backspace/','/Alt+ArrowDown by `expect: manual` only through the schema list; all nine rules are implemented. PageUp/PageDown and letter typeahead from Listbox are not forwarded, since the combobox rules don't list them (typing goes into the input).
- Combobox: style binding fieldBorderFocus is stated for `:focus-visible` in the contract, but the web notes style the field via `:focus-within` (the focus lands on the inner input, and on chip remove buttons inside the field). Used :focus-within on the field.
- Combobox: popupBorder names a color token but no width; used border.width.thin, as Select does. partGap, helperSize, fontSize, fontFamily and lineHeight have no part; applied to the part grid gap, the description/error Text, the label/field text respectively. iconColor and placeholderColor have no part; forwarded iconColor to each ds-icon's `color` override (toggle, clear, chip remove) and placeholderColor to the input ::placeholder.
- Combobox: `enter` (motion.duration.fast) has no described target; used it for the popup's opacity fade (removed under reduced motion), as Select does.
- Combobox: 'Tab closes the list' only specifies single-select not committing; multiple doesn't commit on Tab either.
- Combobox: no rule for clicking the already-selected option in single mode (Listbox reports no change); it closes the list and restores the label, matching React.
- Combobox: statusDebounce reads --motion-duration-base from the host's computed style at run time (× 2); under a reduced-motion theme that zeroes the token, the announcement would not be debounced. Doc should say whether this constant follows reduced motion.
- Combobox: Intl.PluralRules needs a locale and the component has no locale prop; used the nearest [lang] ancestor, else the runtime default.
- Combobox: required indicator copy ' (required)' is rendered inside the label (so it is part of the accessible name), as Select does; the doc doesn't say whether it belongs in the name.

## 2026-09-21 14:04 — round 1

- Combobox: the Lit platform note says the chipRemove/clearButton/toggleButton parts are wrapper elements around their <ds-button>s, but that constraint is a React one (React's Button sets data-part="container" on the same node). On Lit, ds-button's data-part lives in its own shadow root, so there is no collision, and the package precedent (Search.ts) puts data-part/part directly on the <ds-button>. Followed Search; the note should be scoped to web or dropped for Lit.
- Combobox: the Keyboard story cannot satisfy the keyboard table with `open` alone. `open` is a controlled prop, so a story that only sets open:true never closes and the Escape/Tab `expect: closes` rules fail. The doc should state (as React's story comment does, but nothing in the Lit contract does) that the Keyboard story owns `open` and writes open-change back; that is what was implemented.
- Combobox: `open` is listed in platforms.lit.reflect, but the same note says the element's own mirror writes of the attribute must not make it controlled. Lit's reflect:true cannot distinguish its own reflection from a consumer's write. Used a manual mirror (toggleAttribute in updated() behind a flag, plus an attributeChangedCallback that ignores the self-write) instead of reflect:true — the doc should say `open` is mirrored, not reflected.
- Combobox: aria-controls has no Lit answer. The web attribute list points it at the listbox, but on Lit the role="listbox" element is inside <ds-listbox>'s shadow root and an IDREF cannot reach it (the same reason the note gives for dropping aria-activedescendant). Pointed aria-controls at the popup <div> that contains the Listbox.
- Combobox: the `status` part's Lit presentation is unspecified. The RN note makes it visible small muted Text; the web note makes it a visually hidden role="status" region; the Lit note is silent. Used the web treatment (visually hidden, aria-live="polite").
- Combobox: statusDebounce says 'when it cannot be read (jsdom) there is no debounce', but Lit's tests run in real Chromium so the timer is always live, and the doc does not say what the region should announce when the list closes before the timer fires. Chose to clear the pending timer and blank the region immediately on close.
- Combobox: Escape's second action is gated on `clearable`, but `clearable` is documented only as 'Show a clear button when there is a value or text'. It is unclear whether `no-clear` is meant to suppress Escape-clears-text as well. Followed the keyboard table literally and gated it on `clearable`.
- Combobox: the doc never says what value a cleared single-select reports. `form.valueType` is string[] and onChange's payload is `string | string[]`. Chose '' for single and [] for multiple; the behavior scenario `the-clear-button-clears-the-value` only asserts that onChange fires.
- Combobox: copy.activeOption is written to a live span linked by aria-describedby, but the doc does not say whether that span stays in aria-describedby when no option is active. Included it only while the list is open and an option is active, so the description never carries a stale label — at the cost of the describedby list changing as the user arrows.
- Combobox: the resultCount locale is 'the nearest `lang` ancestor's locale on web and Lit'. From inside a shadow root, closest('[lang]') only sees light-DOM ancestors of the host; the doc does not say whether to fall back to document.documentElement.lang. Used closest('[lang]') then the runtime default.
- Combobox: with multiple + allowCustom, committing text that matches an already-selected option 'leaves it selected (no onChange) and clears the text' — but the doc does not say whether input-change fires for that clear. Fired it, reading onInputChange's 'the text a commit ... leaves behind' as covering it.
- Combobox: the doc says a chip 'truncates with an ellipsis once the row runs out of room rather than at a fixed character count', but declares no max-width or flex binding for the chip, so the truncation point is undefined. Used min-inline-size:0 + text-overflow on the chip label within the wrapping field row.
