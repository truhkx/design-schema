# Gaps reported while generating DataGrid for rn

Each entry is a place the doc made the generator guess. Fix the doc, re-run parse, regenerate.

## 2026-09-10 14:05 — round 1

- DataGrid: `selectable: 'range'` has no touch or hardware-keyboard equivalent on native (no drag-rectangle gesture, no Shift+Arrow); it degrades to `'row'` with a `__DEV__` warning, per the platform notes' own guidance. `rangeOverlay`, `rangeBackground`/`rangeBorder`/`rangeBorderWidth` bindings and `copy.selectedRange` are consequently unreachable on this platform.
- DataGrid: Ctrl+C copy-as-TSV has no implementation — core React Native ships no clipboard API and the package permits no extra dependency (only react-native-svg). `copy.copied` is defined for API/copy parity but never surfaces.
- DataGrid: the `date` editor has no package `DatePicker` to compose (the rn package doesn't have one, unlike the schema's Related list), so it falls back to a plain `TextInput` like the `text` editor — same as `select` would if Listbox didn't exist. Flagged since the doc implies a distinct date-picking UI.
- DataGrid: the full APG keyboard model (Tab as single stop with roving/activedescendant focus, Arrow/Home/End/PageUp/PageDown cell navigation, Space row toggle, Ctrl+A) has no hardware-keyboard listener wired on native Views — only Enter/Escape are caught, and only inside the inline text/number editor (via TextInput's onKeyPress, which is the sole RN element that reliably receives key events, and mainly on react-native-web per the platform notes). Touch equivalents are substituted instead: tap a cell to select/edit it, tap the select-all checkbox for Ctrl+A-row, sort by tapping the header button. `copy.position` (the aria-activedescendant announcement) is consequently unused.
- DataGrid: `aria-rowcount`/`aria-colcount`/`aria-rowindex`/`aria-colindex`/`aria-sort`/`aria-multiselectable`/`aria-readonly` from the web attribute list have no RN equivalents; per-cell/-row position is only implied by `accessibilityLabel` content, not announced numerically.
- DataGrid: pinned columns do not truly stay put during horizontal scroll — RN has no `position: sticky` and the package forbids a gesture-handler/reanimated dependency for a second synced FlatList (the schema's own suggested approach), so pinned columns scroll with the rest and only gain `pinnedShadow` once scrolled, the same approximation Table already uses for its sticky row-header column.
- DataGrid: the schema's `platforms.rn.props` lists `accessibilityRole=grid`, but RN's `AccessibilityRole` type has no `'grid'` member (a TS error). Used the newer ARIA-aligned `role` prop instead (`role="grid"`/`"row"`/`"rowgroup"`/`"columnheader"`/`"rowheader"`), per the package convention to prefer `role` where a web semantic exists; RN's `Role` union also has no `'gridcell'`, so plain cells use `role="cell"`.
- DataGrid: column resize is implemented via core `PanResponder` (drag) since gesture-handler is disallowed; there's no accessibility-action or arrow-key equivalent for adjusting a resizable column non-visually, only the visible drag handle.

- DataGrid: anatomy lists a distinct "body" rowgroup part, but FlatList has no built-in wrapper to give the set of body rows its own role/testID separate from the header rowgroup and each row; left unimplemented since RN's List primitives don't expose that seam.
- DataGrid: the web keyboard model's arrow/Home/End/PageUp/PageDown navigation and Ctrl+A select-all are not implemented even for react-native-web, despite the schema's own note that "Arrow keys apply only on react-native-web" — core RN has no onKeyDown on View/Pressable, and wiring a DOM-only path felt out of scope for a component that is otherwise touch-first (per the doc, phones are a poor fit for DataGrid); flagging this as the biggest behavioral gap versus the schema's keyboard block.

## 2026-09-16 11:57 — round 1

- DataGrid: platforms.rn.props puts role=grid and accessibilityLabel on the FlatList, but the rn notes say the list itself carries role="rowgroup" for the body. Chose the props list: the FlatList is role=grid named by the caption, the header row has its own rowgroup, and body rows have no rowgroup element.
- DataGrid: onCellChange's value/previous are declared string | number | boolean, but the Delete rule commits `undefined`, a cleared NumberInput produces undefined, and a row may have no value for a key. Typed both as `string | number | boolean | undefined` (exported as DataGridCellValue).
- DataGrid: when a number or date editor commits is undefined on native. NumberInput has no onBlur and fires onChangeText on every keystroke; DatePicker only has onChange. Chose: these commit when another cell or a sort header is pressed, or through the editing cell's `activate` accessibility action; `escape` cancels. Input commits on blur; Select and Checkbox commit on change. An open number or date editor stays open if focus leaves the grid.
- DataGrid: the spec gives no copy for the editable-cell hint. The rn notes' literal "double tap to edit" is used as a hard-coded English string outside `copy`.
- DataGrid: the caption's Heading level is not in the schema (DataGrid has no captionLevel prop, unlike Table). Used level 2, size md.
- DataGrid: the default column width 160 is a documented literal (`literal-ok`). The Constants rule says to read constants through token expressions, but there is no token for it.
- DataGrid: cellInvalidForeground has nowhere to go. The invalid cell holds a composed editor that must not be restyled, and the message goes to the status bar, whose color (statusBarColor, muted) is locked. Left unused; cellInvalidBackground and cellInvalidBorder (drawn as an inset ring) are applied.
- DataGrid: cellMutedColor has no stated use. Applied only to the empty-state Text (tone muted).
- DataGrid: rangeBackground, rangeBorder and rangeBorderWidth are unused because selectable=range degrades to row on native (with a __DEV__ warning), as the notes say.
- DataGrid: overrides.fixedHeight defaults to space.20 (80px), which with a sticky header leaves less than two compact rows. Kept the token as specified; the RangeSelectionInAFixedHeightGrid example renders very short.
- DataGrid: height viewport's `100vh − 2 × layout.gap.section` was read on native as window height minus 2 × t.layoutGapSection, the same as Table.
- DataGrid: onRangeNeeded's `end` was read as an inclusive last index, and `one page` as the list's measured height divided by row height (onEndReachedThreshold=1). It fires once per end until data.length changes.
- DataGrid: the editor inset-zero overrides assume a `space.0` TokenRef. Select's names are triggerPaddingInline/Block, not paddingInline/Block, so the per-editor mapping is inferred.
- DataGrid: the Select editor is opened immediately (`open`) and closing it without choosing cancels the edit. The notes' BottomSheet on phones comes from Select's own native=auto behaviour, not a separate BottomSheet.
- DataGrid: pinned columns keep their position in `columns` (not reordered) and cast pinnedShadow on both start and end pins once scrolled sideways. The spec only says pins must be contiguous.
- DataGrid: resizeHandle is visible on hover/focus of the header cell per the doc. On touch there is no hover, so the handle is invisible until dragged; it is hit-slopped to size.target.min.
- DataGrid: rowHover is applied as a tint under the cells. The select cell (which has its own background) is not tinted.
- DataGrid: copy.selectedRange and the whole keyboard table (arrows, Home/End, Page keys, Enter/F2/Space, Ctrl+A, Delete) have no native implementation, as the notes say. Only the resize increment/decrement and the editor activate/escape accessibility actions stand in.
- DataGrid: the old RN exports DataGridCellChange and DataGridRangeNeeded are removed now that payloads are positional. DataGridColumnResize is kept only because TreeGrid.tsx imports it for its own object-shaped onColumnResize, which is now inconsistent with DataGrid's positional one.

## 2026-09-17 14:27 — round 1

- DataGrid: `captionLevel` has no observable effect on React Native — Heading sets the header trait regardless of level, and `captionSize`/`captionWeight` pin the typography, so the prop is inert here. It is accepted and forwarded to Heading for parity, but the three derived `renders-caption-level-*` scenarios can only assert that the grid renders. The doc should say the prop is documentation-only on rn, as Heading's own doc does.
- DataGrid: the schema's `height: viewport` text reads '100vh − 2 × layout.gap.section — the window height on native', which can mean either 'subtract twice the section gap from the window height' or 'just use the window height'. I took the first (identical to Table's rn rule) and applied it to the root View, with the scroll region flexing into what the caption and status bar leave.
- DataGrid: `copy.selectedRange` and the `rangeOverlay` part, `rangeBackground`, `rangeBorder` and `rangeBorderWidth` bindings have no code on rn at all, because the platform notes degrade `selectable: range` to `row`. The doc lists them without marking them web/lit-only, so the gap report is the only place this is recorded. Same for `copy.position` in `row`/`none` mode: there is no active cell on touch outside `cell` mode, so the Text only appears once a cell has been tapped in `cell` mode.
- DataGrid: nothing can clear a cell on native. The Delete/Backspace rule is the only path to `onCellChange` with `value: undefined`, keyboard rules do not apply on rn, and the doc names no visible clear affordance (the editors themselves can be emptied, but only the number editor produces `undefined` that way). An editable grid on rn therefore cannot express 'no value'. The doc needs either an rn clear control or a statement that clearing is web/lit-only.
- DataGrid: the status bar binding lists its items (live message, row count, selection count, scroll hint, position) but not their order or their visibility conditions. I rendered them in that listed order and showed the selection count only when something is selected, and `scrollHint` only while the columns overflow the measured region width and it has not been scrolled sideways yet (the guidance sentence for scrollHint), leaving the row count always visible.
- DataGrid: `selectColumnWidth`'s description ('this plus 2 × cellPaddingInline in the rule') does not say whether the sum is the column's total width or its content box. I made the select column `size.target.min + 2 × cellPaddingInline` wide with no padding of its own, so the checkbox gets the full minimum target.
- DataGrid: `copy.editHint` is 'Double tap to edit', which on rn can only be an `accessibilityHint`. Both VoiceOver and TalkBack prepend their own activation verb, so a user hears 'Double tap to activate. Double tap to edit.' The rn-only copy string should be the predicate alone ('Edit this cell') the way other rn hints in the package are written.
- DataGrid: nothing on rn conveys position among unrendered rows. `aria-rowcount`/`aria-colcount`/`aria-rowindex`/`aria-colindex` carry that on web, and the doc explicitly says `copy.position` is not announced here — so with `rowCount` set (server paging) a screen reader on native is told neither the total nor where the focused row sits in it. The row count in the status bar is visible but never spoken. The doc should either allow announcing `copy.position` on rn or accept the loss in writing.
- DataGrid: `escape-dismiss` is in `a11y.requires`, but the only cancel path for an open editor on rn is the `escape` accessibility action (VoiceOver's two-finger scrub / TalkBack's back gesture). There is no visible cancel control, so a sighted touch user cannot abandon an edit without committing it. The doc should name a visible affordance the way it does for sheets ('drag-to-dismiss ONLY as an addition to a visible close control').
- DataGrid: the column model says pinned columns 'must be contiguous at the start or end of `columns`', but no `__DEV__` warning is specified for violating it (unlike the `isRowHeader` rule, which the package warns about by convention). Since pinning has no layout effect on native beyond `pinnedShadow`, I did not add a warning — but the doc should say whether one is expected, since web and lit will want the same check.
- DataGrid: `aria-readonly={!editable}` has no React Native equivalent, so a read-only grid is indistinguishable from an editable one to a screen reader here; only the per-cell `editHint` distinguishes them. Noting it because the doc lists the attribute under web without saying what stands in for it elsewhere.

## 2026-09-21 21:19 — round 1

- DataGrid: platforms.rn.notes requires each cell's accessibilityLabel to be "{column}: {value}", but the copy block has no key for it (Table has copy.cellLabel). Coined a local COPY.cellLabel with that format; the doc should grow the key so it is translatable.
- DataGrid: statusBarGap contradicts itself on rn — "the position only once there is an active cell (so in row and none mode on rn, where there is no active cell until one is tapped, it is absent)". "until one is tapped" implies tapping a body cell makes it active in every mode; "it is absent" says it never appears. Chose the latter: activeCell is tracked only in cell mode, so copy.position never shows in row or none mode, and cells in none mode stay non-pressable (making them all pressable would turn every cell into a tab stop on react-native-web, against "the grid is one tab stop").
- DataGrid: stickyHeader has no reachable effect on rn. "Always true when virtualized" covers height viewport and fixed, and "with height: content (the page scrolls) it has no effect" covers the rest, so no value of the prop changes anything. Forced sticky whenever the grid virtualizes and added a __DEV__ warning when false is passed; the doc should either drop the prop on rn or say what false means for a virtualized grid.
- DataGrid: columns.render is typed `(row: Row) => unknown` in the shape but the prose says it returns a ReactNode on web and rn. Used `(row: DataGridRow) => React.ReactNode`, so the shape is not verbatim here.
- DataGrid: focusRing is specified as the scroll region's ring "while the grid inside it is :focus-visible" — native has neither focus-visible nor grid-level focus. Drew a border that is always laid out and only recoloured (so focus shifts no layout), lit while a cell Pressable reports focus (react-native-web only; core RN gives View and Pressable no focus events) or an editor is open. On a real device the ring is therefore never visible.
- DataGrid: onRangeNeeded says "Checked on scroll and keyboard moves only, never on mount", but FlatList's onEndReached with onEndReachedThreshold={1} fires at layout for any list shorter than its region. Suppressed the request until the list has scrolled once; the cost is that a grid whose first page does not fill the region never pages at all until the user scrolls, which no wording covers.
- DataGrid: the default fixedHeight is space.20 (80px), which is shorter than one comfortable row plus the header and status bar, so `height: fixed` without an overrides.fixedHeight renders a grid with no visible rows. The doc calls space.20 "the floor, not a recommendation" but a floor below one row is not a usable default; rendered it literally.
- DataGrid: nothing says what an empty grid shows while `loading`. Table puts copy.loading in the empty slot; DataGrid's loading description only mentions the status bar and "existing rows stay". Chose: the empty state always shows `emptyMessage ?? copy.empty`, and copy.loading appears only in the status bar's live region — so `data: []` with `loading: true` shows both.
- DataGrid: copy.resize has no per-direction form, but rn's resize is a pair of accessibility actions (increment/decrement) that each need their own label. Used copy.resize verbatim for both, so a screen reader announces two identically named actions on a resizable header cell.
- DataGrid: rn's commit timing says NumberInput and DatePicker "commit when another cell or a sort header is pressed", with no rule for the grid unmounting or the data changing under an open editor. Chose to drop the draft silently in both cases (no onCellChange), consistent with "an open editor stays open if focus leaves the grid".
- DataGrid: `selectable: cell` says "a move ... to the selection column selects nothing", but the selection column only exists in `row` mode, so that clause is unreachable on every platform.
