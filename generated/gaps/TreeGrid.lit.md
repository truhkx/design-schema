# Gaps reported while generating TreeGrid for lit

Each entry is a place the doc made the generator guess. Fix the doc, re-run parse, regenerate.

## 2026-09-10 14:22 — round 1

- TreeGrid: spec says it 'extends the ds-data-grid implementation (shared base class in the package, not a copy)', but DataGrid.ts is a single concrete LitElement with no exported base class or shared hooks/constants. Implemented TreeGrid as its own self-contained component following the same rendering/keyboard/CSS patterns rather than refactoring DataGrid into a shared base (out of scope for a single-component pass).
- TreeGrid: DataGrid's copy strings for the 'as DataGrid' behaviors (select-all/select-row labels, selected-rows count, sort announcements, editing/invalid/position/row-count/empty/scroll-hint text) aren't exported from DataGrid.ts, so the identical strings were duplicated locally in TreeGrid.ts instead of changing DataGrid's public surface.
- TreeGrid: no `selected`/`defaultSelected` prop exists (unlike DataGrid), so row/cell selection is implemented as fully internal, uncontrolled state — a consumer can't seed or control initial selection, only read it via `onSelectionChange`.
- TreeGrid: `showStatusBar`'s doc default is `true`; per the package's negated-boolean-attribute convention (and DataGrid's own implementation of the identical prop) it should reflect as `no-status-bar`. The schema's own `platforms.lit.reflect` list names it `show-status-bar` instead — followed the convention (`no-status-bar`) over the literal reflect-list spelling.
- TreeGrid: `copy.expandAll`/`copy.collapseAll` have no corresponding anatomy part, prop, or keyboard action anywhere in the schema (only `*` expands one row's siblings) — left unused rather than inventing a toolbar control to hang them on.
- TreeGrid: `copy.level` and `copy.childCount` are declared, but the web platform note relies on native `aria-level`/`aria-setsize`/`aria-posinset` instead of visible/announced text (RN's platform note composes them into `accessibilityLabel` instead) — left unused on web.
- TreeGrid: no `emptyMessage` prop or `copy.empty` string is defined despite `emptyState` (composed Text) being in the anatomy. Reused DataGrid's exact 'Nothing to show.' string as a placeholder since no TreeGrid-specific text was specified.
- TreeGrid: `expand-change`/`expand` event detail shapes aren't specified beyond prose ('the new array of expanded ids' / 'with its id'). Implemented as the bare value (`string[]` / `string`) rather than an object wrapper, matching the prose literally — flagging in case `{ expanded }` / `{ id }` was intended for consistency with the other object-shaped details.
- TreeGrid: `selectChildren` cascading semantics aren't fully specified. Implemented so toggling a row's checkbox cascades that row's own id plus all of its *currently loaded* descendant ids into/out of the internal selection set, while every row's checked/indeterminate visual state is derived independently by counting how many descendants are currently selected (a parent's id is only added/removed when the parent checkbox itself is the one clicked).
- TreeGrid: `DataGridColumn.resizable`/drag-resize (as DataGrid) has no corresponding copy string in TreeGrid's `copy` block (DataGrid needs 'Resize {column}' for the handle's accessible label) and no anatomy part for a resize handle. Omitted the interactive resize handle rather than ship an unlabeled control; static `width`/`minWidth`/`pinned` column sizing is still honored.
- TreeGrid: no `edit-start` event is declared (unlike DataGrid's cancelable event of the same purpose), so `editable`'s 'as DataGrid' behavior starts editing unconditionally with no cancelable hook.
- TreeGrid: `minTarget` (locked, `size.target.min`) and `expandButtonSize` (overridable, default `size.target.min`) both default to the same token with different lock status. Interpreted `expandButtonSize` as the expand button's own overridable visual size, and `minTarget` as a locked `min-block-size` floor on the row so a shrunk override can never drop below the accessible minimum.
- TreeGrid: the `'*'` key action ('Expands every sibling of the focused row') doesn't say whether the focused row itself is included. Implemented inclusively — the focused row and all its same-level siblings that have children are expanded together.
- TreeGrid: guide lines are drawn as one vertical line per ancestor level (via stacked CSS background layers keyed to each ancestor's indent depth), an implementation choice for 'a vertical guide under each open parent... always drawn' since the doc doesn't prescribe the rendering technique.
- TreeGrid: lazy loading fires `onExpand` every time a `children: "lazy"` row transitions from collapsed to expanded, not literally 'once ever' — if the caller never replaces `children`, re-expanding the row refires `onExpand`.
- TreeGrid: no `defaultSort` prop is declared (only controlled `sort`), unlike DataGrid. Added an internal uncontrolled-sort fallback anyway so clicking a sortable header does something visible when `sort` isn't supplied, for parity with DataGrid's ergonomics even though the prop table doesn't ask for it.
