## 2026-09-10 03:06 — round 1

- BottomSheet: above the maxWidth breakpoint the spec says to render Dialog directly ('composition, not duplication'), so the mounted root there carries data-ds="Dialog" instead of data-ds="BottomSheet" — the testability hook differs by viewport; there's no way to satisfy both the composition instruction and a stable root hook at once.
- BottomSheet: hideTitle has no effect in the wide/Dialog presentation, since Dialog's schema has no hidden-title mode and the rule forbids restyling/reaching into composed children. The title is always visible there.
- BottomSheet: overrides (the per-instance token hooks) only apply to the bottom-edge presentation; above the breakpoint the sheet renders as Dialog, which has its own distinct overridable-binding set, so BottomSheet overrides are silently unused in that mode. Not stated in the doc.
- BottomSheet: a11y.requires lists target-44px, but the close button is a composed Button, whose schema only exposes size sm/md/lg (no 'comfortable target' variant), and the rules forbid restyling a child's internals. Used size="md" (the largest available) but can't guarantee the rendered target actually reaches 44px — the gap is in Button's schema, not something this generator can fix without growing it.
- BottomSheet: the exit token's description says a drag dismiss 'continues at the drag velocity'; implemented the standard exit transition (same as a non-drag close) instead of momentum-preserving physics, since the schema gives no numeric spec for how velocity should map to animation.
- BottomSheet: the wide/narrow breakpoint is read at runtime via getComputedStyle(--layout-max-width-prose) rather than hard-coded, so it can't reflect a per-instance overrides.maxWidth (that hook only exists on the mounted sheet element, which doesn't exist yet when the presentation decision is made).
- BottomSheet: schema has no initialFocus prop (unlike Dialog), so default focus-on-open always targets the first focusable body control, falling back to the close button — this mirrors Dialog's 'first' default but isn't explicitly specified for BottomSheet.

## 2026-09-16 07:07 — round 1

- BottomSheet: `maxWidth` is in the Overridable list, but its description says the breakpoint is 'read once from the theme (not per-instance overridable)'. The sheet is also full width below the breakpoint, so the value has nothing to style. I declared the `--ds-bottom-sheet-max-width` hook and type entry, but it has no effect. The breakpoint comes from `--layout-max-width-prose` on <html> through matchMedia `(width > X)`.
- BottomSheet: the guidance forwards only `inset`, `radius`, `partGap` and `footerGap` to Dialog in the wide presentation. `scrim`, `shadow`, `layer`, `enter` and `exit` have same-named Dialog bindings but aren't listed. I forwarded only the four listed, so those five do nothing on wide screens.
- BottomSheet: 'the always-visible close button' (behavior and SwiftUI notes) conflicts with 'When false, only the footer actions close it' and 'as in Dialog' (Dialog hides the close button when not dismissible). I don't render the close button when `dismissible` is false, which matches the wide Dialog presentation.
- BottomSheet: `minTarget` (size.target.comfortable) is on the closeButton part and says 'the Button keeps its own size variant and colors', but Button's own min-target hook is locked and declared on `.ds-button`, so a parent can't raise it without restyling the child. I wrapped the Button in a `data-part="closeButton"` span of 44×44 whose click on the extra area calls the button's click(). The Button itself stays ghost/sm. The schema needs a sanctioned way to request a comfortable target from Button, such as a Button `target` prop.
- BottomSheet: `onClose` reason `action` ('a footer action asked to close') has no mechanism: footer is plain content, and nothing (context, render-prop, helper) lets a footer action ask the sheet to close. It is in the type but never fired, same as Dialog.
- BottomSheet: the guidance says the gesture begins 'on the header when the body is at its scroll top', but the web notes attach the gesture to the header, which is separate from the scrolling body. I applied it literally: pointerdown on the header is ignored while the body scroll container's scrollTop > 0.
- BottomSheet: 'faster than 1.5 px/ms' doesn't say how velocity is measured (release instant or average over the drag). I used the speed between the last two pointer samples before release, downward only.
- BottomSheet: the handle is anatomy but its presence isn't specified when the gesture is off. I render it only when `dragToDismiss && dismissible`, so there is no drag affordance where dragging does nothing. The SwiftUI notes always show the drag indicator.
- BottomSheet: 'The always-present wrapper carries data-ds="BottomSheet" in both presentations' conflicts with Dialog setting its own `data-ds` after the spread, and with 'closed-sheet-renders-nothing'. On narrow screens the <dialog> is the root. On wide screens I portal a `display: contents` div with `data-ds="BottomSheet"` and render Dialog with `container` set to that div. The div unmounts once Dialog removes its node (MutationObserver), so Dialog's exit transition still plays. On wide screens the ref points to Dialog's <dialog>.
- BottomSheet: constants `dismissDistance` and `dismissVelocity` must be read 'through its token expression', but they have no token or generated constant export. They are local module constants (`DISMISS_DISTANCE`, `DISMISS_VELOCITY`) with the schema values.
- BottomSheet: the example stories' `given` values are prose descriptions ('A Form of filter controls', 'Clear and Apply Buttons'). To keep 'exactly its given as args', the stories pass those strings verbatim as children and footer, so they render as text rather than real forms or buttons.
- BottomSheet: the spacing inside the sheet isn't in the style bindings: header top padding, handle-to-title gap, heading-to-close-button gap and handle corner radius. I used `inset` for the header top padding, `layout.gap.tight` between handle and title row, `layout.gap.normal` between heading and close button, and `radius.full` for the handle pill.
- BottomSheet: the schema's `exit` binding says motion.easing.exit but the generic rule says transitions use motion.easing.standard. I used standard for enter and exit easing for exit (slide and scrim fade), following the binding description.
