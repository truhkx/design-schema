## 2026-09-10 09:31 — round 1

- SegmentedControl: no style binding covers spacing between adjacent segments (segmentGap is only icon-to-label within one segment), so segments render directly abutting with the pill sliding underneath — chose this over guessing an unlisted gap token.

## 2026-09-21 12:13 — round 1

- SegmentedControl: the `segmentIcon` anatomy part is listed and composed as Icon, but no style binding gives it a color — I pass the segment's own foreground (`color.foreground.muted`, or `color.foreground.strong` when selected) since RN has no `currentColor`. If the icon is meant to track the label's color, say so as a binding; if it is meant to be independent, it needs its own token.
- SegmentedControl: `minTarget` is locked to `size.target.min`, but its own description says React Native uses `size.target.comfortable` so every segment reaches 44px. I implemented the description (comfortable) and ignored the token the binding names. A locked binding whose token is wrong on one platform is contradictory — either the binding should resolve per platform or RN should be exempted explicitly.
- SegmentedControl: `segmentPaddingBlock` (md) and `paddingBlockSm` (sm) are both `space.1`, and the description says `size` therefore changes the height only through fontSize — but every segment also has `minHeight: size.target.comfortable` on RN, so `size` changes the segment height not at all, only its type and intrinsic width. `SizeSm` and `SizeMd` render at identical heights; the doc says "not visibly at all" parenthetically, but that makes `size` nearly a no-op on this platform and worth stating as the intended outcome.
- SegmentedControl: the pill is absolutely positioned from `onLayout` measurements, which arrive after first paint, so on the very first frame the selected segment has no pill. I suppress the slide on the first measurement (`hasMeasuredRef`) so it appears in place rather than animating in from x=0, but the doc only specifies the no-slide case for a `value` matching no option. Confirm that first mount is also instant.
- SegmentedControl: `fill: false` is specified as "stretch to the container width" when true, but nothing says how wide the group is when false. I used `alignSelf: 'flex-start'` so it hugs its segments; `stretch` (RN's default) would have made `fill` a no-op.
- SegmentedControl: the keyboard table's `selects` expectation combined with the guidance's "`onChange` fires only when the target differs from the current `value`" means an arrow onto the already-checked segment fires nothing but still moves focus. My `select()` guard returns early on `optionValue === currentValue`, after the focus call — correct, but the table alone would read as "always selects". Worth an explicit line.
- SegmentedControl: the group is `accessibilityRole="radiogroup"` but deliberately not `accessible`, so RNTL's `getByRole` cannot reach it and the derived `has-accessible-name` scenario must assert `accessibilityRole` and the name on the testID root instead. The platform note says this in prose; the behavior scenario does not, so a regeneration that follows the scenario literally will write a failing `getByRole('radiogroup')` test.
- SegmentedControl: `iconOnly` with an option that has no icon is specified to fall back to the label as text, which makes that one segment much wider than its icon-only neighbours; nothing says whether the fallback should instead reserve the icon's box. I render the label at its natural width.
- SegmentedControl: `shadow.raised` is spread into the pill's style object as RN shadow properties (shadowColor/shadowOffset/shadowRadius/elevation). The binding names a single token, but on RN it expands to several style keys — the overrides contract's "resolve with `resolveToken` and use the result in place of the default" assumes a scalar. It works because the token resolves to an object, but the contract does not describe that case.
