## 2026-09-10 01:45 — round 1

- Checkbox: the existing file predated the package's overrides contract (no `overrides` prop, no `CheckboxOverridableBinding`) and drew the checkmark as a raw Unicode '✓' Text glyph and a hand-drawn dash View. Icon.tsx's own docstring explicitly names 'the check in a Checkbox' as a supported use case and calls the Unicode approach 'retired', so rewrote to use `<Icon name="check"/"dash">` with `color=colorControlSelectedForeground` and `overrides.strokeWidth` forwarding the `indicatorStroke` binding, and added the full overrides contract following Box/Button/Input's established pattern.
- Checkbox: `indicator` box is spec'd as 'controlSize minus 2 × space.1' but Icon's `size` prop only accepts discrete font-size-scale presets (xs/sm/md/lg/xl) or a token-ref override, not an arbitrary computed pixel value — used `size="xs"` (closest preset to the default ~12px derived size) centered in the drawn box via flexbox; a `controlSize` override will not proportionally rescale the glyph.
- Checkbox: `validateValue` was missing the `invalid` → `copy.invalid` branch the schema's precedence (`error` → `required` → `invalid`) requires — Input already implements this three-branch precedence, so mirrored it exactly (text only surfaces once a Form validation run populates `formError`, matching the existing 'Invalid' story's documented behavior of showing no message until then).
- Checkbox: `transition` binding's exact scope ('fill and indicator transitions') is descriptive, not literal — implemented as a single Animated.Value driving box background/border color (unchecked → controlSelectedBackground) and indicator opacity together, eased with motion.easing.standard and skipped under `useReducedMotion()`, mirroring Button's pressed-background animation pattern. The `pressedOverlay` effect is instantaneous and dims the whole box (border+fill+indicator), not just an overlay layer on the fill, since RN has no cheap way to layer a second tinted surface without restyling the border.
- Checkbox: root View now carries `testID="Checkbox"`, which the original file lacked.

## 2026-09-20 22:24 — round 1

- Checkbox: the minTarget binding asks for paddingBlock (minTarget − labelSize × lineHeight) / 2 plus a minHeight of minTarget. With an override making labelSize × lineHeight taller than the target the padding goes negative; the doc does not say which wins. I clamped the padding at 0 and left minHeight as a floor, so the row just grows.
- Checkbox: minTarget says 'with hideLabel the control is still centred in the row', but the row's height is derived from the label's line box, which hideLabel removes from view. I kept the control slot at labelSize × lineHeight regardless, so the row keeps its height and the control lands centred; the doc does not state whether a hidden label should still set the row height.
- Checkbox: with hideLabel and a description, the description is the only visible text and the control is centred on a line box no text occupies, so it sits above the description's first line rather than beside it. The doc's four examples never combine the two, so I did not special-case it.
- Checkbox: the error message is indented by controlSize + gap, but the doc does not say what happens when hideLabel is set — there is no label to line up with. I indent unconditionally so the error keeps a consistent inset; indenting under an invisible label may not be what was meant.
- Checkbox: the transition binding covers the control's background and border color, but the border color is a plain string while invalid or focused (it is not interpolated). So entering or leaving the invalid/focused state snaps while a checked/unchecked change cross-fades. The doc does not say whether the invalid and focus border colors are themselves part of the transition.
- Checkbox: indicatorStroke is declared as a binding (border.width.focus, locked) but its own description says nothing is forwarded into the Icon because Icon already strokes at that token. I render no stroke code at all, so the binding has no effect on this platform — it is documentation, not behavior.
- Checkbox: the `value` prop is accepted for API parity and 'does nothing' on RN, so it is stored but never read. It stays in the props type and the Default story args purely so the API matches web/Lit.
- Checkbox: `pressedOverlay` uses the opacity.disabled token for a pressed fill, which reads as a token reused for an unrelated purpose. I implemented it as written, but the two bindings moving together under one theme change looks accidental.
- Checkbox: a11y.requires lists target-24px while the minTarget binding uses size.target.comfortable (44px). I followed the binding; the requires entry is the weaker floor and is satisfied by it.
- Checkbox: the RN notes say the error's live region is 'none' inside a Form with errorSummary on, and assertive otherwise. There is no guidance on the non-Form case, so a bare Checkbox with an error announces assertively on mount, which fires on first render of an already-invalid field.
