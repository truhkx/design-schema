# Gaps reported while generating ActionSheet for web

Each entry is a place the doc made the generator guess. Fix the doc, re-run parse, regenerate.

## 2026-09-10 03:16 — round 1

- ActionSheet: the wide/Menu presentation must anchor 'to the element that was focused when open became true' (an arbitrary external DOM node), but Menu owns and renders its own internal trigger Button — there's no API to anchor Menu to a foreign element. Chose to render Menu with its own trigger positioned (via the sanctioned style-prop passthrough) at a fixed rect captured from document.activeElement at open time, made invisible (opacity 0, pointer-events none) so Menu's popup positions itself relative to that point. This leaves a zero-opacity, pointer-events-none but still keyboard-focusable proxy button in the DOM whenever the wide sheet is open — not a perfect substitute for anchoring to the real opener.
- ActionSheet: Menu's onOpenChange(false) fires for both a real dismissal (Escape/outside click) and, just before onAction, for a chosen action — it doesn't say which, and ActionSheet's contract requires onClose to fire only for the former. Worked around with a same-tick setTimeout that the paired onAction call cancels. Also, Menu doesn't distinguish escape from an outside click, so both collapse to onClose('escape') in the wide presentation (the only one of the four reasons — escape/scrim/cancel/drag — that fits a non-modal, scrim-less, cancel-row-less surface).
- ActionSheet: general generation instructions mention overlay portals may accept a `container` prop override, but the component's own YAML props list has no `container` prop (only open/title/actions/cancelLabel). Followed the schema as source of truth and hardcoded `document.body` as the portal target, unlike BottomSheet/Popover which do declare `container`.
- ActionSheet: anatomy lists no 'handle' part, but the platform notes say the phone presentation reuses BottomSheet's <dialog> mechanics 'as BottomSheet', which includes a drag handle enabling the drag-to-dismiss gesture referenced by the 'drag' close reason and the gesture-alternative requirement. Rendered a decorative grab handle (aria-hidden, no data-part since it isn't a named anatomy part) to support this, matching BottomSheet visually.
- ActionSheet: styles list gives `itemGap` the description 'Between icon and label' only (no separate token for vertical spacing between rows). Interpreted this literally — rows are stacked with no gap and get their rhythm entirely from `itemPaddingBlock`, unlike Menu.css which reuses its `itemGap` for both row spacing and icon-label spacing.
- ActionSheet: `fontFamily` and `lineHeight` are generic overridable bindings but the title renders through a composed `Text`, which always sets its own font-family/line-height (never inherits). Forwarded both bindings into Text's own `overrides` (alongside `titleSize`→Text `fontSize`) as well as applying them as root CSS hooks for the item rows, so a single override value affects both consistently — mirroring the `Divider → Text fontSize` precedent, extended by analogy to `fontFamily`/`lineHeight` since no other component schema exercises that exact combination.
- ActionSheet: the forwardRef exposes the phone presentation's `HTMLDialogElement` only; in the wide/Menu presentation the consumer's ref is not attached to anything (Menu's root is an `HTMLDivElement`, an incompatible type), unlike BottomSheet's wide branch which forwards the same ref to Dialog because both render a native `<dialog>`.

## 2026-09-16 07:18 — round 1

- ActionSheet: platforms.web.notes says Menu 'takes no external anchor' and asks for the Menu host to be moved to the opener's position with its own trigger hidden (opacity 0, pointer-events none, tabindex -1, aria-hidden). The package's Menu already has `anchor?: RefObject<HTMLElement | null>`, which renders no trigger and puts focus back on the opener, so I passed the opener ref as `anchor` instead. The note needs updating to match Menu.
- ActionSheet: Button always sets its own data-part="container", so a data-part on the composed Button is overwritten. I put data-part="cancelButton" on the row that wraps the Button (as AlertDialog/Dialog do for their buttons); the behavior test clicks `[data-part=cancelButton] button`. The doc does not say where a composed Button's part hook goes.
- ActionSheet: the `maxWidth` override cannot move the breakpoint. The breakpoint is read from `--layout-max-width-prose` on <html> through matchMedia, before any root element exists to carry an inline hook, so `overrides.maxWidth` only sets a hook that nothing reads. The doc lists maxWidth as overridable without saying how an override reaches a media query.
- ActionSheet: `overrides` has no effect in the wide presentation. The doc says nothing about forwarding them to Menu (radius/shadow/itemPadding*/fontFamily/layer map naturally onto Menu bindings); I forwarded nothing.
- ActionSheet: `dismiss` in the overlay block lists `close-button` and `swipe`, while the onClose reasons are `cancel` and `drag`. I treated close-button as the cancel row and swipe as the drag and reported the event's reason names.
- ActionSheet: the `titleColor` (locked) and `titleSize` bindings have no `part`. I read them as the heading Text: tone=muted size=sm, with titleSize forwarded as Text `fontSize`. The doc does not name the heading as their part or say that titleSize goes through Text.
- ActionSheet: the doc has `itemGap` apply to the item row but `fontFamily`, `fontSize` and `lineHeight` have no part. I applied them to each item row, not the list.
- ActionSheet: `divider` covers 'above the danger group and above the cancel row', but nothing says whether a sheet whose actions are all danger (or none) still gets the first divider. I draw it only when both groups are non-empty; the wide Menu gets a separator under the same rule.
- ActionSheet: the `enter`/`exit` durations have no easing binding. The rules say motion.easing.standard for both directions, so I used it for both, although an exit easing token may exist.
- ActionSheet: the doc says Enter/Space 'chooses the focused action and closes', while onAction says the consumer closes. Enter/Space only fire onAction through the native button click, and the sheet stays open until `open` changes. For a disabled item, Enter/Space do nothing.
- ActionSheet: the Tab rule is 'wide-screen menu presentation' only; in the sheet presentation the FocusScope traps Tab between the menu's single tab stop and the Cancel button. The doc does not say what Tab does in the sheet.
- ActionSheet: the UnnamedSheet example's `given` has no heading, but the stories' default args include `heading: "Photo.jpg"`. To keep 'exactly its given', the story sets `heading: undefined` explicitly. The doc does not say whether example args are applied on top of the Default story's args or replace them.
- ActionSheet: the doc names no drag start (distance or angle) that tells a drag apart from a tap. Any pointerdown on the header starts a drag, and a release is scored on distance/height > 0.25 or speed > 1.5 px/ms.
- ActionSheet: the `anatomy` list includes `focusScope` and `itemIcon`, but the rules for the wide presentation give no part hooks. Menu owns them there, so no ActionSheet data-part values appear when wide; in the sheet `itemIcon` is a span wrapping Icon, since the doc does not say whether Icon passes data-* attributes through.
