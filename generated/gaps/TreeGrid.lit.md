# Gaps reported while generating TreeGrid for lit

Each entry is a place the doc made the generator guess. Fix the doc, re-run parse, regenerate.

## 2026-09-10 14:22 — round 1

- TreeGrid: spec says it 'extends the ds-data-grid implementation (shared base class in the package, not a copy)', but DataGrid.ts is a single concrete LitElement with no exported base class or shared hooks/constants. Implemented TreeGrid as its own self-contained component following the same rendering/keyboard/CSS patterns rather than refactoring DataGrid into a shared base (out of scope for a single-component pass).
- TreeGrid: DataGrid's copy strings for the 'as DataGrid' behaviors (select-all/select-row labels, selected-rows count, sort announcements, editing/invalid/position/row-count/empty/scroll-hint text) aren't exported from DataGrid.ts, so the identical strings were duplicated locally in TreeGrid.ts instead of changing DataGrid's public surface.
- TreeGrid: no `selected`/`defaultSelected` prop exists (unlike DataGrid), so row/cell selection is implemented as fully internal, uncontrolled state — a consumer can't seed or control initial selection, only read it via `onSelectionChange`.
- TreeGrid: `showStatusBar`'s doc default is `true`; per the package's negated-boolean-attribute convention (and DataGrid's own implementation of the identical prop) it should reflect as `no-status-bar`. The schema's own `platforms.lit.reflect` list names it `show-status-bar` instead — followed the convention (`no-status-bar`) over the literal reflect-list spelling.
- TreeGrid: `copy.expandAll`/`copy.collapseAll` have no corresponding anatomy part, prop, or keyboard action anywhere in the schema (only `*` expands one row's siblings) — left unused rather than inventing a toolbar control to hang them on.
- TreeGrid: `copy.level` and `copy.childCount` are declared, but the web platform note relies on native `aria-level`/`aria-setsize`/`aria-posinset` instead of visible/announced text (RN's platform note composes them into `accessibilityLabel` instead) — left unused on web.
- TreeGrid: no `emptyMessage` prop or `copy.empty` string is defined despite `emptyState` (composed Text) being in the anatomy. Reused DataGrid's exact 'Nothing to show.' string as a placeholder since no TreeGrid-specific text was specified.
- TreeGrid: `expand-change`/`expand` event detail shapes aren't specified beyond prose ('the new array of expanded ids' / 'with its id'). Implemented as the bare value (`string[]` / `string`) rather than an object wrapper, matching the prose literally — flagging in case `{ expanded }` / `{ id }` was intended for consistency with the other object-shaped details.
- TreeGrid: `selectChildren` cascading semantics aren't fully specified. Implemented so toggling a row's checkbox cascades that row's own id plus all of its *currently loaded* descendant ids into/out of the internal selection set, while every row's checked/indeterminate visual state is derived independently by counting how many descendants are currently selected (a parent's id is only added/removed when the parent checkbox itself is the one clicked).
- TreeGrid: `DataGridColumn.resizable`/drag-resize (as DataGrid) has no corresponding copy string in TreeGrid's `copy` block (DataGrid needs 'Resize {column}' for the handle's accessible label) and no anatomy part for a resize handle. Omitted the interactive resize handle rather than ship an unlabeled control; static `width`/`minWidth`/`pinned` column sizing is still honored.
- TreeGrid: no `edit-start` event is declared (unlike DataGrid's cancelable event of the same purpose), so `editable`'s 'as DataGrid' behavior starts editing unconditionally with no cancelable hook.
- TreeGrid: `minTarget` (locked, `size.target.min`) and `expandButtonSize` (overridable, default `size.target.min`) both default to the same token with different lock status. Interpreted `expandButtonSize` as the expand button's own overridable visual size, and `minTarget` as a locked `min-block-size` floor on the row so a shrunk override can never drop below the accessible minimum.
- TreeGrid: the `'*'` key action ('Expands every sibling of the focused row') doesn't say whether the focused row itself is included. Implemented inclusively — the focused row and all its same-level siblings that have children are expanded together.
- TreeGrid: guide lines are drawn as one vertical line per ancestor level (via stacked CSS background layers keyed to each ancestor's indent depth), an implementation choice for 'a vertical guide under each open parent... always drawn' since the doc doesn't prescribe the rendering technique.
- TreeGrid: lazy loading fires `onExpand` every time a `children: "lazy"` row transitions from collapsed to expanded, not literally 'once ever' — if the caller never replaces `children`, re-expanding the row refires `onExpand`.
- TreeGrid: no `defaultSort` prop is declared (only controlled `sort`), unlike DataGrid. Added an internal uncontrolled-sort fallback anyway so clicking a sortable header does something visible when `sort` isn't supplied, for parity with DataGrid's ergonomics even though the prop table doesn't ask for it.

## 2026-09-16 12:12 — round 1

- TreeGrid: the Events contract lists the detail keys `ids` (expand-change) and `id` (expand), but the event descriptions and the lit platform notes say bare values ('the bare array, as Tree; not wrapped in an object'). Chose bare detail values (string[] / string); the payload should say so, or the contract renderer should allow a bare payload.
- TreeGrid: onCellChange `value`/`previous` are typed `string | number | boolean`, with no way to say a cell held no value (DataGrid allows undefined, and a cleared number editor has no number). Chose to report an absent value as the empty string ''.
- TreeGrid: the keyboard table says Shift with the arrows 'keeps their own meaning (column navigation, expand and collapse)', which removes DataGrid's Shift+Arrow column resize on a header. The resize separator is therefore pointer-only; say whether TreeGrid keeps DataGrid's keyboard resize.
- TreeGrid: 'Keyboard: implement exactly as listed and nothing else' leaves out keys DataGrid has: PageUp/PageDown, Delete/Backspace clearing, and typing to start an edit. They are not implemented; if 'Elsewhere as DataGrid' was meant to bring them in, list them.
- TreeGrid: ArrowLeft on a row header of a collapsed or leaf level-1 row has no parent to move to, so I made it a no-op. Because the row header comes right after the selection column, ArrowLeft can never reach the checkbox column from the row header in row mode; only Home does. Say whether it should fall back to the previous cell.
- TreeGrid: `defaultExpanded: ['*']` expands 'every loaded row'; the doc doesn't say whether rows loaded later are covered, or whether lazy rows count. Chose to keep '*' live: it covers every row whose children is a non-empty array, now or later, and never lazy rows, which would otherwise fire expand unasked. The first user toggle turns it into explicit ids, which is what expand-change reports. It is honoured the same way in controlled `expanded`.
- TreeGrid: whether `children: []` counts as 'has children' (showing aria-expanded and a chevron) is unspecified. I treat an empty array as a leaf.
- TreeGrid: `copy.selectedRows` total and `copy.rowCount` say 'how many rows the treegrid has', but not whether that means visible rows or all loaded rows. Chose all loaded rows at every level, to match select-all's scope; aria-rowcount still counts visible rows plus the header.
- TreeGrid: the loading placeholder row's navigation is unspecified. It is a navigable row (level + 1, setsize 1, posinset 1) with copy.loading in the row-header column and empty other cells; it is not selectable or editable, and ArrowLeft on it moves to its parent.
- TreeGrid: Ctrl+Home/End says 'first / last visible row of the grid', but whether that includes the header row is unsaid. Followed DataGrid: Ctrl+Home goes to the header row.
- TreeGrid: the `indent` binding says 'padding-inline-start on the row header' but binds part `indent`. Chose to put the per-level padding on the `data-part=indent` element at the start of the row header, so the cell keeps its own inline padding.
- TreeGrid: guideLine says lines are 'aligned with that ancestor's expand button', but TreeGrid has no binding for the row header's inline padding (DataGrid's cellPaddingInline is not in TreeGrid's styles). Positioned the guide at space.2 (DataGrid's default) + indent × depth + size.target.min / 2, so a DataGrid-style padding override would misalign guides; TreeGrid should list cellPaddingInline or say the guide offset.
- TreeGrid: 'Its own element following ds-data-grid's CSS' but TreeGrid's styles list only its tree bindings, so DataGrid's header, grid-line, status-bar, caption and fixedHeight hooks have no TreeGrid hook and use DataGrid's default tokens directly. `height: fixed` therefore can't be resized per instance (DataGrid's fixedHeight override has no TreeGrid equivalent).
- TreeGrid: selectChildren says a parent is 'checked when all, indeterminate when some, else its own id' but not which state aria-selected reports for an indeterminate parent. Chose aria-selected='false' for indeterminate.
- TreeGrid: 'toggling a parent row' cascades only when the row's own checkbox is used; the doc doesn't say whether plain Space, Enter on the select cell or Ctrl+click are the same act. Chose to treat them all as the row's own toggle (they cascade); only Shift+Space and Shift+click ranges don't.
- TreeGrid: `columns` shape is `DataGridColumn[]`, so the type is imported from DataGrid.ts (type-only), while the lit notes say 'nothing is imported from DataGrid'. Kept the type import, since only the copy strings were meant.

## 2026-09-17 14:51 — round 1

- TreeGrid: the keyboard table says Delete/Backspace "clear editable cells in the selection" but TreeGrid has no `range` mode and the doc never defines "the selection" for `selectable: cell` or `none`. Chose DataGrid's shape: in `row` mode every editable cell of every selected row; otherwise the active cell alone (including `selectable: none`, where the focused cell is still meaningful).
- TreeGrid: Ctrl+A is listed only as "As DataGrid", and DataGrid's select-all covers `row` and `range`. With `range` absent here the doc does not say what Ctrl+A does in `cell` mode. Chose: Ctrl+A selects every loaded row only when `selectable: row`, and is unhandled otherwise.
- TreeGrid: Escape is listed as "As DataGrid", but DataGrid's Escape only clears a range, which TreeGrid has none of, while `a11y.requires` still lists `escape-dismiss`. Chose: Escape cancels an open editor and returns focus from a control inside a cell to the grid; on the grid itself it is unhandled and bubbles (no collapse-all, which the doc never asks for).
- TreeGrid: copy.position's `row` number is undefined — the visible-row index (matching aria-rowindex) or a position among all loaded rows, which copy.rowCount/copy.selectedRows use. Chose the visible index (active row + 1), so the shown position agrees with aria-rowindex.
- TreeGrid: the lazy loading placeholder row's accounting is unspecified. Chose: it is a navigable row counted by aria-rowindex/aria-rowcount, but not by copy.rowCount or copy.selectedRows totals (which count loaded data rows), and it is neither selectable nor editable.
- TreeGrid: Shift+Space says it extends "from the last plain-Space anchor", with no rule for an anchor whose row is no longer visible (its subtree was collapsed, or sorting moved it). Chose: fall back to a plain, non-cascading toggle of the focused row.
- TreeGrid: "Typing a printable character opens an editor, as DataGrid" does not say whether the typed character seeds a select, date or checkbox editor. Chose DataGrid's rule: the character seeds the text and number editors only; other editors open unseeded.
- TreeGrid: `onCellChange.value` is "undefined when cleared … never coerced to an empty string", but the doc gives no rule for a text editor committed empty by the user. Chose: an emptied text editor commits `''` (the editor's own value) and only Delete/Backspace produces `undefined`.
- TreeGrid: `fixedHeight` (space.20) does not say whether the height covers the whole component or only the scroll region. Chose DataGrid's current shape: it sizes the container, and the scroll region takes what the caption and status bar leave.
- TreeGrid: the `transition` binding is documented as the chevron rotation only, while DataGrid animates row background and the editing cell with its own transition. Chose no row or cell transition here, so the only motion is the chevron (removed under prefers-reduced-motion).
- TreeGrid: the web note says the expand Button carries `aria-hidden` and that the rotation lives on a span TreeGrid owns around it. Implemented the span with `aria-hidden="true"`, which hides the Button as a descendant rather than repeating the attribute on the Button itself — the doc should say which element holds it.
- TreeGrid: the status bar's copy strings are listed without saying which are announced. Followed DataGrid: only loading, the `invalid` message, `editing` and `sortedAnnouncement` go in the role="status" span; rowCount, selectedRows, scrollHint and position are shown but never announced.
