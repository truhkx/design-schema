# Gaps reported while generating Stepper for lit

Each entry is a place the doc made the generator guess. Fix the doc, re-run parse, regenerate.

## 2026-09-10 11:26 — round 1

- Stepper: composition table says `step: Button`, but ds-button's API only supports a single text label plus leading/trailing icon slots — it has no default slot for the label+description Text pair the platform notes describe as 'wrapped inside' the Button. Implemented the interactive step control as a native <button> (styled with the component's own tokens), matching the precedent in Disclosure.ts (which also declares its own locked focusRing/focusRingWidth bindings rather than relying on a composed Button's). ds-text is still used for the label/description parts.
- Stepper: the a11y section wants the accessible name to read 'Step 2: Payment, current step' and the web platform notes say this comes from 'a visually-hidden <span> inside the control'. I instead set a single `aria-label` on the control (built from copy.stepLabel + the status word) and left the visible label/description as decorative, with the description linked via aria-describedby instead of folded into the name. This avoids double-announcement and keeps the description available to AT, but is a different mechanism than the literal hidden-span instruction.
- Stepper: `label` (nav landmark accessible name, default 'Progress') is used in the web platform notes and accessibility section but is not declared in the `props` table, and 'Progress' is not in `copy`. Added it as an optional property defaulting to 'Progress', inferring the default from prose rather than a copy token.
- Stepper: navigable="completed" eligibility was decided as position-based (`index < currentIndex`, i.e. any visited step, including one explicitly marked `error`) rather than strictly `status === 'complete'`, since the doc frames it as 'go back, not skip ahead' and an error step is exactly the one a user most needs to revisit. Not explicit in the schema.
- Stepper: no token is given for the indicator's numeral/icon color on upcoming/current steps (only indicatorCompleteForeground/indicatorErrorForeground are defined). Used `color.foreground` as a reasonable default; the contrast pair list doesn't explicitly cover this combination against `color.control.background`.
- Stepper: the `styles` block has no hover-background or radius token for the step control (unlike Button/Disclosure/Tabs, which declare one), so the control renders with no hover affordance and square focus outline — treated as intentional minimalism rather than an omission to fill in.
- Stepper: `compact` prop and the auto-compact container query both toggle the same CSS (hide non-current labels, show "Step n of m"); the doc doesn't say whether manual `compact` should also apply to vertical orientation, so it was implemented to work for either orientation, while the automatic container-query switch is scoped to horizontal only per the platform notes.

## 2026-09-10 18:45 — round 1

- Stepper: stepHover and stepRadius were listed in the schema's styles and Overridable set but had no CSS binding in the file I found — added `--ds-stepper-step-hover` (color.action.ghost.backgroundHover, applied on button.control:hover/:active) and `--ds-stepper-step-radius` (radius.sm, applied as border-radius on .control) plus a background-color transition using the existing transition hook, since the spec didn't say whether radius applies to the non-navigable div control too — I applied it to both for a consistent hit-area shape since only the interactive affordance (hover/press) is button-only.

## 2026-09-16 09:45 — round 1

- Stepper: Behavior says a navigable step's accessible name is copy.stepLabel plus the status word set as aria-label, but the same section (and Lit notes) says on web/Lit the <ol> already gives the ordinal so the control shows its plain label plus a visually hidden status word. Chose the latter; copy.stepLabel is therefore unused on Lit — the doc should say stepLabel is native-only.
- Stepper: platforms.web.notes says each navigable <li> holds a Button (ghost), while navigable's description and Behavior say it is the component's own native <button>, not Button. Chose the native <button>; the web notes and Guidance > Platform notes > Web need updating.
- Stepper: the compact breakpoint is layout.maxWidth.prose, but a container-query condition cannot read a custom property, so the value (572px) is hard-coded with literal-ok. The doc should name how Lit gets the built token value (or accept the literal).
- Stepper: labelWeight, labelCurrentWeight, labelSize and descriptionSize are listed as parts label/description with their own hooks, but the label and description are composed Text. Chose to forward them to <ds-text>.overrides (fontWeight/fontSize) and to declare no --ds-stepper-label-* hooks; fontFamily is both a host hook and forwarded. The doc should state the forwards explicitly (child binding names).
- Stepper: labelColor/labelUpcomingColor/descriptionColor are expressed as Text tone default/muted; the doc does not map these bindings to tone values. Chose muted for upcoming (non-current) labels and all descriptions.
- Stepper: partGap, fontFamily, minTarget, focusRing and focusRingWidth have no part. Chose partGap = gap between indicator and label inside the control (also its inline padding), fontFamily on the host, minTarget as the control's min block/inline size, focus ring on the button's :focus-visible.
- Stepper: the stepOf count has no anatomy part or style binding (size, tone, placement). Chose a <ds-text size=sm tone=muted> after the <ol>, shown only when compact applies.
- Stepper: steps[].status 'current' on a step whose id is not `current` is undefined behavior. Chose: indicator/status word follow the status (says 'current step'), but aria-current and the compact reveal follow the id.
- Stepper: when `current` matches no step id, status derivation, navigability and 'Step n of m' are unspecified. Chose all steps upcoming, none navigable under `completed`, count shows 'Step 1 of m', and a dev warning.
- Stepper: 'Hidden labels are clipped' in compact — the doc does not say whether descriptions and the status word are clipped with the label. Chose to clip the whole label/description/status-word group of non-current steps.
- Stepper: the doc never says whether descriptions render in horizontal orientation (orientation says vertical shows them). Chose to render descriptions only when vertical.
- Stepper: the connector-complete condition is unspecified (by position before current, or by the step's status). Chose by position (index < current index), matching 'completed means visited'.
- Stepper: behavior scenario `compact-shows-the-step-count` only checks text; the Lit test also asserts the count is visible. The `copy:` scenarios are checked against shadow-root textContent because the words are visually hidden.
