# Gaps reported while generating Listbox for web

Each entry is a place the doc made the generator guess. Fix the doc, re-run parse, regenerate.

## 2026-09-10 09:40 — round 1

- props: schema has no `error`/`invalid` prop (unlike RadioGroup/Checkbox/Fieldset), yet a11y.requires lists error-identification and copy has `required`. Implemented required-only validation via Form registration; the error message (when Form supplies one) is rendered visibly with role=alert, but there's no way for a consumer to pass an ad-hoc error directly to a standalone Listbox outside a Form.
- platforms.web.attributes for the root omit aria-invalid/aria-required/aria-describedby entirely (only role=listbox, aria-label, aria-labelledby, aria-multiselectable, aria-activedescendant, tabindex=0 are listed for the root; aria-disabled/aria-selected are listed but read as per-option). Followed the whitelist literally and did not add aria-invalid/aria-required/aria-describedby to the root, so the visible error text and `required` state are not programmatically associated with the listbox for screen readers beyond the Form's own error-summary link.
- FormContext's `FormFieldValue` was `string | boolean | undefined`, which can't represent multi-select's array value described in the docs ('Multiple values are collected as an array'). Widened it to `string | string[] | boolean | undefined` in FormContext.ts (shared file) since no narrower fix was possible.
- styles.optionSelectedCheck (locked) has no dedicated CSS hook on the Listbox root — mirrored Alert's pattern of forwarding a locked color straight into the composed Icon's own `overrides` prop rather than declaring an unused `--ds-listbox-*` hook that no rule would read.
- onChange/onActiveChange fire as `(value)` / `(value | null)` with no DOM event, since a selection can originate from a keyboard key, a pointer click, or a programmatic multi-select toggle (Ctrl+A) with no single native event to forward — mirrors Menu's `onAction(id)`.
- Home/End and typeahead aren't explicitly said to honor `selectionFollowsFocus` (only ArrowUp/ArrowDown's action text mentions 'selects it when selection follows focus'); implemented Home/End/typeahead through the same `moveActive` helper as the arrows for a consistent single-select picker feel, so they also auto-select when `selectionFollowsFocus` is true.
- Enter's action text says 'Selects the focused option (single)' with no `when: multiple` gate like Shift+Arrow/Ctrl+A have; treated it as single-select-only (a no-op in `multiple` mode, where Space is the only committer) rather than replacing the whole multi-selection with one value.
- ArrowDown/ArrowUp aren't documented as wrapping; implemented them as clamping at the first/last enabled option (Home/End reach the ends explicitly) rather than cycling.
- maxVisible's row-based scroll cap has no row-height token and platforms.web has no mechanism note (only the RN notes describe 'maxHeight = rows × row height measured from the first row'); ported that same runtime-measurement technique to web (via `getBoundingClientRect`) since inventing a fixed px literal would fail the literal lint and no token exists for a single option row's height.
- optionSelectedCheck's token comment ('always rendered — invisible slot when unselected — so labels align') isn't scoped to `multiple` even though the `multiple` prop's own description says 'each option shows a check indicator'; rendered the check indicator in both single- and multi-select modes for alignment, per the token note.
- copy.selectedCount is documented as text 'the surrounding UI' shows, not part of this component's own anatomy; it's defined in COPY for completeness but never rendered by Listbox itself.

## 2026-09-10 18:32 — round 1

- Listbox: the existing implementation was missing the `invalid`, `error`, `embedded`, `defaultActiveValue`, and `loading` props entirely (only `label`, `labelledBy`, `options`, `multiple`, `value`, `defaultValue`, `selectionFollowsFocus`, `required`, `disabled`, `name`, `emptyMessage`, `maxVisible` were present) — added all five to match the schema, plus the corresponding `aria-invalid`, `aria-required`, `aria-busy`, and `aria-describedby` root attributes that were also missing.
- Listbox: the schema's `invalid` prop description says it renders 'with `copy.invalid`', but no `invalid` key exists under the component's `copy:` block (only `empty`, `required`, `selectedCount`, `loading`). Treated `invalid` as a state-only flag (sets `aria-invalid`) with no bundled message; `error` (explicit prop) takes precedence over the Form-derived required-validation message for the visible error text.
- Listbox: `defaultActiveValue` vs. the documented default ('first selected, else first enabled') isn't given an explicit precedence order. Chose: `defaultActiveValue` wins if it names an enabled row, else first selected, else first enabled — applied once on first focus via a new `onFocus` handler (previously there was no focus-driven initial-active logic at all).
- Listbox: `embedded` has no dedicated override-suppression rule in the spec beyond 'overrides change values, never presence.' Implemented by having `.ds-listbox--embedded` set `border`/`border-radius`/`background-color` directly (bypassing the `--ds-listbox-border*`/`-radius` hooks), so any `border`/`borderWidth`/`radius` override becomes a no-op while embedded, per the stated contract.
- Listbox: `copy.selectedCount` is explicitly documented as shown by surrounding UI, not the component itself, so it's omitted from the component's `COPY` object (kept as a code comment, not exported) — flagging in case a consumer expects it re-exported for reuse.
