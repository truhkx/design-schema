## 2026-09-10 09:33 — round 1

- SegmentedControl: accessibility narrative says selection is shown by 'the stronger and heavier text' but only one fontWeight token (font.weight.medium) is defined in styles, with no separate selected/unselected weight pair (unlike segmentColor/segmentSelectedColor which do have a locked pair). I applied the documented fontWeight only to the selected segment and left unselected segments at font-weight-regular (not a listed binding, just the ambient base look) to satisfy the 'heavier text' cue described in Accessibility — flag if a distinct unselectedWeight binding was actually intended.
- SegmentedControl: the a11y section says icon-only segments must 'expose it visually through a Tooltip', and the Web platform notes wrap each icon-only segment in a Tooltip — but `composition` only lists `segmentIcon: Icon` and the Lit platform notes say nothing about Tooltip. I implemented iconOnly with `aria-label` for the accessible name only, with no Tooltip composition, matching what `composition`/lit notes actually declare; add `segmentTooltip: Tooltip` to composition if a Tooltip is required on this platform too.
- SegmentedControl: the keyboard table gives Home/End the actions 'First segment.'/'Last segment.' with expect `focus-first`/`focus-last`, distinct from the arrow rows which explicitly say 'Moves to and selects'. Since the component is documented as always having a selection and every other key changes selection immediately (radio semantics), I made Home/End select the jumped-to segment as well — but the schema's wording for Home/End doesn't explicitly say 'and selects' the way the arrow rows do, so a focus-only Home/End (leaving the current radio selected) is also a defensible reading.
- SegmentedControl: `options[].icon` is typed `IconName`, but the shared Icon glyph set (packages/lit/src/Icon.ts) has no 'list'/'grid' icons matching the doc's own View-mode example. Stories/demo use a 'Day/Week/Month' text example for Default and existing chevron/dash icons as stand-ins for the IconOnly story rather than domain-accurate glyphs.

## 2026-09-21 12:10 — round 1

- SegmentedControl: the doc never says how a disabled option is disabled. `platforms.web.attributes` lists role=radio/aria-checked/tabindex and no disabled attribute, and `platforms.lit.notes` is silent. Native `disabled` would drop a checked-but-disabled segment (which `defaultValue` explicitly allows) out of reach of AT and would let Playwright refuse the click the `disabled-segment-is-not-selectable` scenario needs. Chose `aria-disabled="true"` plus a guard in the click handler, matching the React output; the behavior test needs `{ force: true }` because Playwright's actionability check treats aria-disabled as not enabled.
- SegmentedControl: the `keyboard` block lists only arrows, Home and End — no Space or Enter, which APG's radio pattern requires for activation. Because each segment is a native `<button>`, Space and Enter select anyway through the native click, so the control is operable; but the table as written does not describe that and the generation rule says implement the listed keys 'and nothing else'. Left the native behavior in place and added no explicit handler. The doc should either list Space/Enter as `native` rules or say the buttons carry them.
- SegmentedControl: `platforms.lit.reflect` includes `value`, but `value` is the controlled property while the uncontrolled selection lives in internal state. Reflecting the internal selection would make an uncontrolled element indistinguishable from a controlled one (and would make `value` look set when it is not). Chose to reflect only the `value` property, so an uncontrolled control renders with no `value` attribute even though a segment is checked. The doc should say which of the two `reflect: value` means.
- SegmentedControl: `minTarget` (size.target.min) is described only as 'each segment's minimum' with no axis. Applied it to both `min-inline-size` and `min-block-size`, matching the React CSS; on the inline axis it makes a one-character label render wider than its padding would give.
- SegmentedControl: the doc says a `value`/`defaultValue` naming a disabled option 'keeps that segment checked with the pill under it', but `disabledOpacity` is bound to the `segment` part only. The result is a full-opacity pill under a faded label. Drew it that way (the pill is a separate part, so the opacity does not cascade); if the pill should fade with its segment, the binding needs to name `indicator` too.
- SegmentedControl: it is unspecified whether a disabled icon-only segment still gets a Tooltip. Since `aria-disabled` buttons still receive pointer events, kept the `<ds-tooltip no-describes>` wrapper on every icon-only segment including disabled ones, so the label is still discoverable on hover.
- SegmentedControl: no behavior is specified for an empty `options` array (the 'two to five' guidance is explicitly not enforced and carries no warning). Renders an empty `role="radiogroup"` with no tab stop and no pill, and the keydown handler returns early — but an empty radiogroup is a control a keyboard user can never enter. Worth a documented warning or a stated no-op.
