# Gaps reported while generating DataGrid for lit

Each entry is a place the doc made the generator guess. Fix the doc, re-run parse, regenerate.

## 2026-09-10 14:08 — round 1

- DataGrid: platforms.lit.reflect names the showStatusBar attribute `show-status-bar` verbatim, but showStatusBar defaults to true — per the general 'booleans defaulting true reflect as a negated attribute' rule (and the Table.ts precedent for stickyHeader/`no-sticky-header`), I reflected it as `no-status-bar` instead so a static-HTML author can express false at all.
- DataGrid: stickyHeader is absent from platforms.lit.reflect's list entirely despite defaulting to true; I reflected it anyway as the negated `no-sticky-header` attribute (matching Table.ts) since height=viewport/fixed force it true and only height=content needs the toggle.
- DataGrid: the doc's Web/Lit platform notes describe composed editors (Input/NumberInput/Select/DatePicker/Checkbox) rendered with 'label visually hidden, size sm'; none of those Lit components expose a hideLabel or size prop (checked their actual @property lists), so the editor's label is visibly rendered at default size while a cell is being edited — there is no way to hide it without restyling the child's shadow tree, which the composition rules forbid.
- DataGrid: 'typing a character also opens it with that character' (Enter/F2 row of the keyboard block) is implemented only as 'typing opens the editor' — the typed character itself is not seeded as the editor's initial value, since forwarding a keystroke into five different composed field components' internal value/selection/cursor state isn't implementable generically without reaching into their internals.
- DataGrid: the Space row's own text is self-contradictory ('toggles the focused row' then, in the same bullet, 'Shift+Space selects the row' and 'Ctrl+Space the column in range mode'). I implemented: selectable=row → Space toggles the row (no Shift-range-extend, since the row's own bullet already claims Space alone does the toggle); selectable=range → Space selects the full-width 1-row range, Ctrl+Space selects the full-height 1-column range. This is a best-effort reading, not a literal implementation.
- DataGrid: resizable columns have no keyboard entry in the keyboard block (only pointer interaction is implied by 'draggable with the pointer and adjustable with arrow keys' in the Web platform note, which the keyboard block itself never lists as a key→action row). Per the instruction to implement keys 'exactly as listed and nothing else', resize is pointer-drag only; the separator is not independently focusable, so keyboard/screen-reader users cannot resize columns — flagging this as a real accessibility gap, not just an implementation shortcut.
- DataGrid: 'rowCount with onRangeNeeded lets the caller page in from a server' doesn't specify how a sparse/out-of-order window maps to `data` indices. I assumed `data` is always a contiguous prefix starting at index 0 that only grows by appending (never a sparse middle window), and fire `range-needed` when the virtualized scroll position approaches the end of the loaded prefix. Keyboard/PageDown navigation is clamped to loaded rows and does not itself trigger `range-needed`.
- DataGrid: pinned-column sticky offsets are computed among pinned columns only and ignore the selection checkbox column's width, so a pinned-start column combined with `selectable: row` will sit one checkbox-width off from the true visual left edge — a documented simplification rather than full sticky-offset arithmetic.
- DataGrid: 'activates it' for a body cell containing a Link/Button/Checkbox (via `column.render`) is implemented generically as `cellEl.querySelector('ds-button, ds-link, ds-checkbox, button, a[href], [role="button"]')?.click()`, since the doc gives no way to know the shape of a consumer's custom `render` output ahead of time; this may not correctly activate every possible control a consumer renders.
- DataGrid: the `position` copy ('Row {row}, {column}') is exposed as a single hidden `aria-describedby` span updated on every active-cell change, rather than announced through the polite live region on every arrow press (which would make the status-bar/live-region very chatty) — screen readers pick it up as part of the activedescendant cell's accessible description instead.
- DataGrid: Ctrl+A / Ctrl+C are bound via `event.key === 'a'/'A'`/`'c'/'C'`, which is US-QWERTY-centric; the doc doesn't specify a `code`-based binding, so this may not fire correctly on some non-Latin keyboard layouts.
- DataGrid: true drag-to-select for range mode is implemented only as click + Shift+click (anchor/extend), not a continuous pointermove-drag rectangle; the doc's 'Shift+arrow / drag rectangles' phrasing implies mouse-drag support that isn't built.
