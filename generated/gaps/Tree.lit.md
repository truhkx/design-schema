# Gaps reported while generating Tree for lit

Each entry is a place the doc made the generator guess. Fix the doc, re-run parse, regenerate.

## 2026-09-10 14:34 — round 1

- showGuides defaults to true, but platforms.lit.reflect literally names the attribute 'show-guides'; per this package's own negated-boolean-attribute convention (a true-default boolean can't be a positively-named attribute) I implemented it as 'hide-guides' instead, following the doc's own 'showValue -> hide-value' precedent — this contradicts the schema's literal reflect-list entry.
- labelSelectedWeight and badgeSize are declared overridable, but the composed <ds-text> label/badge expose only fixed enum props (weight, size), not free TokenRef overrides, so Tree's overrides prop can't actually push an arbitrary token into their rendered font-weight/font-size. The CSS custom-property hooks exist on the host (the documented 'escape hatch'), and the correct default appearance is produced via Text's own weight/size props, but the override path is inert until Text.ts gains a matching override binding.
- The multiple-mode 'Checkbox glyph' (doc: 'not the Checkbox component: the treeitem itself is the control') has no dedicated style binding for its box size/border/fill in the schema's styles list. I reused the locked iconColor token for the unchecked border, color.control.selectedBackground (same token as rowSelectedBorder) for the checked fill, and rowRadius for its corner radius.
- Mouse click semantics are unspecified (the doc only defines keyboard behavior and 'double-click' for activate). I chose: single click focuses + selects/toggles per selectable mode (mirroring Enter/Space), double-click activates.
- composition only lists expandButton: Button, icon: Icon, label: Text, omitting Link even though href nodes require composing it (per anatomy/platform notes), and omitting an explicit mapping for the badge anatomy part (rendered with Text, consistent with label).
- The empty state (nodes: [], copy.empty) is rendered as a single <li role="presentation"> inside role="tree" since the ARIA treeview pattern has no defined 'empty' treeitem shape; role=presentation keeps it out of the accessibility tree rather than exposing an invalid owned child.
- ArrowRight into an open parent's 'first child': when the literal first child is disabled, focus lands on the next non-disabled descendant instead (via the disabled-skipping navigable list), since the doc's 'first child' rule and its separate 'disabled nodes ... skipped by arrows' rule aren't reconciled.
- Shift+ArrowDown/Up ('extends selection to the next/previous node') is implemented as adding both the currently-focused and the newly-focused node to the existing selection, not a full anchor-based contiguous range, since the doc doesn't specify exact range semantics beyond that phrase.

## 2026-09-10 19:10 — round 1

- Tree: schema names both a `label` and a `link` anatomy part but never distinguishes when each applies; inferred that `label` is the ds-text-rendered node label (no `href`) and `link` is the ds-link-rendered one (`href` set), and split the previously-shared `part="label"` accordingly.
- Tree: `labelSelectedWeight` is documented as forwarded to the label Text's `overrides.fontWeight`, but ds-link (used for `href` nodes) exposes no font-weight override hook at all, so a selected navigation node's label cannot be bolded via this binding — only non-href (ds-text) labels respond to `--ds-tree-label-selected-weight`.
- Tree: `headingSize` says it's 'forwarded as overrides.fontSize' to the composed Heading; implemented by setting ds-heading's own `--ds-heading-font-size` custom property from the Tree's `--ds-tree-heading-size` hook (CSS-level forwarding) rather than calling the Heading's `overrides` prop with a TokenRef, since the latter would freeze the value and defeat runtime CSS overriding of the hook — same pattern already used by Divider for its composed Text.

## 2026-09-16 12:27 — round 1

- Tree: event payloads say `ids`/`id` keys (and the declared contract says detail has exactly the listed keys) but each description says 'as a bare array'; chose detail = the bare array / bare id string, matching TreeGrid in the same batch.
- Tree: timing order of `expand` vs `expand-change` on first expand of a lazy node is not given; chose expand first, then expand-change (as TreeGrid).
- Tree: label Text composition forwards only labelSelectedWeight, but Text defaults to size md, which would override the tree's own fontSize binding (font.size.sm); chose to also forward the tree's fontSize to the label Text's overrides.fontSize.
- Tree: expandButtonSize (size.target.min, locked) targets a composed Button that has no size override; chose a min-inline-size layout floor on the ds-button host and left its internals to Button.
- Tree: checkboxGap is 'between the checkbox and the label' but rowGap already separates every row child, and the icon may sit between them; chose margin-inline-end = checkboxGap - rowGap on the checkbox so the effective gap equals checkboxGap.
- Tree: Enter on an href node — spec says it 'follows href' and web notes say 'Enter activates it'; chose to programmatically click the composed ds-link's anchor (so consumer click routing still sees it) and not fire `activate`; with single it also selects first.
- Tree: the loading placeholder is 'a placeholder item with copy.loading' but its role is not specified; chose `li role=none` (not a focusable treeitem) inside the group, with aria-busy on the parent treeitem, and no Text composition since emptyState is the only listed Text for status copy.
- Tree: selectedCount live region — when it announces is not stated beyond 'in multiple mode the count is announced'; chose to announce on every user selection change in multiple mode only, and not to announce expand/collapse.
- Tree: Control+a — spec says Control only; Meta+A (macOS) is not listed, so it is not handled.
- Tree: type-ahead is listed as a-z; digits and other printable characters are ignored even though labels may start with them.
- Tree: ArrowLeft 'moves to the parent' does not say what happens when the parent is disabled (disabled nodes are 'skipped by arrows'); chose to stay put.
- Tree: `*` 'opens every sibling' does not say whether disabled siblings open; chose to skip disabled siblings.
- Tree: whether disabled nodes can be expanded by pointer is unstated; the chevron is disabled and clicks on a disabled row do nothing.
- Tree: in multiple mode with selectChildren, whether a parent's own id is kept in `selected` is unstated; chose to add a parent id when all its descendants are selected and remove it (and all ancestor ids) when any descendant is unchecked, deriving the parent's aria-checked from its descendants.
- Tree: whether the selected fill/bar applies to aria-checked nodes in multiple mode is unstated; chose to apply it to aria-checked=true as well.
- Tree: the tree element itself (ul role=tree) has no anatomy name (container is the wrapping div), so tests and styles cannot address it by data-part; tests query [role=tree].
- Tree: emptyState Text props (tone, element) are not given; chose default Text with no props.
- Tree: forwarded bindings (labelSelectedWeight, headingSize, badgeSize) reach children only via the `overrides` property; a consumer setting the --ds-tree-* hook from CSS for those three does not reach the child, since child overrides accept TokenRef only.

## 2026-09-17 15:25 — round 1

- Tree: the generated keyboard gate cannot express a tree's arrow navigation. tools/keyboard_tests.ts builds its focusable list from `a[href], button:not([disabled]), …, [tabindex]:not([tabindex="-1"]), [role=menuitem|option|radio]`, which has no `[role=treeitem]`; with the roving tabindex the doc mandates, exactly one treeitem is ever in that list, so the ArrowDown/ArrowUp/Home/End rules (expect: focus-next/focus-prev/focus-first/focus-last) compare indices over [one treeitem + the chevron buttons] and cannot pass. Kept the doc's roving tabindex and reported it rather than making every item tabbable. Fix is either `expect: manual` on those four rules (as ArrowRight/ArrowLeft already are) or adding `[role="treeitem"]` to the gate's selector. Read from the generated spec, not run — the gate needs three Storybook servers plus Playwright.
- Tree: the doc says the chevron Button is `tabIndex={-1}` and href labels compose a Link, which is a React-shaped instruction: in Lit a `tabindex` on a custom-element host does not reach the child's inner `<button>`/`<a>`, so a literal reading gives the tree N+1 tab stops and puts a tabbable button inside `aria-hidden` (an axe `aria-hidden-focus` failure). Chose to demote the composed control to `tabindex="-1"` after each render, as TreeGrid does for cell controls. The doc should say what a Lit composite does with a composed child's own focusable element.
- Tree: expandButton/heading/link wrappers contradict the sibling component. The Tree doc says these parts are wrappers the tree owns around an unmodified child, but TreeGrid — same repo, same chevron — puts `data-part="expandButton"` on the `ds-button` itself. Followed the Tree doc (wrappers), which also changes how a test reaches the chevron: `[data-part=expandButton] ds-button` then its shadow `button`. One of the two docs should move.
- Tree: the row order around the checkbox is unspecified. `checkboxGap` is described as the space "between the checkbox and the label", but an optional `icon` also sits in that span. Chose chevron → checkbox → icon → label, so when a node has an icon the checkboxGap lands between the checkbox and the icon, not the label.
- Tree: `expanded` (controlled) containing a still-`"lazy"` id is unspecified. The doc only rules on `defaultExpanded` ("a lazy id listed explicitly stays closed until the user opens it"). Chose: the default is filtered, but a controlled `expanded` is honoured verbatim — the node renders open with `aria-busy` and the `Loading` placeholder and no `expand` fires, since that is not a user act. A caller can therefore render a permanent `Loading`.
- Tree: "Shift+ArrowDown/Up cascade like Space" (selectChildren) is ambiguous, because Space toggles while Shift+Arrow only adds. Chose add-only: the node it lands on plus its loaded enabled descendants are added, and any ancestor whose enabled loaded descendants are then all selected is added; Shift+Arrow never removes.
- Tree: whether unselected nodes carry `aria-selected="false"` in `single` mode is unstated (platforms.web lists only `aria-selected`). Chose `aria-selected` on every node in single mode (`"false"` when unselected) and `aria-checked` on every node in multiple mode, which is what the derived `renders-selectable-single` test reads; the alternative (the attribute only on the selected node) changes what a screen reader announces for the rest.
- Tree: `Tab` "moves into the tree (to the selected node, else the first)" does not say which node when `multiple` has several selected. Chose the first selected in tree order. Related: the doc says a click does what Space does, but in `selectable: none` Space does nothing, so a click only focuses — while the RN notes say "in `none` a tap only activates". Web/Lit activate on double-click only, so single-click and tap disagree across platforms.
- Tree: copy.selectedCount is written into the visually-hidden `role="status"` region on every user selection change as the doc asks, but an identical string (two different single-node selections both yielding "1 selected") is not re-announced by screen readers. The doc does not say whether the region should be forced to re-announce.

## 2026-09-21 22:19 — round 1

- Tree: platform notes say the expand chevron is 'a Button with aria-hidden and tabindex=-1', but tabindex=-1 removes an element from the tab order, not from focus, so aria-hidden on a real <button> is axe's aria-hidden-focus. Dropped aria-hidden and kept the ds-button exposed under copy.expand/collapse with tabindex=-1. The doc should say the chevron stays exposed and reconcile that with its own 'the chevron is decoration (2.1.1)' guidance.
- Tree: with the chevron exposed, a treeitem's name-from-contents becomes 'Expand Documents Documents'. The doc gives no treeitem naming rule (rn has one: '{label}, level {n}'), and an explicit aria-label would have to invent punctuation for the badge, so nothing was added — matching React. The doc should state what names a web/lit treeitem once the chevron is not hidden.
- Tree: the lit notes name heading/expandButton/link as tree-owned wrappers and say 'Text takes data-part directly', but never say which Icon is. Unlike React (where Icon writes data-part="glyph" into the same tree), ds-icon's glyph part lives in its own shadow root, so data-part="icon" went on the ds-icon host with no wrapper — the `icon` part therefore resolves to a different element shape on lit than on web.
- Tree: the overrides contract says every style binding becomes a --ds-tree-* hook, but the lit notes say forwarded bindings reach the child through `overrides` only. Chose no hook at all for labelSelectedWeight, headingSize and badgeSize (a hook for them would be dead CSS); fontFamily/fontSize/lineHeight keep a hook AND are forwarded resolved.
- Tree: the generated keyboard gate's FOCUSABLE selector counts `button:not([disabled])` regardless of tabindex, so every visible chevron is an index in its focus list. That makes `End` fail whenever the last visible node is a parent (its chevron sorts after the treeitem). The Keyboard story's node list has to end in a leaf for the gate to pass — a constraint the doc's keyboard block does not state and no generator can infer.
- Tree: the doc never says what a key pressed while focus is on a composed control inside a treeitem (the chevron ds-button, an href ds-link — both tabindex=-1 but still focusable) should do. Chose to resolve the nearest [role="treeitem"] from the event target so arrows/Home/End keep driving the tree; without it ArrowUp and Home fail the keyboard gate.
- Tree: `expanded` says a held-lazy id 'stays in the array the caller passed and in what onExpandChange reports', but not what expand-change reports when the caller passed ["*"]. Chose TreeGrid's rule — the first user toggle resolves "*" to concrete loaded-parent ids and reports those, with held-lazy ids preserved in place.
- Tree: Control+a's 'the key never deselects' contradicts selectChildren's 'a parent's id is in selected exactly when all its enabled loaded descendants are'. Ctrl+A adds a collapsed unselected parent whose hidden descendants stay unselected, and normalising the invariant removes that parent id again. Chose the invariant, so Ctrl+A is a no-op for such a parent.
- Tree: a lazy id listed in defaultExpanded/expanded renders nothing and never requests children, since `expand` fires only for user acts — so no story can show copy.loading or the parent's aria-busy without an interaction, and the LazyLoading story only documents the closed state. The doc needs an example whose children are an already-loading array, or a play function.
- Tree: `selectOnFocus` says 'moving focus also selects' but the only scenario uses ArrowDown. Chose keyboard movement only — a click already selects, and selecting on Tab-in or on focus landing from a chevron click would fire a selection change on mere entry. The doc should say whether Tab-in and pointer focus count.
- Tree: nothing specifies what happens to DOM focus when a branch containing the focused node collapses. Arrow and chevron paths always focus the toggled node first, but a controlled `expanded` change that closes an ancestor drops focus to <body>. Left as-is; TreeGrid moves focus up to the collapsed row.
- Tree: rowSelectedBorder is 'an inset shadow on the row, or an absolutely positioned box' — used an absolutely positioned ::before on nodeRow with pointer-events:none, since the anatomy declares no part for it and no data-part hook exists.
- Tree: checkboxGap is 'the gap after the checkbox' while rowGap covers every other gap in the row. Chose nested flex groups (checkbox + body at checkboxGap, icon + label at rowGap inside body) rather than a margin, since a single flex gap cannot differ per pair.
- Tree: composition forwards headingSize to the Heading's fontSize, but ds-heading also has its own `size` prop, and the doc does not say which one the visible label should carry. Set size="md" plus overrides.fontSize=headingSize so the two agree at the default (React does the same); an override of headingSize alone silently disagrees with the Heading's `size`.
- Tree: story names are pinned by the doc only for the four `examples`. The rest were matched to the React package by hand (GuidesHidden, LazyLoading, SelectableSingle/Multiple args), and the lit-only SelectOnFocus and DisabledNode stories were dropped to keep parity — nothing in the doc records the non-example story set, so it can drift again on the next regeneration of either platform.

## 2026-09-23 13:58 — round 1

- Tree: the web/lit notes give the treeitem aria-label as `{label}, {badge}`, but copy has no key for that pattern, so it is built by string concatenation. The rule says to use copy.* verbatim; chose the concatenation the notes describe. A copy key (e.g. `nodeWithBadge: '{label}, {badge}'`) would make it translatable.
- Tree: 'When a controlled `expanded` change closes an ancestor of the focused node, focus moves up to that ancestor' does not say what happens when every ancestor up to the root is disabled or unrendered, or when a `nodes` change removes the focused node outright (no ancestor). Chose: move to the nearest enabled, rendered ancestor, and otherwise leave focus where the browser puts it.
- Tree: the doc does not say whether closing an opened lazy node and then receiving a controlled `expanded` that still lists its id should reopen it without a user act. Chose to re-hold it (it stays closed, like any held-lazy id), which fits 'onExpand only fires for user acts'.
- Tree: the lit notes ask for the inner ds-button `<button>` to be demoted to tabindex=-1 after each render, while the Lit conventions note (roving tabindex) says ds-button already forwards the host's tabindex to its inner button. Did both: the host has tabindex=-1 and the inner button gets a same-value-guarded demotion, which is harmless if redundant. The notes could name one mechanism.
- Tree: rowHover says 'a selected row keeps rowSelected' but not whether a mixed (indeterminate) parent, which has no selected fill, shows the hover. Chose to show hover on mixed rows, since only aria-selected=true and aria-checked=true rows are excluded.
- Tree: the new behaviour (reopening a lazy node fires `expand` again, focus moving to an ancestor on a controlled collapse, the explicit treeitem aria-label) has no behavior scenario, so no generated test covers it on any platform.

## 2026-09-23 13:59 — round 2

The hook is declared but nothing reads it, so it is dead CSS. - Tree: iconColor is locked but forwarded to ds-icon's overrides (not overridable, yet forwarded). The gate treats it as exempt, so no hook is declared. The doc could say plainly that a locked, forwarded binding has no hook.
