## 2026-09-16 04:11 — round 1

- Input: platforms.rn says it forwards onHoverIn, onHoverOut and onLongPress to the native element, but in RN 0.87 TextInput has none of them. I mapped onHoverIn/onHoverOut to onPointerEnter/onPointerLeave and built onLongPress from onPressIn plus a 500 ms timer (Pressable's default delayLongPress, marked literal-ok, since no token exists). - Input: Tooltip also sets onPressOut on its child, but the Input rn notes don't list it. I forwarded it too.
- Input: description and a parent's accessibilityHint (Tooltip) both go to accessibilityHint, and the spec doesn't say how to combine them. I read the description first, then the forwarded hint, joined with a space.
- Input: a parent's accessibilityLabel replaces the label as the accessible name, and the Fieldset legend still goes in front. The spec doesn't say which comes first; I followed Button.
- Input: 'disabled stays focusable' applies to web and Lit only. On native, editable={false} makes an iOS TextInput unfocusable, and the doc doesn't say whether native should use editable={false} or stay focusable and block edits. I kept editable={false} with accessibilityState.disabled.
- Input: the size binding says sm uses font.size.sm, but it doesn't say whether that covers only the field text or the label too. I sized the label with `size` as well; description and error stay at helperSize.
- Input: minTargetSm is locked and there's no locked minTarget swap per size in the overrides list, so the sm height floor is always size.target.min.

## 2026-09-17 04:27 — round 1

- Input: platforms.rn.notes says the label, description and errorMessage parts are 'the composed Text with testID="Input.<part>" passed to it, not a wrapper View', but Text's schema has no testID prop (and no accessibilityLiveRegion for the error announcement). - Input: the error-slot rule ('a message only while invalid is true: copy.required for an empty required field, else copy.invalid') doesn't say where the RN Form's per-field message (FormContext errors[name]) comes in the order. Chose error prop, then the Form's message, then the invalid-derived copy.
- Input: constant longPressDelay has no token expression, so 'logic reads each constant through its token expression' can't apply; kept a named module constant (500, marked literal-ok) matching Pressable's delayLongPress.
- Input: behavior scenario disabled-stays-focusable-and-is-announced keeps only `state: disabled` for rn, but the rn note says the field is not focusable on native (editable={false}). The test asserts accessibilityState.disabled and that RNTL treats the field as disabled; the scenario name contradicts native behavior and should be narrowed or renamed for rn.

## 2026-09-20 05:37 — round 1

- Input: the events block maps onChange to `onChangeText` on rn, but the prose ("Behavior", "React Native" platform note) only ever calls it `onChange`, and the committed component shipped `onChange`. I followed the contract, which is a breaking rename with four in-repo call sites. The doc should name the rn prop in prose too, or the events map should say `onChange`.
- Input: ref target is contradictory. The web note says the forwarded ref targets the <input> so focus()/select() work; the rn rule in the generation prompt says a component that exposes its root declares `ref?: Ref<ViewInstance>` and attaches it to the root. I attached it to the group View, which leaves no public handle on the TextInput — a consumer cannot focus the field except through the Form context. The doc should state which element native's ref means.
- Input: a11y.requires lists `target-44px`, but `minTargetSm` floors the sm field at `size.target.min` (24) and is locked as an accessibility floor. These contradict. I did not add hitSlop to make sm reach 44 — slop on a text field swallows taps meant for neighbouring grid cells — so `size: sm` does not meet target-44px. The doc should either exempt sm or say how it compensates.
- Input: the doc says the error wrapper carries `accessibilityLiveRegion` but never says polite or assertive. I chose `assertive` to match web's role=alert; `polite` is equally defensible and the two announce very differently over an already-speaking screen reader.
- Input: the iOS announcement is specified as firing "when it appears", which does not say what happens when the message changes from one error to another, or when it stays put across re-renders. I matched Checkbox's existing idiom (announce whenever the displayed message changes while defined), so an error that changes text re-announces.
- Input: `transition` is declared overridable and the rn note says it stays in the native overrides type "for parity" with no effect. Nothing in the component reads it, so it is the only binding that typechecks as accepted and is silently ignored — a caller gets no signal. The doc should say whether that is intended API or should be excluded from the rn union.
- Input: the `lineHeight` binding is documented as covering "the label and the field", so I set it on the TextInput's style. On Android an explicit lineHeight on a single-line TextInput clips descenders and mis-centers the text vertically. The doc does not say whether the field should take lineHeight at all on native.
- Input: an empty `error` string is specified to count as unset, but nothing is said about an empty `description`. I treated '' as unset for both, so an empty description renders no part View and contributes no trailing space to the accessibilityHint.
- Input: the Form contract says a field validates on blur when validateMode is `blur` or submitFailed, and on change when it is `change` or submitFailed. Read literally, a Form set to `validate: change` never re-validates on blur. I implemented it literally. If change-mode should also validate on blur, the contract should say so.
- Input: the error-slot precedence distinguishes "the Form's context entry with an empty message" (falls through to derived copy) from "no entry" (not invalid), but `FormContextValue.errors` is `Partial<Record<string, string | undefined>>`, where an entry explicitly set to `undefined` is indistinguishable from absence by lookup. I used hasOwnProperty for the presence test; the context type cannot express the distinction the doc relies on.
- Input: `hideLabel` with `required` has no visible carrier. The rn note says required is conveyed "by the copy.requiredIndicator label text alone" and that hideLabel drops the label Text entirely, so a hidden-label required field conveys required to screen readers (via accessibilityLabel) and to sighted users not at all. The doc should say whether that is accepted.
- Input: the synthetic long press is specified as cancelled by `onPressOut`. It does not say whether blur, a scroll that steals the touch responder, or a value change should also cancel it; I cancel only on onPressOut and unmount, so a press interrupted by a scroll still fires onLongPress.
- Input: focusRingWidth says "padding shrinks by the difference so the field does not shift", but at `size: sm` paddingBlock is `space.1`. If `border.width.focus` minus `border.width.thin` ever exceeds that, the compensation clamps at 0 (I used Math.max) and the field does shift on focus. The doc asserts no shift without bounding the tokens that make it true.
