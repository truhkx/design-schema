# Package conventions — @design-schema/react (web)

Versions (2026-09-11): React 19.3 (`ref` is a prop, no `forwardRef`) · TypeScript 7.0 (`isolatedDeclarations`, built by tsdown 0.23) · Storybook 10.6 CSF3 (`@storybook/react-vite`) · Vite 8.3 · Vitest 5.0 (jsdom).

Read this instead of the whole package. Open at most two files if a detail is missing: `packages/react/src/index.ts` (exports) and the one existing component closest to what you are writing.

- **Files.** `packages/react/src/<Name>.tsx`, `<Name>.css`, `<Name>.stories.tsx`. Component is a named export function component that takes `ref` as a prop; types exported alongside (`<Name>Props`, `<Name><Enum>` unions). Add `export { <Name> } from './<Name>'; export type { … } from './<Name>';` to `index.ts` in the existing style (one block per component, in order).
- **React 19: `ref` is a prop; no forwardRef; `useId`; Actions are not used by components.** The component signature is `function <Name>({ ref, …rest }: <Name>Props & { ref?: Ref<HTMLElement> | undefined }): ReactElement` with the root element's type in place of `HTMLElement` (`Ref<HTMLButtonElement>`); the ref goes on the root (`ref={ref}`, or `useImperativeHandle(ref, …)` when the root is owned by an inner ref). Never `forwardRef`, never `useActionState`/`useFormStatus`/form `action` props — Form submits through its own `onSubmit`.
- **A ref on a Fragment is a `FragmentInstance`, not an element: its `scrollIntoView` takes no options object** — only `scrollIntoView()` or `scrollIntoView(alignToTop: boolean)`, and passing `{ behavior, block, inline }` throws (React error #566) — so when a scroll needs options, put the ref on a real element or scroll the scroll container itself with `scrollTo`/`scrollBy`, and never inject a ref with `cloneElement` into a child that may be a `<>…</>` (unwrap fragments first, as Carousel's `collectSlides` and Toolbar's `flattenChildren` do).
- **Props.** `interface <Name>Props extends Omit<ComponentPropsWithoutRef<'element'>, 'conflicting' | 'keys'>`; every schema prop is a documented field with a JSDoc line taken from the schema description. Enum props whose values are digit strings also accept the number. `content` props are `ReactNode`. Function/array props use the schema `shape` verbatim; export the item type (`RadioGroupOption`, `BreadcrumbItem`). Optional props are written `name?: T | undefined` (function props `onX?: ((…) => void) | undefined`) — `exactOptionalPropertyTypes` is on, and callers pass `undefined` explicitly.
- **Types.** TypeScript 7 with `isolatedDeclarations`: every exported symbol carries an explicit type annotation, and no export type is inferred — components return `ReactElement` (`ReactElement | null` when they can render nothing), contexts are `Context<Value>`, hooks and helpers declare return types. `noUncheckedIndexedAccess`: an index read (`items[i]`, `list[0]`) is `T | undefined` — guard it, or assert with `!` where the index is known to exist. `verbatimModuleSyntax`: type-only imports use `import type` or inline `type` specifiers. Stories: `const meta: Meta<typeof <Name>> = {…}` (annotated rather than `satisfies`, so `typeof meta` in the exported stories is emittable). A test that spreads `meta.args` into the component casts the spread, since `Meta['args']` is a Partial: `<Name {...(props as ComponentProps<typeof Name>)} />`.
- **Ids.** `useId()` for every generated id; `aria-describedby` joins description and error ids.
- **Styling.** `import './<Name>.css'` (typed by `css.d.ts`). Class names `ds-<name>`, elements `ds-<name>__<part>`, modifiers `ds-<name>--<value>`. Every visual value is `var(--<token-kebab>)`; interpolated bindings become one modifier class per enum value (`.ds-button--primary { background: var(--color-action-primary-background) }`). No hex/px/ms/font literals — `tools/lint_literals.ts` fails the build. The visually-hidden clip pattern (1px) and `color-mix()` of tokens are the sanctioned exceptions; anything else needs `/* literal-ok: reason */`.
- **Overrides.** Every style binding is a CSS custom-property hook on the root, `--ds-<name>-<binding>` (kebab), defaulting to its token; rules read the hook. `overrides?: Partial<Record<OverridableBinding, TokenRef | undefined>> | undefined` (`import type { TokenRef } from '@design-schema/tokens'`, `cssVar(ref)` from the same package) writes hooks inline; locked bindings (listed in the prompt) are excluded from the type but keep their hook — `locked` closes the override API, not the styling hook, so a locked binding stays themeable from page CSS and renameable by the naming codemod. Only a binding forwarded to a composed child's `overrides` declares no hook of its own.
- **Spacing between siblings** is never a margin: Stack `gap` (`layout.gap.*`), Box/Card `inset` (`layout.inset.*`), Container gutters. A resolved token path ending in `.default` drops it (`--color-background`).
- **States.** `disabled` → `aria-disabled="true"` + the element stays focusable; on checkable inputs also `preventDefault()` in `click` and `change`. `:focus-visible` outline `var(--border-width-focus) solid var(--color-border-focus)`. Transitions use the component's `transition` token with `var(--motion-easing-standard)` and are removed under `@media (prefers-reduced-motion: reduce)`. Disabled dims with `var(--opacity-disabled)`.
- **Form fields** register with `FormContext` (`useFormContext()`): `{ name, label, id, getValue, validate, focus }`; `getValue` returns `string | boolean | undefined` (undefined = omitted). Validation precedence: `error` prop → `required` (`copy.required`) → `invalid` (`copy.invalid`), with `{label}` replaced by the visible label. `validate: blur` means on-change for toggles.
- **Re-validation after a failed submit.** Every field that validates reads the Form's mode and `submitFailed` together, spelled as Input spells them: `const validateMode = form ? (form.validateMode ?? form.validate) : undefined; const afterFailedSubmit = form?.submitFailed ?? false; const validatesOnChange = validateMode === 'change' || afterFailedSubmit; const validatesOnBlur = validateMode === 'blur' || validateMode === 'change' || afterFailedSubmit;` (a toggle validates on change under `blur` too), and calls `form.validateField(name)` from those two flags only. Never compare `form.validate` alone: under `validate: submit` a field that ignores `submitFailed` keeps showing its error after the user corrects it, until the next submit (Listbox and DatePicker shipped that way). `validateField` runs the registration's `validate()` synchronously, before the re-render: a field whose `validate()` reads a render-refreshed ref (`latest.current`) writes the new value into it before calling `validateField`, or it validates the value it just replaced (Listbox; Input reads the DOM, DatePicker its `valueRef`). A field that never validates (Switch) and a control that is not a field (SegmentedControl) have nothing to re-validate.
- **`aria-hidden` never wraps a control.** A subtree with `aria-hidden="true"` must contain nothing focusable, and `tabIndex={-1}` does not help: it removes an element from the tab order, not from focus, so a `<Button tabIndex={-1} aria-hidden>` is still a click target inside a subtree screen readers cannot reach. That is axe's `aria-hidden-focus` (TreeGrid's expand control, NumberInput's steppers). Hide the decoration — the icon, the indent span — and leave the control itself exposed with its real label; a plain non-focusable element such as a scrim may keep `aria-hidden` and its `onClick`. Where a whole subtree really is unusable, `inert` it (which does remove focus) rather than hiding it from AT alone.
- **Copy** strings from the schema are constants used verbatim (`const COPY = { required: '{label} is required.' }`).
- **Composition.** Use `Button`, `Link`, `Text`, `Icon` from the package; never restyle a child (no class overrides). Icons go through `Icon` (`<Icon name="check" inline />`) or a component's `leadingIcon` prop.
- **Icon glyphs come from `tools/icon-paths.json`**, the one table every platform draws from: one SVG path `d` per glyph name on the 16×16 grid, plus `filled`. When Icon is regenerated, build its `paths` table from that file — one `<path d={…} />` per glyph, `filled` ones carrying `fill="currentColor" stroke="none" fillRule="evenodd"` — with the `d` strings verbatim, and take the names and their order from it. To add or redraw a glyph, change the JSON, not `Icon.tsx`: `packages/swiftui/Sources/DesignSchema/Icon+Paths.swift` (`pnpm icons`) and the reference PNGs in `tests/icon-snapshots/` (`pnpm icons:snapshots`) are generated from the same table, and the SwiftUI gate fails on any glyph whose pixels disagree with them.
- **Dev warnings** are guarded by `process.env.NODE_ENV !== 'production'` (a `declare const process` shim is acceptable).
- **Stories.** Storybook 10 CSF3, `import type { Meta, StoryObj } from '@storybook/react-vite'`, `title: '<Name>/React'`, `Default` plus one story per enum value named `<Prop><Value>` (`ToneInfo`), plus notable states. `tags: ['autodocs']`. Demos live in `packages/react/demo/` with `title: 'Demo/<Name>/React'`. CSF factories (`preview.meta()`) are not used.
- **Tests.** Vitest 5 on Vite 8 (`packages/react/vitest.config.ts`, jsdom, `@testing-library/react`); behavior scenarios become `<Name>.test.tsx` beside the component. No Jest.
- **Theming** is external: the app loads `@design-schema/tokens/calm-precise/css` once and toggles `data-mode="dark"` on `<html>`; components contain no theme logic.
- **Testability hook.** The root element carries `data-ds="<Name>"`. Components generated before this convention lack it; add it to any file you touch, and never rely on its absence.
- **Parts and props.** `data-part` values are the anatomy names verbatim (`headerActions`, not `header-actions`); a part drawn as a pseudo-element has no hook. `...rest` never forwards `style` or `className` to the root — the override contract is the only per-instance styling. An override for a composed child's binding is forwarded to that child's `overrides` (Fieldset → Stack `gap`, Divider → Text `fontSize`, Alert → Icon `color`/`size`), never applied as CSS on the child.
- **Observer callbacks converge.** Roving tabindex (Toolbar, Tree, TreeGrid, DataGrid, Menu, RadioGroup, SegmentedControl) and similar DOM bookkeeping write only when the value changes: `const next = index === current ? 0 : -1; if (el.tabIndex !== next) el.tabIndex = next;`. A same-value `tabIndex`/`setAttribute` write still queues a mutation record, so a `MutationObserver` whose `attributeFilter` includes what its callback writes (`tabindex`, `aria-checked`, `disabled`) re-fires itself forever and freezes the tab. The same goes for `ResizeObserver`: `observe()` always delivers one initial notification, so an observer created in an effect that re-runs after the state its callback sets (Toolbar `overflow: menu` remeasuring) must compare the new size with the last one it saw before setting state, or it remeasures every frame.
- **Portals.** Every overlay rendered through a portal accepts `container?: HTMLElement` (default `document.body`) as a platform prop; it is not in the schema and never affects semantics.
- **SSR-safe rendering: nothing browser-only shapes the markup before mount.** The website server-renders every component and hydrates it, so the first client render must produce exactly what the server did. Never read `window`, `document`, `matchMedia`, `getComputedStyle` or `localStorage` in render or in a `useState` initializer (`useState(() => query.matches)` is the bug); start from the server's answer (`false`, narrow, not persistent) and correct it in a layout effect after mount. A portal, and anything else that needs `document`, renders only once hydrated: `const hydrated = useSyncExternalStore(subscribeNothing, () => true, () => false)` (false on the server and through hydration, true on a client-only mount), then `{hydrated && host ? createPortal(…, host) : null}` — `typeof document === 'undefined'` is *not* this gate, since it is true on the client during hydration. Every layout effect that reads a ref inside the portal (showModal, the enter frame, initial focus) lists `hydrated` in its deps, or it runs once against a null ref and never again. A presentation switch decided by a media query (ActionSheet sheet vs Menu, SidePanel persistent sidebar) renders the narrow form on the server and switches after mount. `packages/react/src/hydration.test.tsx` checks this with `renderToString` + `hydrateRoot`; add any new portaled overlay to it.
- **Overlay open state: the visible flag follows the DOM, not the prop.** An overlay that animates in mounts closed (`present` true, `--visible` off) and turns its `--visible` / `ds-<name>__surface--visible` class on in a `requestAnimationFrame` scheduled from a layout effect keyed on everything that decides whether the surface exists — `present`, `open`, the presentation (persistent, wide), and `hydrated` — so the flip is never scheduled before the surface is in the DOM, and whatever path set `open` (the trigger, a controlled `open` prop, the site's own harness) reaches it. The open class is derived from that one flag (`shown = visible && open`), never from a separate `data-state` or a prop only the trigger path sets.
- **Form fields.** Every field component's root carries `data-ds-field` (plus `data-ds`); Form discovers fields by that attribute, never by a tag or component list. A field's label is a native `<label for>` styled from the field's label bindings; description and error text are Text.
