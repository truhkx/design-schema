# Gaps reported while generating Listbox for web

Each entry is a place the doc made the generator guess. Fix the doc, re-run parse, regenerate.

## 2026-09-10 09:40 — round 1

- props: schema has no `error`/`invalid` prop (unlike RadioGroup/Checkbox/Fieldset), yet a11y.requires lists error-identification and copy has `required`. Implemented required-only validation via Form registration; the error message (when Form supplies one) is rendered visibly with role=alert, but there's no way for a consumer to pass an ad-hoc error directly to a standalone Listbox outside a Form.
- platforms.web.attributes for the root omit aria-invalid/aria-required/aria-describedby entirely (only role=listbox, aria-label, aria-labelledby, aria-multiselectable, aria-activedescendant, tabindex=0 are listed for the root; aria-disabled/aria-selected are listed but read as per-option). Followed the whitelist literally and did not add aria-invalid/aria-required/aria-describedby to the root, so the visible error text and `required` state are not programmatically associated with the listbox for screen readers beyond the Form's own error-summary link.
- FormContext's `FormFieldValue` was `string | boolean | undefined`, which can't represent multi-select's array value described in the docs ('Multiple values are collected as an array'). Widened it to `string | string[] | boolean | undefined` in FormContext.ts (shared file) since no narrower fix was possible.
- styles.optionSelectedCheck (locked) has no dedicated CSS hook on the Listbox root — mirrored Alert's pattern of forwarding a locked color straight into the composed Icon's own `overrides` prop rather than declaring an unused `--ds-listbox-*` hook that no rule would read.
- onChange/onActiveChange fire as `(value)` / `(value | null)` with no DOM event, since a selection can originate from a keyboard key, a pointer click, or a programmatic multi-select toggle (Ctrl+A) with no single native event to forward — mirrors Menu's `onAction(id)`.
- Home/End and typeahead aren't explicitly said to honor `selectionFollowsFocus` (only ArrowUp/ArrowDown's action text mentions 'selects it when selection follows focus'); implemented Home/End/typeahead through the same `moveActive` helper as the arrows for a consistent single-select picker feel, so they also auto-select when `selectionFollowsFocus` is true.
- Enter's action text says 'Selects the focused option (single)' with no `when: multiple` gate like Shift+Arrow/Ctrl+A have; treated it as single-select-only (a no-op in `multiple` mode, where Space is the only committer) rather than replacing the whole multi-selection with one value.
- ArrowDown/ArrowUp aren't documented as wrapping; implemented them as clamping at the first/last enabled option (Home/End reach the ends explicitly) rather than cycling.
- maxVisible's row-based scroll cap has no row-height token and platforms.web has no mechanism note (only the RN notes describe 'maxHeight = rows × row height measured from the first row'); ported that same runtime-measurement technique to web (via `getBoundingClientRect`) since inventing a fixed px literal would fail the literal lint and no token exists for a single option row's height.
- optionSelectedCheck's token comment ('always rendered — invisible slot when unselected — so labels align') isn't scoped to `multiple` even though the `multiple` prop's own description says 'each option shows a check indicator'; rendered the check indicator in both single- and multi-select modes for alignment, per the token note.
- copy.selectedCount is documented as text 'the surrounding UI' shows, not part of this component's own anatomy; it's defined in COPY for completeness but never rendered by Listbox itself.

## 2026-09-10 18:32 — round 1

- Listbox: the existing implementation was missing the `invalid`, `error`, `embedded`, `defaultActiveValue`, and `loading` props entirely (only `label`, `labelledBy`, `options`, `multiple`, `value`, `defaultValue`, `selectionFollowsFocus`, `required`, `disabled`, `name`, `emptyMessage`, `maxVisible` were present) — added all five to match the schema, plus the corresponding `aria-invalid`, `aria-required`, `aria-busy`, and `aria-describedby` root attributes that were also missing.
- Listbox: the schema's `invalid` prop description says it renders 'with `copy.invalid`', but no `invalid` key exists under the component's `copy:` block (only `empty`, `required`, `selectedCount`, `loading`). Treated `invalid` as a state-only flag (sets `aria-invalid`) with no bundled message; `error` (explicit prop) takes precedence over the Form-derived required-validation message for the visible error text.
- Listbox: `defaultActiveValue` vs. the documented default ('first selected, else first enabled') isn't given an explicit precedence order. Chose: `defaultActiveValue` wins if it names an enabled row, else first selected, else first enabled — applied once on first focus via a new `onFocus` handler (previously there was no focus-driven initial-active logic at all).
- Listbox: `embedded` has no dedicated override-suppression rule in the spec beyond 'overrides change values, never presence.' Implemented by having `.ds-listbox--embedded` set `border`/`border-radius`/`background-color` directly (bypassing the `--ds-listbox-border*`/`-radius` hooks), so any `border`/`borderWidth`/`radius` override becomes a no-op while embedded, per the stated contract.
- Listbox: `copy.selectedCount` is explicitly documented as shown by surrounding UI, not the component itself, so it's omitted from the component's `COPY` object (kept as a code comment, not exported) — flagging in case a consumer expects it re-exported for reuse.

## 2026-09-16 08:13 — round 1

- Listbox: `initialActiveValue` replaces the previously generated `defaultActiveValue`, and the schema declares no deprecation for the old name; Select.tsx (the only caller) was updated to the new name rather than keeping an alias.
- Listbox: `optionSelectedCheck` says the check is 'rendered only with `multiple`; single-select shows selection by the row fill' and also 'always rendered (invisible slot when unselected) so labels align', while `optionActiveBackground` says selection is shown 'by the check and weight' and the row fill is the active state. Chose: the check slot exists only with `multiple` (always present there, hidden when unselected); single-select shows selection by `optionSelectedWeight` alone, never a fill, so active and selected stay distinct.
- Listbox: `maxVisible` prop says height is 'rows × the height measured from the first rendered row'; the guidance says rows are 'fontSize × lineHeight + 2 × optionPaddingBlock' tall. Chose the formula as a pure CSS calc (max with minTarget, plus list padding and border) via per-value modifier classes, with no DOM measurement; rows with a description are taller than counted.
- Listbox: `errorMessage` is in the anatomy but the root must be the role=listbox element, whose children may only be options/groups. Chose to render the error Text as a sibling after the listbox (component returns a fragment); nothing spaces it from the list, since no binding exists for that gap and margins are forbidden.
- Listbox: `copy.invalid` uses `{label}`, but with `labelledBy` the visible label text is unknown to the component; the `label` prop is interpolated in both cases.
- Listbox: `optionGap` is 'between check, icon, label and description' only; the earlier generation also used it between rows. Rows now have no gap (row height formula assumes none).
- Listbox: behavior when Space/Enter is pressed with no active option (list never focused, e.g. keys forwarded by a Combobox) is unspecified. Chose: they act on the resolved initial active option (initialActiveValue → first selected → first enabled); ArrowDown/ArrowUp with no active option land on the first/last enabled option rather than moving past it.
- Listbox: Shift+Arrow says 'adds' the option; whether it removes an already-selected one is unstated. Chose add-only. Ctrl+A 'again clears' — chose to clear only enabled options, leaving selected disabled options selected.
- Listbox: typeahead timeout is unspecified and has no token; used a 500ms internal constant (interaction timing, not rendered).
- Listbox: PageUp/PageDown with `maxVisible: all` has no visible row count; chose to jump to the first/last enabled option.
- Listbox: whole-list `disabled` keeps focus (tabindex=0) and sets aria-disabled on the listbox; keys, hover and clicks do nothing. The schema lists aria-disabled only among option attributes.
- Listbox: form `valueType: string[]` but single-select submits a single string in the React Form contract (FormFieldValue); chose string for single, array for multiple, omitted when empty.
- Listbox: `data-ds-field` is set only when `name` is given, since guidance says a list without `name` does not register with a Form; the convention says every field root carries it.
- Listbox: `emptyColor` (locked) has no part; the emptyState part is Text tone=muted, which resolves to the same token, so the hook is declared but not read.
- Listbox: `invalid` has no visual binding (no border-invalid token), so invalid is conveyed by aria-invalid and the rendered copy only.

## 2026-09-17 11:42 — round 1

- Listbox: the spec makes the root a wrapper div (data-ds) around the role=listbox list, but never says which element gets `id` and the `...rest` DOM props. Select depends on `${id}-option-${value}` ids and aria-controls pointing at the listbox, so `id` goes on the list. `ref` and `...rest` go on the wrapper, and keydown/focus/blur are handled there so a host can dispatch events on the ref.
- Listbox: the Web platform notes ask for a `useListbox` hook/ref exposing `activeId` and the keydown handler for Combobox. No prop, event or type in the schema describes it, and today's React Combobox doesn't need it. Not built; the equivalent is sending keydown/focusin to the ref.
- Listbox: typeaheadReset is 'read at runtime from the list', but the spec doesn't say how to turn a CSS time into a timer or what to do when it can't be read (jsdom, no token stylesheet). I parse `ms`/`s` from getComputedStyle; if it can't be read the buffer clears right away, so only single-letter typeahead works.
- Listbox: `onActiveChange` fires 'with null when the list loses focus', but in Select, DOM focus stays on the trigger and the list never gets real focus. Only a real blur of the list element clears the active option, so a host that fakes focus with `focusin` has to reset the active option itself.
- Listbox: the spec lists `aria-describedby` on the list and `aria-describedby` for descriptions, but doesn't say whether option descriptions are linked. Each option's description gets an id, and the option points to it with `aria-describedby`.
- Listbox: 'a composed part receives exactly the listed props' clashes with what the component needs: the errorMessage Text needs an `id` (for aria-describedby) and every part needs its `data-part` hook, and optionCheck needs its check colour. Kept `id` and `data-part`, dropped `role=alert` and `element`, and passed the check colour to Icon `overrides.color` because the binding names part optionCheck. Icon `size: sm` is only specified for optionIcon; the check uses it too.
- Listbox: the `copy.selectedCount` text is declared, but on web nothing in the list shows it (the guidance says the surrounding UI does). Kept in COPY, unused.
- Listbox: making ListboxOption a single row (per the `options` description) broke Select.tsx, Select.stories.tsx and Combobox.tsx, which used it as the row-or-group type. Changed them to ListboxItem/ListboxGroup; Combobox's filterTree no longer recurses, because groups don't nest.
- Listbox: 'implies invalid' + 'invalid while invalid OR error is non-empty': the spec doesn't say whether a Form error message alone (with no `error` prop) sets aria-invalid. It does, because an error message is showing.

## 2026-09-21 12:26 — round 1

- Listbox: the doc puts the empty/loading row inside the list with the option padding, but a role=listbox owns only option/group, so axe's aria-required-children fails every empty story (loading escaped only because aria-busy exempts the rule). Chose to hide the row from AT and point the list's aria-describedby at it, so the message is still announced on focus; the doc should state which element the empty state is and how it is announced.
- Listbox: `optionWeight` is in the overridable list with token font.weight.regular but no `state`, while `optionSelectedWeight` has none either. Chose optionWeight as the base weight on every row with the selected modifier overriding it; the doc should say the selected rule wins rather than leaving two unqualified weight bindings on the same part.
- Listbox: the web platform block lists `tabindex=0` flatly, while `embedded` says an embedded list is not a tab stop (tabindex=-1). Chose tabindex=-1 when embedded, 0 otherwise; the attribute list should carry the condition.
- Listbox: `initialActiveValue` moves the active option 'without firing onActiveChange' when it changes 'while the list has no focus', but for an activedescendant composite the host (Combobox) holds DOM focus and still drives the list. Chose the test 'the list element does not contain document.activeElement', so a host-driven list always follows the new value.
- Listbox: `copy.selectedCount` has no web surface — the doc assigns it only to RN's accessibilityValue and otherwise says 'the surrounding UI shows it'. Left it defined and unused on web; if the web list should announce the count (a visually-hidden line, or aria-description), the doc must name the element.
- Listbox: the `options` description mandates that 'a previously exported ListboxGroupOption stays as a deprecated alias of ListboxOption', but the React package never exported that name (it exports ListboxOption/ListboxGroup/ListboxItem already). Added no alias rather than inventing a deprecated export; the doc should scope that clause to the platforms it applies to.
- Listbox: PageUp/PageDown 'moves by the maxVisible row count' — ambiguous whether that count is over enabled options or over drawn rows (which include disabled options and group labels, the things maxVisible's height formula counts). Chose enabled options, so the move never lands on a disabled row and never stalls.
- Listbox: `optionGap` is documented as the gap 'between check, icon, label and description', but the description renders under the label in a column, where layout.gap.normal would be far looser than the theme's density. Applied the gap only along the row (check/icon/text), with no gap between label and description.
- Listbox: `value`/`defaultValue` are typed `string | string[]` regardless of `multiple`, and the doc never says what a single-select list does with an array (or a multi-select with a bare string). Chose to normalise both ways — an array's first entry is the single selection, a string becomes a one-entry array — rather than warn.
- Listbox (harness, not the component): the generated keyboard spec's ariaState() reads aria-expanded/checked/selected off document.activeElement without following aria-activedescendant, which its own focusIndex() does follow. For this one activedescendant composite that makes the Space and Enter rules unpassable by any spec-conforming implementation; a browser check confirms both select the active option. The same root cause likely explains Combobox's two keyboard failures.
