# Gaps reported while generating Carousel for rn

Each entry is a place the doc made the generator guess. Fix the doc, re-run parse, regenerate.

## 2026-09-10 13:01 — round 1

- Carousel: "Previous and Next move one slide (or one page of perView)" doesn't define page alignment, so Next/Prev/autoplay/swipe-detection all advance exactly one slide index at a time; perView only changes how many slides are visible at once (item width = viewport/perView), never the step size.
- Carousel: styles.controlBackground (color.overlay.surface, locked) and controlShadow can't be applied to prevButton/nextButton directly — the composed Button has no plain 'background' override slot, and restyling a child is forbidden. Implemented as Button variant="ghost" (transparent) inside a small wrapper View that carries controlBackground/controlShadow and a radiusFull backdrop, so the 'overlaid arrows sit on a readable surface' intent is preserved without touching Button internals.
- Carousel: the play/pause control is rendered only when autoplay && !reducedMotion, since 'Starts only when the user has not asked for reduced motion' makes rotation permanently impossible under reduced motion — judged a visible-but-dead control worse than omitting it; a persistently-rendered disabled pause button may have been intended instead.
- Carousel: 'stops on hover, focus, touch' — hover doesn't apply on native. Touch is handled (onTouchStart on the region, onScrollBeginDrag on the track). Focus-based pausing could only be wired for the hand-built picker items; prevButton/nextButton/playButton are composed Buttons with no onFocus prop exposed, so focusing them cannot pause autoplay.
- Carousel: platforms.rn asks for accessibilityRole="adjustable" with increment/decrement actions on the region while also requiring prevButton/nextButton/picker to be individually reachable in tab order. Implemented without accessible={true} on the region so descendants stay individually focusable, with adjustable role/actions layered on as the documented swipe alternative — exact VoiceOver behavior for an adjustable-but-not-collapsed container is unverified.
- CarouselSlide.heading is a plain string prop (not rendered) used only to build each slide's accessibility name and its tabs-picker label, since RN can't extract text from arbitrary children; the visible content must repeat its own heading (e.g. inside a Card), mirroring the web model's separate aria-label.
- Carousel: snap=false only disables native paging/snapToInterval (scrolling/swiping still works); the spec only describes snap's 'on' behavior.
- Carousel: non-loop autoplay that reaches the last page simply stops advancing (no bounce/reverse), since the spec doesn't define wrap-less autoplay's end behavior.

## 2026-09-16 11:02 — round 1

- Carousel: the RN platform note says the composed arrow and play Buttons expose no focus callback, so focus cannot pause rotation. The package Button does forward onFocus/onBlur, so I wired them (and the picker items' focus) to pause autoplay while focus lasts, as the Behavior section asks for web.
- Carousel: the platform notes say autoplay is 'cleared on any touch' / 'setInterval cleared in onTouchStart', but Behavior says touch pauses 'only while they last' and only the pause button stops it for good. I followed Behavior: the region's onTouchStart/onTouchEnd/onTouchCancel pause and resume, and only the pause button (or reaching the end without loop) stops rotation.
- Carousel: the region is accessibilityRole=adjustable but deliberately not `accessible`, as the notes require. On iOS a non-accessible View is not a VoiceOver element, so its increment/decrement actions may never be reachable. The spec doesn't reconcile keeping the controls individually reachable with a working adjustable region. I kept the note's form and added accessibilityValue (copy.slideLabel).
- Carousel: the accessibility action labels for increment/decrement are not in copy; I reused copy.next and copy.previous.
- Carousel: the spec gives no rule for where Next lands when fewer than perView slides remain, or what loop does with a partial last page. I chose: Next clamps to the last full page (total - perView), Next from there wraps to 0 with loop, and Prev from 0 wraps to total - perView. Picker indices are clamped the same way.
- Carousel: a dots picker with perView > 1 has one dot per slide (copy.goTo is per slide), but the spec doesn't say which dots are 'current'. I marked every slide on the current page as selected.
- Carousel: the Tab order in the keyboard rules (play/pause, previous, next, picker, then slide content) can't be matched without extra layout tricks, because the picker sits visually below the slides. Native focus follows view tree order, so the RN order is play, previous, next, slides, picker.
- Carousel: the tabs picker has no tab typography, colour or selected-indicator tokens (only dot tokens exist). I composed the package Text: size sm, weight semibold when selected and regular otherwise, tone strong when selected and muted otherwise, padding space.sm, with a size.target.comfortable target (the minTarget binding). Dots use dotTarget (size.target.min).
- Carousel: the `transition` binding covers 'dot and tab state changes'. Tabs change weight and tone, which can't animate, so only the dot background colour animates (motion.easing.standard, instant under reduced motion).
- Carousel: the controlSurface radius is described only in the web notes ('a full radius') and has no binding; I used radius.full on RN.
- Carousel: controlOffset has no `part`; I applied it as horizontal padding on the overlay that holds the two controlSurfaces inside the viewport. The play button's distance above the viewport is not specified; I used layout.gap.tight as padding (not a margin).
- Carousel: prevButton, nextButton and controlSurface parts can't carry `Carousel.<part>` testIDs on the composed Button (Button hard-codes testID="Button"), so each part testID sits on a wrapper View: controlSurface wraps the prevButton/nextButton View, which wraps the Button. Both controlSurface wrappers share one testID.
- Carousel: 'fewer are shown as the viewport narrows (one below the prose width)' comes with no RN measurement rule; I compared the viewport's onLayout width with t.layoutMaxWidthProse. Before the first layout, perView applies as given.
- Carousel: the notes use onViewableItemsChanged for the index, but it also fires during scrolls started by code (arrows, picker, controlled prop changes), which would be misreported as `swipe`. I only honour it between onScrollBeginDrag and onMomentumScrollEnd; this isn't specified.
- Carousel: the interval dev warning is only shown when autoplay is on (the value is unused otherwise); the spec doesn't say.
- Carousel: the liveRegion accessibilityLiveRegion switches to 'none' while rotating, following the web aria-live rule; the RN notes only mention announceForAccessibility, which I also call on iOS for user-initiated changes.
- Carousel: the AmbientHero and ThreeUpGallery examples call for photographs and images, but the package has no image assets or Image component; the stories use strong-surface Boxes with a visible heading as stand-ins.
- Carousel: the Keyboard story has no `given` to follow; it turns autoplay on so the play/pause control is present, and puts a focusable Button in each slide (demo text 'Add to cart' is story content, not copy).
