The [ARIA Authoring Practices Guide](https://www.w3.org/WAI/ARIA/apg/patterns/) is the behavioral reference for this system. When Material, Primer, Polaris and Spectrum disagree about how a widget should behave, the APG wins; the theme decides how it looks. Each component doc names the pattern it implements in its `apg` field, and the generation prompts tell the AI to follow that pattern's keyboard and focus rules.

The APG is written for the web. Native platforms have their own idioms (bottom sheets, action sheets, pull-to-refresh) and their own accessibility APIs (traits, `accessibilityRole`, `accessibilityActions`). The roadmap therefore has two sources: the 30 APG patterns and a short list of mobile patterns with no APG entry, each of which is documented as a variant of the closest APG pattern so the a11y rules carry over.

## Order of work

Components are grouped into tiers by what they require from the schema and from each other. Each tier introduces a small number of new accessibility requirements, which are added to the schema enum before the tier starts so nothing is bolted on later.

**Tier 0 — done.** Button, Heading, Text, Input, Form, Stack. Requirements exercised: accessible-name, focus-visible, keyboard-operable, target sizes, contrast, heading-hierarchy, label-association, error-identification.

**Tier 1 — done (docs and generated code; verification on a real toolchain pending).** Link, Checkbox, Switch, RadioGroup, Disclosure, Alert, Landmark, Breadcrumb, Meter. Requirements exercised: `expanded-state`, `live-region`, `landmark-role`, `arrow-navigation`, `roving-tabindex`, `reduced-motion`. What the tier added to the system: `color.status.*`, `color.link.*` and `color.control.*` semantic tokens derived per mode with contrast-aware step selection; `array`/`object`/`function` prop types with a `shape`; a `copy.invalid` string on every validating control; a Form value contract (`string | boolean`, absent when empty); `keepMounted` on Disclosure; and the rule that composites never restyle a child. Still owed from this tier: an **Icon** primitive (every icon so far is a hand-drawn glyph), a shared visually-hidden utility, and a Fieldset.

**Tier 1.5 — primitives and surfaces.** Icon (done; generated by the pipeline), Box, Card, Container (docs done — they are the components that dogfood the `layout.*` rhythm tokens and the override contract; see [Layout and rhythm](/foundations/layout/) and [Styling and overrides](/foundations/styling-and-overrides/)), then Fieldset and Divider. Stack's `gap` moved from raw `space` steps to the `layout.gap` presets.

**Tier 2 — overlays (docs done 2026-09-10; generation pending).** Dialog, AlertDialog, BottomSheet, ActionSheet, Tooltip, Toast, Menu. What the tier added before a line of code: `keyboard` (key → action from the APG) and `composition` (anatomy part → system component) schema blocks with parser checks; requirements `inert-background`, `scroll-lock`, `no-hover-only`; tokens `color.overlay.*`, `color.inverse.*` (with a contrast-chosen step per status tone), `shadow.{raised, overlay}` scaled by a new `elevation` theme decision, and `layer.*`; Button gained `inverse`. SidePanel (added 2026-09-10) is the start/end-edge drawer built on the APG disclosure pattern — a button with `aria-expanded`/`aria-controls` showing a landmark region, focus staying on the button — with `modal` opting into the dialog behavior and `persistent` turning it into a desktop sidebar. Every overlay decides its presentation by the `layout.maxWidth.prose` breakpoint — BottomSheet becomes Dialog and ActionSheet/Menu swap — so screens are written once. 226 contrast pairs, 0 failures.

**Tier 3 — composite selection (docs done 2026-09-10; generation pending).** Fieldset, Divider, Tabs, SegmentedControl, Listbox, Select, Combobox, Accordion, Slider (single and range), NumberInput, Popover. Decisions the tier fixed: one Listbox engine with `multiple` drives Listbox, Select and Combobox (multi-select chips in Combobox reuse it); `aria-activedescendant` keeps focus in the input for Combobox and the keyboard gate resolves it; SegmentedControl is a RadioGroup in tabs' clothing, not Tabs; Accordion composes Disclosure and keeps every trigger a tab stop; Slider and NumberInput are `adjustable` on native with increment/decrement actions as the gesture alternative; Popover is the non-modal sibling of Dialog and composes FocusScope. Schema gained a `behavior` block (given/when/then scenarios for a behavior gate). 300 contrast pairs, 0 failures; 34 keyboard specs. Second batch (same day): ProgressBar, Stepper, Toolbar, Carousel, Search, DatePicker — the last of which carries the first grid keyboard model (roving tabindex over a `role=grid`) that Tier 4 builds on. 44 components; 360 pairs, 0 failures; 44 keyboard specs. Icon gained `calendar`.

**Tier 4 — data (docs done 2026-09-10: Table, DataGrid, TreeGrid, Tree, Splitter, Feed).** Table (`role=table`, static content: sort, selection, sticky header, `responsive: stack | scroll`) and DataGrid (`role=grid`: one tab stop, `aria-activedescendant` over virtualized rows, in-place editors composed from the form controls, row/cell/range selection with TSV copy, pinned and resizable columns — a separate component because a grid's keyboard model contradicts a table's). TreeGrid extends DataGrid with `aria-level`/`setsize`/`posinset` over the flattened visible rows; Tree is the one-field-per-node sibling with type-ahead; Splitter is a focusable `separator` with a value; Feed follows the APG feed commands (PageUp/Down between articles, new items offered by a button rather than inserted). 50 components; 418 contrast pairs, 0 failures; 56 keyboard specs. Remaining from the APG list: none; the tier is documented. The tier's rule: every table role is stated explicitly on native elements, because CSS that changes `display` — which both responsive modes and sticky positioning do — strips the implicit roles. Rows are data, never children, so Lit can render them inside its shadow root and React Native can read them as a list.

| *(no APG entry)* | **ActionSheet** | 2 | Menu semantics inside a BottomSheet on touch; a Menu on desktop. One doc, platform mapping chooses. |
| Tooltip | Tooltip | 2 | Hover **and** focus on web, never hover-only; RN has no tooltip idiom — mapped to `accessibilityHint` plus a long-press popover, with a note that it is a degraded pattern. |
| Menu Button, Menu and Menubar | MenuButton, Menu, MenuItem | 2 | Full arrow/Home/End/typeahead model on web; RN maps to ActionSheet on touch. |

| Combobox | Combobox, Select | 3 | Select is the read-only Combobox; RN maps to a picker sheet. Autocomplete variants documented as props. |
| Tabs | Tabs, Tab, TabPanel | 3 | Automatic vs manual activation as a prop; RN `accessibilityRole="tab"` + `tablist`. |
| Toolbar | Toolbar | 3 | Roving tabindex across mixed controls; on RN it is a horizontal Stack with no extra semantics. |
| Accordion | Accordion | 3 | A Disclosure group with optional single-open behavior; headings inside are real Headings with `level`. |
| Slider, Slider (Multi-Thumb) | Slider, RangeSlider | 3 | RN `accessibilityRole="adjustable"` with `accessibilityActions` increment/decrement — the gesture-alternative is built in. |

| Carousel | Carousel | 3 | Auto-rotate must be pausable; swipe is a gesture event with visible prev/next as the alternative. |
| Table | Table | 4 | Static semantics only; RN has no table roles — documented as a list of rows with header text prefixed into each cell's label. |
| Grid, Treegrid | DataGrid, TreeGrid | 4 | Full 2-D arrow navigation; RN support is declared `supported: false` for the PoC with a documented reason. |

## Mobile patterns beyond the APG

Besides BottomSheet and ActionSheet above: **PullToRefresh** (a gesture event on a list; the alternative is a visible Refresh button, and on web it is not rendered at all), **SegmentedControl** (Tabs semantics with a compact look — one doc, a `variant`), **Pager/Swipeable views** (Carousel semantics), and **FAB** (a Button `variant` with a position rule, not a new component). Each is a variant or a documented mapping of an APG pattern rather than a new behavioral model, which keeps the accessibility story coherent across platforms.

## What this adds to the schema

The schema already gained what these tiers need: the `a11y.requires` vocabulary now includes `focus-trap`, `focus-restore`, `escape-dismiss`, `arrow-navigation`, `roving-tabindex`, `expanded-state`, `selected-state`, `live-region`, `reduced-motion`, `gesture-alternative`, and `landmark-role`; events can be marked `gesture: true`, and the parser refuses a gesture event unless `gesture-alternative` is declared (WCAG 2.5.1 and 2.5.7); the `apg` field links a component to its pattern; and categories `overlay` and `data` exist for tiers 2 and 4. Two things are still ahead: a `composition` block for components made of parts (Tabs → Tab, TabPanel; Menu → MenuItem), and a `keyboard` block that lists key → action pairs from the APG so the tables render on the site and the prompts include them verbatim. Both will be added at the start of Tier 2.
