# Gaps reported while generating DataGrid for lit

Each entry is a place the doc made the generator guess. Fix the doc, re-run parse, regenerate.

## 2026-09-10 14:08 — round 1

- DataGrid: platforms.lit.reflect names the showStatusBar attribute `show-status-bar` verbatim, but showStatusBar defaults to true — per the general 'booleans defaulting true reflect as a negated attribute' rule (and the Table.ts precedent for stickyHeader/`no-sticky-header`), I reflected it as `no-status-bar` instead so a static-HTML author can express false at all.
- DataGrid: stickyHeader is absent from platforms.lit.reflect's list entirely despite defaulting to true; I reflected it anyway as the negated `no-sticky-header` attribute (matching Table.ts) since height=viewport/fixed force it true and only height=content needs the toggle.
- DataGrid: the doc's Web/Lit platform notes describe composed editors (Input/NumberInput/Select/DatePicker/Checkbox) rendered with 'label visually hidden, size sm'; none of those Lit components expose a hideLabel or size prop (checked their actual @property lists), so the editor's label is visibly rendered at default size while a cell is being edited — there is no way to hide it without restyling the child's shadow tree, which the composition rules forbid.
- DataGrid: 'typing a character also opens it with that character' (Enter/F2 row of the keyboard block) is implemented only as 'typing opens the editor' — the typed character itself is not seeded as the editor's initial value, since forwarding a keystroke into five different composed field components' internal value/selection/cursor state isn't implementable generically without reaching into their internals.
- DataGrid: the Space row's own text is self-contradictory ('toggles the focused row' then, in the same bullet, 'Shift+Space selects the row' and 'Ctrl+Space the column in range mode'). I implemented: selectable=row → Space toggles the row (no Shift-range-extend, since the row's own bullet already claims Space alone does the toggle); selectable=range → Space selects the full-width 1-row range, Ctrl+Space selects the full-height 1-column range. This is a best-effort reading, not a literal implementation.
- DataGrid: resizable columns have no keyboard entry in the keyboard block (only pointer interaction is implied by 'draggable with the pointer and adjustable with arrow keys' in the Web platform note, which the keyboard block itself never lists as a key→action row). Per the instruction to implement keys 'exactly as listed and nothing else', resize is pointer-drag only; the separator is not independently focusable, so keyboard/screen-reader users cannot resize columns — flagging this as a real accessibility gap, not just an implementation shortcut.
- DataGrid: 'rowCount with onRangeNeeded lets the caller page in from a server' doesn't specify how a sparse/out-of-order window maps to `data` indices. I assumed `data` is always a contiguous prefix starting at index 0 that only grows by appending (never a sparse middle window), and fire `range-needed` when the virtualized scroll position approaches the end of the loaded prefix. Keyboard/PageDown navigation is clamped to loaded rows and does not itself trigger `range-needed`.
- DataGrid: pinned-column sticky offsets are computed among pinned columns only and ignore the selection checkbox column's width, so a pinned-start column combined with `selectable: row` will sit one checkbox-width off from the true visual left edge — a documented simplification rather than full sticky-offset arithmetic.
- DataGrid: 'activates it' for a body cell containing a Link/Button/Checkbox (via `column.render`) is implemented generically as `cellEl.querySelector('ds-button, ds-link, ds-checkbox, button, a[href], [role="button"]')?.click()`, since the doc gives no way to know the shape of a consumer's custom `render` output ahead of time; this may not correctly activate every possible control a consumer renders.
- DataGrid: the `position` copy ('Row {row}, {column}') is exposed as a single hidden `aria-describedby` span updated on every active-cell change, rather than announced through the polite live region on every arrow press (which would make the status-bar/live-region very chatty) — screen readers pick it up as part of the activedescendant cell's accessible description instead.
- DataGrid: Ctrl+A / Ctrl+C are bound via `event.key === 'a'/'A'`/`'c'/'C'`, which is US-QWERTY-centric; the doc doesn't specify a `code`-based binding, so this may not fire correctly on some non-Latin keyboard layouts.
- DataGrid: true drag-to-select for range mode is implemented only as click + Shift+click (anchor/extend), not a continuous pointermove-drag rectangle; the doc's 'Shift+arrow / drag rectangles' phrasing implies mouse-drag support that isn't built.

## 2026-09-17 14:20 — round 1

- DataGrid: the `statusBar` part is declared as a composed `Text` forwarding `statusBarSize`, but the web notes describe it as a div carrying `statusBarSurface`/`statusBarPadding`/`statusBarGap` with an inner `role="status"` span and sibling Texts beside it — one name cannot be both. Chose: `data-part="statusBar"` on the live `ds-text`, with the surface/padding/gap on an undeclared wrapper div, so three style bindings style an element that carries no `data-part`.
- DataGrid: `surface`, `pinnedShadow`, `rangeBackground`, `rangeBorder`, `rangeBorderWidth`, `resizeStep`, `fixedHeight`, `fontFamily`, `fontSize`, `lineHeight`, `numericFont`, `minTarget`, `focusRing`, `focusRingWidth` and `transition` declare no `part`. Chose: surface/font/line-height on the scroll region and `:host`, `focusRing*` on `scrollRegion` (it draws the ring while the inner grid is `:focus-visible`, per the web notes), `range*` on `rangeOverlay`, `pinnedShadow` on pinned cells, `resizeStep`/`columnWidth`/`minTarget` read as lengths from a hidden probe span so an override of the hook changes them.
- DataGrid: `selectColumnWidth` says the selection column is "this plus 2 × cellPaddingInline in the rule", but the select cell only centres a Checkbox and the contract gives Checkbox no inset overrides. Chose: `min-inline-size: size.target.min` with `padding-inline: 0`, so the `+ 2 × cellPaddingInline` is not applied and the column is exactly the minimum target.
- DataGrid: the doc never says whether `aria-rowcount` counts the header row. Since the header row is `aria-rowindex="1"` and body rows therefore start at 2, chose `aria-rowcount = (rowCount ?? data.length) + 1`.
- DataGrid: no glyph is named for the sort direction indicator. Chose `chevron-up`/`chevron-down` in a `trailing-icon` slot, matching Table's Lit sort header, and the direction cycle is ascending ↔ descending only — the doc never says a third activation clears the sort.
- DataGrid: `caption` is `required: true` with no default and no stated failure mode. Chose: default `''` plus a one-time `import.meta.env.DEV` warning; the same dev path warns when `isRowHeader` is not on exactly one column and when pinned columns are not contiguous, both doc rules with no stated enforcement. The Declared contracts only sanction dev warnings for deprecations, so these three are inventions.
- DataGrid: the lit notes say only `columns` and `data` are properties and the reflect list omits `rowCount`, `caption`, `emptyMessage`, `sort`, `defaultSort`, `selected` and `overrides`, leaving their attribute story unstated. Chose: `caption`, `row-count` (Number) and `empty-message` as plain non-reflected attributes; `sort`, `defaultSort`, `selected` and `overrides` as `attribute: false` properties.
- DataGrid: `selected` is listed as controlled but there is no `defaultSelected` and no `controls` block pairing it with `onSelectionChange`, so the uncontrolled behaviour of row selection is undefined. Chose: internal `@state` selection when `selected` is undefined, `selection-change` fired in both modes (matching the Controlled state rule for `sort`).
- DataGrid: the Tab rule says that from the last editable cell an open editor "commits and leaves the grid", which on the web platform means the editor must be gone before the browser resolves the default Tab. Chose: commit, focus the grid, then force a synchronous `performUpdate()` so the editor is removed in the same task. If `validate` rejects that last commit the key is swallowed and the editor stays open — the doc does not say which wins.
- DataGrid: Enter on a cell whose `render` contains a control says "focuses and activates the first focusable descendant" without saying how a custom element is activated or when focus returns. Chose: focus the element, then `click()` its inner native `a[href]`/`button`/`input` when it has a shadow root, with Escape handing focus back to the grid; `render`ed controls are demoted to `tabindex="-1"` after every update so the grid stays one tab stop, which the doc implies but never states.
- DataGrid: `columns[].render` is typed `(row: Row) => ReactNode` in the shape but the prose says a lit-renderable value on Lit. Used `(row: DataGridRow) => unknown` verbatim-incompatibly with the shape — `unknown` is the only type that accepts TemplateResult, string and number without importing React types.
- DataGrid: `copy.copied` and `copy.rowCount` must select a plural form with `new Intl.PluralRules(locale)`, but no locale source is named for a web component. Chose `document.documentElement.lang || undefined` (the runtime default).
- DataGrid: in `cell` mode the doc says selection follows focus and fires "on every move to a body cell", but does not say whether a pointer click on a body cell counts as a move. Chose: yes, fired when the clicked cell differs from the active one. Likewise `aria-multiselectable` is only defined by implication — chose `"false"` for `cell`, `"true"` for `row`/`range`, and omitted for `none`.
- DataGrid: Ctrl+C copies "with headers when whole columns are selected", which is undefined for a partially loaded set. Chose: the header line is written when the range spans every loaded row (`rowStart === 0 && rowEnd === rows.length - 1`), and `copy.copied` is announced only after `navigator.clipboard.writeText` resolves — a rejected clipboard permission announces nothing.
- DataGrid: `a11y.requires` lists `escape-dismiss`, but the component has no overlay or dismissible surface; the keyboard table gives Escape only "cancels the edit" and "clears a range selection". Implemented those two and let Escape bubble otherwise.
- DataGrid: `defaultSort` says the grid sorts `data` itself when `rowCount` is not set, but it does not say what a controlled `sort` implies. Chose: the grid sorts only when the sort is uncontrolled and `rowCount` is unset (a controlled `sort` means the caller has already ordered `data`, as Table).

## 2026-09-21 20:29 — round 1
