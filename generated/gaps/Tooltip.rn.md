# Gaps reported while generating Tooltip for rn

Each entry is a place the doc made the generator guess. Fix the doc, re-run parse, regenerate.

## 2026-09-10 02:27 — round 1

- Tooltip: the schema's own composition example (attach to a Button/Link/Input) can't actually work on RN — none of this package's Button, Link or Input forward unrecognized props, so the accessibilityHint/accessibilityLabel and onLongPress/onHoverIn/onHoverOut/onFocus/onBlur handlers Tooltip clones onto its child are silently dropped when the child is one of those three. They only take effect on a child that forwards extra props onto a native Pressable/TextInput (or a raw core RN element). Fixing this for real requires Button/Link/Input's own schemas to grow a passthrough or an accessibilityHint/description prop, which is out of scope for a single-file generation; I implemented the clone as specified and called this out prominently in the doc comment rather than silently shipping something that looks functional but isn't.
- Tooltip: RN has no generic hardware-keyboard event API, and the schema only says 'on native implement the subset hardware keyboards can reach' plus 'react-native-web ... hover and focus behave as on web' without specifying how Escape should be wired there. I gated a `window`/`keydown` listener to `Platform.OS === 'web'` (a real browser exists under react-native-web) and left true native with no Escape path, since the popup is never shown there. This is a judgment call, not a documented requirement.
- Tooltip: 'placement... flips when it would overflow the viewport' is not implemented for top/bottom. Unlike Menu's dropdown, the tooltip bubble isn't portaled or measured against the window, so there's no viewport rect to flip against without adding that machinery; placement is static (start/end still resolve against writing direction).
- Tooltip: the schema defines no `open`/`onOpenChange` prop (correctly — visibility is meant to be fully hover/focus/long-press driven), but the generic testability rule asks for a `Keyboard` story 'rendering it open'. There's no declarative way to force that without inventing a prop, and no interaction-testing package (`@storybook/test` or similar) is present in devDependencies to script it programmatically (adding one would violate the no-new-dependencies rule). The Keyboard story instead renders three tooltip-wrapped focusable triggers (satisfying the 'at least three focusable children' half) and documents that a reviewer must focus/hover/long-press a trigger to actually open it.
- Tooltip: the 'warm' toolbar grace window (how long a tooltip stays warm after hiding so the next sibling shows instantly) has no specified duration beyond the default-delay formula. I reused `motion.duration.base` as that window as a judgment call; the schema/web notes describe the behavior but not its length.
- Tooltip: 'the child must be focusable' (a11y requirement) and the `describes` semantics are accessibility contracts, not something checked at runtime — RN has no generic way to introspect whether an arbitrary subtree is focusable. Only a dev-mode warning verifies that exactly one child element was passed.

## 2026-09-16 06:00 — round 1

- Tooltip: the spec contradicts itself on native flipping. Guidance > Behavior says 'On native there is no viewport measurement, so top and bottom do not flip', but platforms.rn.notes and overlay.collision say it flips using measureInWindow. I followed the section and the rn notes: all four sides flip against useWindowDimensions, and the cross axis is clamped into the window.
- Tooltip: `open` is controlled but has no change event, and the keyboard rule says Escape closes the tooltip. I chose that Escape hides a controlled tooltip until the `open` prop next changes. This breaks 'a controlled component shows the new state only once the prop changes'; the doc should either add an open-change event or say Escape does nothing when controlled.
- Tooltip: the schema's `delay` description calls the warm window 'one motion.duration.loop' and the pointer grace 'motion.duration.fast', but `constants.warmWindow` says motion.duration.base. I used the constant (base).
- Tooltip: the rn notes say the bubble shows 'for the duration of the press' and the React Native guidance says 'until onPressOut'. Neither says what happens when a long-press ends while the trigger still has focus on react-native-web. I track press, hover, bubble-hover and focus separately, so the tooltip stays visible while any of them is active.
- Tooltip: there is no portal on native, so the bubble is absolutely positioned inside the Tooltip root with zIndex layer.toast. An ancestor with overflow hidden, or a sibling stacking context, can still clip or cover it. The doc doesn't say whether native should use a Modal or portal (Toast's 'portal-less View' rule suggests not). I stayed inline.
- Tooltip: hoverable-bubble (WCAG 1.4.13) on react-native-web needs pointer events on the bubble. I used View onPointerEnter/onPointerLeave with pointerEvents auto on web and none on native. The doc doesn't name the event API.
- Tooltip: the bubble is hidden from accessibility on native (accessibilityElementsHidden, importantForAccessibility no-hide-descendants, aria-hidden) because the trigger's hint or label already carries the text. The web anatomy's second copy, a visually-hidden role=tooltip node, has no rn equivalent in the doc, and the two role=tooltip behavior scenarios are web/lit only.
- Tooltip: the examples name glyphs the icon table lacks (`bold` for icon-only-button-name and warm-toolbar, a copy/link glyph for below-the-trigger). The stories use `plus`, `minus` and `external` as stand-ins; tools/icon-paths.json needs bold, italic and copy or link.
- Tooltip: the example givens describe children in prose ('A table column header Button', 'An icon-only Button inside a Toolbar') with no label text or Toolbar label. I wrote the story labels 'Items' and 'Formatting' myself; the examples should give them verbatim.
- Tooltip: the spec declares no ref, but the package rule says a component that exposes its root takes `ref?: React.Ref<ViewInstance>`. I added it on the root View.
- Tooltip: the Default story args use describes=false with an icon-only Button (the recommended use), while the schema default for describes is true. The doc doesn't say which one Default should show.
