# Gaps reported while generating Tree for rn

Each entry is a place the doc made the generator guess. Fix the doc, re-run parse, regenerate.

## 2026-09-10 14:28 — round 1

- No RN element expresses a11y.role 'tree'/'treeitem'/'group'; per the platform notes I used FlatList with accessibilityRole='list' and accessibilityLabel={label}, with per-row accessibilityState/accessibilityActions carrying expanded/selected/checked state instead.
- Anatomy's 'group' (nested container per open parent) has no separate wrapper: visible children are flattened into the single virtualized FlatList (matching the existing TreeGrid precedent) rather than rendered as nested per-parent group views.
- Arrow-key navigation, roving tabindex, Home/End, type-ahead, Shift+Arrow and Ctrl+A are web keyboard-model behaviors with no hardware-keyboard equivalent on most RN devices; only Enter-equivalent (tap to activate) and the always-visible expand chevron are implemented, with expand/collapse also exposed via accessibilityActions for assistive technology, per the 'implement the reachable subset' rule.
- In `multiple` mode the row has no outer Pressable — the composed Checkbox's own control and label are the entire hit target — so onActivate/href navigation is not reachable there (no native gesture distinguishes 'move' from 'select' the way Enter/Space do on web); activation only fires in `none`/`single` mode. Documented rather than adding a second overlapping touch target.
- Checkbox owns its own visible/accessible label, so in `multiple` mode the row's accessible name is the plain node label (no ', level N' suffix); the '{label}, level {n}' format from the platform notes is only applied in `none`/`single` mode where the row itself is a Pressable exposing accessibilityLabel.
- `selectOnFocus` (documented for `single` mode) is wired to the row Pressable's onFocus event, which fires for external-keyboard tab focus and assistive-technology (VoiceOver/TalkBack) navigation on RN/react-native-web — there is no separate 'move' input on touch, so this is the closest native analogue to the web behavior.
- href navigation combined with `selectable: 'multiple'` has no dedicated tap target (the row's only interactive area is the Checkbox, which toggles selection); href is only actionable in `none`/`single` mode via Linking.openURL.
- 'live-region' is implemented as the docs' explicit accessibility note describes: only `copy.selectedCount` announcements on selection change in `multiple` mode (AccessibilityInfo on iOS, a hidden polite-live-region Text on Android) — expand/collapse changes are conveyed via each row's own accessibilityState.expanded rather than a separate announcement, matching TreeGrid's existing precedent in this package.

## 2026-09-16 12:31 — round 1

- Tree: the rn notes ask for an `activate` accessibility action beside expand/collapse, but `activate` is a standard RN action name that takes over the screen reader's double-tap (it would stop the tap from toggling selection), and copy has no label for a custom action. Chose the standard `longpress` action (no label needed) in `multiple` mode, which calls the same handler as a long press, i.e. activation.
- Tree: what a tap does in `single`/`none` is not stated for rn (the web pointer model is click = Space, double-click = Enter; rn only says tap toggles and long press activates in `multiple`). Chose tap = Enter: activate (onActivate or href) and, in `single`, also select. In `none` a tap only activates; it does not toggle expansion.
- Tree: 'follows href' has no navigation target on native, and Link skips its own `Linking` call when given an `onPress` handler. The row opens `href` with `Linking.openURL` itself and passes Link an `onPress` that returns `false`, so a tap on the link text still selects and toggles like the rest of the row. There is no router hook for in-app hrefs like `/settings/account`.
- Tree: `fontFamily`, `fontSize` and `lineHeight` are overridable but have no part, and the parts contract lists only `fontWeight` as the label Text's forward ('add no other'). Chose to forward them to the label Text's overrides only when the caller sets them; defaults come from `Text size="sm"`.
- Tree: the `link` part cannot take `fontSize` (Link exposes only `transition`), and standalone Link uses font.size.md. Chose to nest the Link in a label `Text size="sm"` so it inherits the tree's size; the selected weight is not applied to it, as `labelSelectedWeight` describes.
- Tree: `checkboxBorder` (color.control.border) has no width binding. Chose border.width.thin, and the border takes checkboxSelected's color when checked or mixed so the fill has no contrasting edge.
- Tree: `rowSelectedBorder` is a start-edge bar, but whether it adds to layout width is unspecified. Drew it as an absolutely positioned View at the row's start so selecting does not shift the content.
- Tree: `rowHover` on touch. There is no hover on native, so the row uses it for both pressed and react-native-web hover; the selected fill wins over it. `transition` only animates the chevron: hover swaps instantly (the theme prefers no animation).
- Tree: `onExpand` says 'first time', but TreeGrid fires on every expand while children are still lazy so a failed load can retry. Followed Tree's spec: once per id per mount, tracked in a ref.
- Tree: the chevron color is unbound (`iconColor` is the node glyph's part). Chose color.foreground to match TreeGrid's chevron; the Button is left accessible, named with copy.expand/collapse, because rn calls it 'a real target' while web hides it.
- Tree: with `selectChildren`, whether disabled or lazy descendants cascade is unspecified. Chose loaded, enabled descendants only. A parent's own id counts toward mixed only when some but not all descendants are selected.
- Tree: the `Keyboard` story needs 'its trigger' but a Tree has none. Chose showLabel plus `docs` expanded, which gives expand buttons and several focusable rows.
- Tree: `*` (open all siblings) is listed for rn in the keyboard table but the notes say no arrow keys or type-ahead, and there is no touch equivalent or copy for an 'expand all' accessibility action (TreeGrid invents one). Not implemented on rn.
- Tree: the `container` and `group` parts have no rn element (groups are flattened into the list). The root View carries `testID="Tree"` and the FlatList has no anatomy testID; the has-accessible-name test finds it by `accessibilityLabel`.
- Tree: the `typeaheadReset` constant is unused on rn, since there is no type-ahead.
