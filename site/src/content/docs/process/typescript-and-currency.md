Two decisions, taken 2026-09-10, that change how the repository is built rather than what it builds.

The first is that TypeScript is the repository's language. The three packages already were TypeScript — every file in `packages/react/src`, `packages/lit/src` and `packages/rn/src` is `.ts`/`.tsx` under `strict: true` — but the pipeline that produced them was Python (`tools/*.py`, `mcp/*.py`) launched through a `tools/py.mjs` shim, and the token build had a Python fallback beside the Style Dictionary one. A contributor needed two toolchains to run `pnpm check`. **Workstream A finished 2026-09-12**: they need one. Node runs every tool from source, and `pnpm install` is the whole setup.

The second is currency. The packages are pinned to majors that are one to three behind: React 18 (19.3 is current), TypeScript 5.6 (7.0), Storybook 8 (10.6), Vite 5 (8.3), Vitest 3 (5.0), React Native 0.74 (0.87), Jest 29. A design system that advertises "generated for your stack" cannot ship types for a React the consumer no longer uses. The policy is: every dependency tracks its latest stable release, the upgrade is automated, and a CI job fails when anything falls more than one minor behind.

## Workstream A — port the pipeline to TypeScript

One tool per job, in dependency order, each job replacing a Python file with a `.ts` file that produces byte-identical output on the current docs before the Python file is deleted. The Zod schema in `schema/component.ts` becomes the single source of truth: `parse.ts` validates with it, and `schema/component.schema.json` is regenerated from it (`z.toJSONSchema`) so the two can never drift.

1. `tools/parse.ts` — YAML frontmatter → `generated/components.json`, prompts, the same `DocError` messages. Runs with `node tools/parse.ts` (Node 24 type stripping; `tsx` fallback for Node 22). **Done 2026-09-11**: byte-identical `generated/` on the current docs (593 files, stdout, exit code), then `tools/parse.py` deleted. The YAML the prompts embed is written by `tools/lib/pyyaml.ts`, a port of PyYAML's dumper, so the generation lock hashes did not move; `tools/schema.ts` derives `schema/component.schema.json` from the Zod schema (`pnpm schema`, checked by `pnpm check`); the tests are `tools/__tests__/*.test.ts` (`pnpm test:tools`).
2. `tools/check_contrast.ts` (+ `oklch.ts`) — same pairs, same numbers to two decimals. **Done 2026-09-11**: byte-identical stdout on the current docs (1284 pairs, 137,603 bytes), same exit codes (0, and 1 with the same stderr when `generated/components.json` is missing), neither run touches `generated/`; `tools/check_contrast.py` deleted. `oklch.ts` agrees with `oklch.py` over 5,963 hex colors and 10,615 OKLCH triples — every `oklch_to_hex` is character-identical and every number matches to two decimals (worst non-hue delta 7×10⁻¹⁶, one ulp; the hue angle of achromatic grays, where `C ≈ 10⁻⁸`, is the only place drift reaches 10⁻⁷ and it changes no output). `tools/oklch.py` stays until steps 4 and 6, because `tools/theme.py` and `mcp/server.py` still import it; the last Python copy of `expand()` moved to `tools/spec_sheet.py`, which step 3 deletes. The tests are `tools/__tests__/{check_contrast,oklch}.test.ts`.
3. `tools/keyboard_tests.ts`, `tools/lint_literals.ts`, `tools/behavior_tests.ts`, `tools/spec_sheet.ts`, `tools/checks.ts`. **The first three are done 2026-09-11**: the keyboard and behavior gates write byte-identical trees (211 files, 803,702 bytes) and the same stdout line on the current docs, and `lint_literals` agrees with the Python over every `.ts`/`.tsx`/`.css` file in the repository (723 files, 88 identical finding lines) plus `--platform`, `--files` and the argparse exit codes — the only stdout difference is that Python's Windows text-mode `print` ends lines with CRLF where the ported tools, like `parse.ts` and `check_contrast.ts` before them, write LF. `tools/lib/components.ts` is the `generated/components.json` reader the two gates share; `behaviorFor` and `accessibleNameProp` are now imported from `parse.ts` instead of being mirrored; `tools/lib/py.ts` gained `json.dumps`, `re.escape` and `sorted()` equivalents. Only after that did the three Python files (and their pytest modules) go, the generated headers flip to `.ts`, and `package.json` / `tools/checks.py` call the TypeScript tools. The tests are `tools/__tests__/{keyboard_tests,lint_literals,behavior_tests}.test.ts` (136 cases).

   **The last two are done 2026-09-11.** `tools/spec_sheet.ts` writes the same page byte for byte on all three built themes (275,327 / 275,493 / 276,369 bytes, 1,558 lines each; only line 7, the "generated by" marker, moves from `.py` to `.ts`), with the same stdout, stderr and exit code for `--theme`, an unbuilt theme, an unknown flag and `--help`. It takes `expand()` from `check_contrast.ts` — the last Python copy is gone — and `shadow_css` moved into `tools/lib/tokens.ts`. `tools/checks.ts` produces identical gate lines and exit codes for `--platform web|lit|rn` (with and without `--skip`) and the same argparse errors, and its gate table — name, argv and cwd — matches the Python's for all 30 platform × `--with` × `--skip` combinations, browser gates included. It resolves `pnpm`/`node` like `shutil.which` and the two remaining Python gates (`check_deps.py`, `check_modules.py`) like `tools/py.mjs` does; on Windows the argv goes through cmd.exe pre-quoted, because `pnpm` is a `.cmd` and the repository path has a space in it. `tools/checks.py` and `tools/spec_sheet.py` (and `tests/test_spec_sheet.py`) are deleted, `package.json`'s `check`, `spec-sheet` and `gates` scripts call the TypeScript, and `tools/generate.py` — the one remaining caller, ported in step 5 — reads the gates back from `node --import tsx tools/checks.ts --json` instead of importing the module. The tests are `tools/__tests__/{spec_sheet,checks}.test.ts` (42 cases).
4. `tools/theme.ts` — delete the Python token fallback; Style Dictionary 4 (`tokens/build.mjs`) is the only token build, extended with the Swift format the iOS plan needs. **Done 2026-09-11**: `node tools/theme.ts` writes a byte-identical `tokens/themes/` on the current docs (12 files, 66,985 bytes) with the same stdout text and exit code, after which the "generated by" marker in the three `$description` lines per theme flipped from `.py` to `.ts` — nine one-line changes, the only difference in the tree, and none of them in a resolved token (`$description` is a reserved key the flattener skips, so `generated/` does not move). Two libraries carry it: `tools/lib/jsonschema.ts` is the draft 2020-12 subset `schema/theme.schema.json` uses with Python `jsonschema` 4.26's messages, paths and error order (43 broken-frontmatter cases agree line for line; the one divergence is that YAML gives JavaScript a single number type, so a whole-number float reads back as `1` where Python's `repr` says `1.0` — visible only inside an out-of-range message), and `tools/lib/py.ts` gained `round()` (half to even, and the `ndigits` form), a `Map` case and an `indent` option for `json.dumps`. The `Map` matters: JavaScript hoists integer-like keys to the front of an object, so `space` and `font.size` would have emitted `"0"` before `"$type"`. `tools/theme.py` is deleted, and with it `tools/tokens.py`'s dist writers — `tokens/build.mjs` now emits the `names.{js,d.ts}` token-name contract (the same 197 names in the same order), and `pnpm themes` is `node tools/theme.ts && node tokens/build.mjs`. What is left of `tools/tokens.py` is the reader `mcp/server.py` imports, which step 6 deletes with it; `write_theme` already runs the generator as `node --import tsx tools/theme.ts`. That reader and its port, `tools/lib/tokens.ts`, agree exactly: dumped over all three themes × both modes — 1,182 resolved tokens with their `$type` and unresolved `raw`, plus `public_name` and `css_name` for all 197 public names — the two JSON dumps are the same 158,887 bytes once Python's Windows text-mode CRLF is normalised. The `names.{js,d.ts}` contract Style Dictionary now writes differs from the file the Python fallback wrote on line 1 only, the "generated by" marker. The tests are `tools/__tests__/{theme,jsonschema,tokens}.test.ts` (196 cases, the port of `tests/test_theme.py`, `tests/test_theme_derivation.py`, `tests/test_two_seed.py` and `tests/test_tokens.py`).
5. `tools/generate.ts` — the runner, lock files, gap capture, preflight; the PowerShell scripts call it unchanged. **Done 2026-09-12**: no model is needed to prove a generator, because everything around the model call is deterministic. Over the current docs the two versions agree on 22 command lines — stdout, stderr and exit code — including `--check` (153 stale of 156 targets), every argparse error, and `--dry-run` over every stale target (242,159 bytes of prompt heads); the full `task_prompt` + `fix_prompt` corpus for all 156 targets is the same 5,674,299 bytes; and a harness that drives the internals through a sandbox (both lockfile writers, the legacy-file migration, the abandoned-log rule, gap files, the `custom/` snapshot, report parsing, the retry schedules, `--adopt`, and 17 scenarios of the round loop behind a fake runner) produces the same 26,250-byte report line for line. `--help` differs only where it must: `generate.py` reads `generate.ts` and the six usage examples say `node tools/generate.ts`, as `spec_sheet.ts` did before it. Two things the language moved rather than changed. The gates are called in process (`runAll` from `checks.ts`) instead of through `node --import tsx tools/checks.ts --json`, and that bridge — the last cross-language call in the pipeline — is gone: on the real gates the preflight set and a verbose run print and return exactly what the subprocess version did. And the `api` runner asks for `@anthropic-ai/sdk` (an optional install, as `anthropic` was for Python) instead of the Python SDK; `tools/requirements.txt` loses its last non-MCP line. The one Python detail worth code: `json.dumps` spells a whole-number float `0.0`, so the lock writer keeps `costUsd` a float and the committed lockfiles do not move. `tools/lib/proc.ts` now holds the `shutil.which` and cmd.exe quoting `checks.ts` and the cli runner share, and `tools/lib/py.ts` gained `appendText` (text-mode append, which is how a gap file grows a round). `tools/generate.py` and `tests/test_generate_{lock,report,retry}.py` are deleted, `package.json`'s `generate` and `generate:check` call `node --import tsx tools/generate.ts`, and `generate.ps1`, `tier2.ps1` and `regen.ps1` run `node tools/generate.ts` with the same argv they built before (`run-jobs.ps1` never named the tool). The tests are `tools/__tests__/generate.test.ts` (84 cases — the three pytest modules, plus the command line and a `claude` process mocked at `spawnSync`, which the Python tests never reached).
6. `mcp/server.ts` on the official MCP TypeScript SDK; `mcp/index.ts`, `mcp/smoke.ts`. **Done 2026-09-12**: the gate is a transcript, and it matches byte for byte — `pnpm mcp:smoke` prints the same 7,315 bytes the Python smoke test printed on the same docs, and `pnpm mcp:index` the same 27 lines, ending `✔ 1609 chunks → mcp\.chroma`. The same 14 tools under the same names, the same JSON shapes and the same five resources, now registered with `@modelcontextprotocol/sdk` 1.30 (`McpServer` over `StdioServerTransport`, Zod 4 input schemas) and driven end to end by a real client over stdio. Three things had to be rebuilt rather than translated. **The embedding function**: an index is only the same index if the vectors are, so `mcp/lib/embed.ts` is a port of chromadb's `ONNXMiniLM_L6_V2` down to the archive it downloads, its SHA-256, the `~/.cache/chroma/onnx_models` directory it unpacks into, the 256-token window and the batch size — running the same `model.onnx` through `onnxruntime-node`. **The tokenizer**: that function calls Hugging Face `tokenizers`, which has no Node twin, so `mcp/lib/wordpiece.ts` ports the pieces the model's own `tokenizer.json` selects (`BertNormalizer`, `BertPreTokenizer`, the WordPiece model, `TemplateProcessing`, and the added-token split that runs before them). The two agree exactly: over a probe spanning Markdown, CSS, em dashes, accents, CJK, tabs and control characters, every token id is identical and every embedding matches Python's to six decimals. **The store**: there is no embedded Chroma for Node — the `chromadb` npm package is an HTTP client for a running server — so `mcp/lib/store.ts` reads and writes `mcp/.chroma/chroma.sqlite3` itself through `node:sqlite`, in ChromaDB's own format: `mcp/chroma-schema.sql` is that database's own DDL, dumped and replayed (28 objects, schema-identical), and the rows keep Chroma's encodings — `FLOAT32` little-endian vector blobs, the document under the `chroma:document` metadata key, decimal-digit `seq_id` blobs. What is not written is the `hnsw-local-persisted` segment directory beside it: an hnswlib binary plus a Python pickle, holding an *approximate* nearest-neighbour index over the same vectors. At 1,609 chunks the server scans them exactly instead, which is faster than building the graph and strictly more accurate than querying it — and the identical transcript is the proof that no ranking moved. (Foreign keys stay off while writing, as Python's sqlite3 leaves them: `segments.collection` references a table Chroma's own DDL spells `collections`.) The chunker is a straight port and provably so: dumped side by side, all 1,609 chunks — ids, metadata and text — are the same 4,384,425 bytes. `tools/lib/tokens.ts` gained `camelName` (the `{slot}` bindings `lookup_code` reports are not in the built name contract, so it needs the function rather than the table) and `tools/lib/pyyaml.ts` a `width` argument, which is what `write_theme`'s `safe_dump(..., width=1000)` wanted. The one known divergence is the float rule the earlier steps already carry: `check_contrast`'s `required` reads `3` where Python wrote `3.0`, on the large-text levels the smoke test does not exercise. Deleted: `mcp/server.py`, `mcp/index.py`, `mcp/smoke.py`, and the two modules that survived only for them — `tools/tokens.py` and `tools/oklch.py` — with `tests/test_mcp_index.py`, `test_mcp_server.py`, `test_mcp_tools_extra.py`, `test_tokens.py`, `test_oklch.py`, `test_docs.py` and `tests/helpers.py`. The tests are `mcp/__tests__/{index,server,tools,wordpiece}.test.ts` (148 cases — the three pytest modules, plus the tokenizer, which was a library call before and is code now); `vitest.config.ts` runs `mcp/__tests__` alongside `tools/__tests__`, `tools/tsconfig.json` type-checks `mcp/`, and the token half of `test_docs.py` moved into `tools/__tests__/docs.test.ts`. `tools/requirements.txt` has nothing left to install.
7. Remove `tools/py.mjs`, `tools/requirements.txt`, `tools/__pycache__`; `package.json` scripts call `node tools/<name>.ts` directly. **Done 2026-09-12**: the three tools the earlier steps left behind because nothing blocked on them — `check_deps.py`, `check_modules.py` and `gap_digest.py`, standard library only — are `tools/check_deps.ts`, `tools/check_modules.ts` and `tools/gap_digest.ts`, and they agree with the Python over every code path: the same stdout and exit code for `check_deps` with no flags and each `--platform`, for `check_modules` on all three platforms with and without `--no-typecheck` (the typechecking path included, which compiles the shipped `custom/analytics.ts` against its stub), and for `gap_digest` with and without `--phase` — including the digest itself, byte for byte over the 55 files in `generated/gaps/` once the "Generated \<now\>" line is normalised. Deleted: `tools/py.mjs`, `tools/requirements.txt`, `tools/__pycache__`, the three `.py` tools, `pytest.ini` and the last four pytest modules (`conftest.py`, `test_check_deps.py`, `test_check_modules`'s home in `test_extensions.py`, `test_gap_digest.py`). ## Workstream B — bring every dependency current

Order matters because each step's gate is the previous step's toolchain.

1. **Runtime floor**: `engines.node >= 22`, `packageManager: pnpm@<latest>`, `.nvmrc`. CI installs from `packageManager`.
2. **Dev tooling**: Storybook 10 (`npx storybook@latest upgrade` across the three packages and `storybook/`), Vite 8, Vitest 5, Playwright latest. Stories keep CSF3; the Lit package moves its browser tests to the Vitest browser provider.
3. **React 19** in `packages/react` and the RN package's dev tree: `npx types-react-codemod@latest preset-19 ./packages`, remove `forwardRef` (generated components take `ref` as a prop), peer range `react: ^19`. Regeneration is not needed — the typecheck gate proves the codemod.
4. **React Native 0.87** (+ react-native-svg latest, Jest 30 with the RN preset — RN's test renderer still wants Jest, so the RN package keeps Jest and the others keep Vitest), Expo SDK matching 0.87 for the gallery app (job 130).
5. **TypeScript 7** for `tsc --noEmit` everywhere, `tsdown` with `isolatedDeclarations: true` for builds (every exported symbol gets an explicit type — the generator templates already require typed props), tsconfig cleanup: remove `experimentalDecorators`, `useDefineForClassFields`, `baseUrl`; add `verbatimModuleSyntax`, `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`. Lit decorators go standard: `@property() accessor label = ''`.
6. **Publish checks**: `publint` and `@arethetypeswrong/cli` in `release:check`; the `exports` map gets `"default"` conditions.

## Workstream C — stay current automatically

- `renovate.json` extends `config:best-practices` with `rangeStrategy: "bump"` and lockfile maintenance; minor and patch updates automerge (`automergeType: "pr"`) once CI is green; majors are grouped weekly (one PR per ecosystem: react, storybook, vite+vitest+playwright, typescript+tsdown, react-native+expo+svg, lit) so a breaking change arrives with its friends.
- CI job `currency`: `pnpm outdated --recursive --format json` is parsed by `tools/currency.ts` (run directly by Node's type stripping, no build step) and the job fails when any dependency is more than one minor behind its `latest` tag. Exceptions live in `.currency-allow.json` as `{ "name", "until": "YYYY-MM-DD", "reason" }` entries, and an entry past its `until` date fails the job on its own; `node tools/currency.ts` gives the same report locally.
- CI job `next` (`continue-on-error: true`): copies the workspace to a temp directory, installs `react@canary`, `typescript@next` and `storybook@next` there, runs typecheck and the package tests, and writes the outcome to the job summary — so the day a major lands the breakage is already known.
- Templates and conventions carry the versions as facts, not aspirations: `prompts/templates/*.md` say "Storybook 10 CSF3", "React 19 (`ref` prop)", "TypeScript 7 isolatedDeclarations". Job 260 rewrites those lines; the next regeneration then emits current idioms.

## Risks and how they are contained

TypeScript 7 has no programmatic API until 7.1, so anything that embeds the compiler must resolve `@typescript/typescript6`; pnpm lets two majors coexist and `tsdown`'s isolated declarations avoid the API entirely for our own builds. React 19 removes `forwardRef` idioms the generator once emitted; the codemod plus typecheck covers it, and the templates stop emitting them. React Native 0.87 pins React 19.2 while `packages/react` moves to 19.3; the workspace tolerates that because RN is its own package with its own dev tree. Storybook 10's CSF factories are optional; stories stay CSF3 until the generator is asked to change. The Python port is the largest workstream; doing it tool by tool with byte-identical output as the gate keeps the regeneration scripts runnable throughout.
