- BottomSheet: hideTitle has no effect in the wide/Dialog presentation, since Dialog's schema has no hidden-title mode and the rule forbids restyling/reaching into composed children. The title is always visible there.
- BottomSheet: overrides (the per-instance token hooks) only apply to the bottom-edge presentation; above the breakpoint the sheet renders as Dialog, which has its own distinct overridable-binding set, so BottomSheet overrides are silently unused in that mode. Not stated in the doc.
- BottomSheet: a11y.requires lists target-44px, but the close button is a composed Button, whose schema only exposes size sm/md/lg (no 'comfortable target' variant), and the rules forbid restyling a child's internals. Used size="md" (the largest available) but can't guarantee the rendered target actually reaches 44px — the gap is in Button's schema, not something this generator can fix without growing it.
- BottomSheet: the exit token's description says a drag dismiss 'continues at the drag velocity'; implemented the standard exit transition (same as a non-drag close) instead of momentum-preserving physics, since the schema gives no numeric spec for how velocity should map to animation.
- BottomSheet: the wide/narrow breakpoint is read at runtime via getComputedStyle(--layout-max-width-prose) rather than hard-coded, so it can't reflect a per-instance overrides.maxWidth (that hook only exists on the mounted sheet element, which doesn't exist yet when the presentation decision is made).
- BottomSheet: schema has no initialFocus prop (unlike Dialog), so default focus-on-open always targets the first focusable body control, falling back to the close button — this mirrors Dialog's 'first' default but isn't explicitly specified for BottomSheet.

- BottomSheet: the handle is anatomy but its presence isn't specified when the gesture is off. I render it only when `dragToDismiss && dismissible`, so there is no drag affordance where dragging does nothing. The SwiftUI notes always show the drag indicator.

## 2026-09-17 10:54 — round 1

- BottomSheet: web notes say the wide presentation uses a CSS media query `(width > <resolved token>)` marked literal-ok, but React has to choose between Dialog and the sheet in JS. I read `--layout-max-width-prose` from the loaded theme at runtime and pass it to `matchMedia`. Without a token stylesheet (jsdom, SSR) it always renders the sheet.
- BottomSheet: the `dragSlop` constant is a token (`space.1`) used as a pixel distance, but the doc doesn't say how to turn it into a number. I parse the computed `--space-1` on the surface. If the token isn't loaded, the slop is 0 and any downward move starts the drag.
- BottomSheet: 'holds the release position until the consumer's update renders' doesn't say what happens if the consumer updates `open` asynchronously, after the next render. I check `open` on the render that follows the drag dismiss (the consumer's `setState` in `onClose` is batched into it). If it's still true, the sheet springs back straight away.
- BottomSheet: it isn't clear whether the slide-in translate counts from where the pointer went down or from where the slop was passed. I translate by the full distance from pointer-down, so the sheet jumps by the slop when the drag starts.
- BottomSheet: the `scrim` part could be `::backdrop` or a real element. Web notes say only 'the same native <dialog> as Dialog', and the `click: scrim` scenario needs something to click. I used a real `data-part="scrim"` element inside the dialog, as the current Dialog does, and made `::backdrop` transparent.
- BottomSheet: the `inset` binding covers inline padding and the last part's bottom padding, but not the header top when there's no handle or the body's own padding. Body inline padding sits on a scroll wrapper around `Box inset="none"`, not in Box's overrides, and bottom padding plus the safe area sits on the surface.
- BottomSheet: `footerGap` is forwarded to the footer Stack's `overrides` and also through the `--ds-stack-gap` hook in CSS (the Dialog pattern), so a consumer setting `--ds-bottom-sheet-footer-gap` in their own CSS still reaches the Stack. The spec doesn't say whether the CSS hook route counts as restyling a child.
- BottomSheet: in the wide presentation `container` is passed through to Dialog. The Guidance list of props forwarded to Dialog doesn't name `container` or the other `<dialog>` HTML attributes.
- BottomSheet: `overlay.layer` is `sheet`, but the wide Dialog keeps its own `layer.dialog` unless a `layer` override is passed. The spec doesn't say whether the wide presentation should switch to `layer.sheet`.

## 2026-09-21 08:50 — round 1

- BottomSheet: the footer composition lists exactly `direction: horizontal` and `justify: end`, and the contract says add no other prop, so I dropped the `wrap` Dialog passes its footer Stack. On a phone-width sheet a footer whose actions do not fit now overflows horizontally instead of wrapping. Say whether the footer Stack wraps — this is a phone-first overlay, so it probably should.
- BottomSheet: no heading level is stated and there is no `headingLevel` prop; the guidance calls the heading's id/ref/tabindex wiring but never its level. Chose `level="2"`, as Dialog does.
- BottomSheet: `FocusScope` writes its own `data-part="scope"`, exactly like Button/Heading/Stack, but the web notes list only heading/closeButton/footer as sheet-owned wrappers. I wrapped FocusScope in a sheet-owned `data-part="focusScope"` div (Dialog's pattern); say so, or the `focusScope` part hook does not exist on any platform whose FocusScope names itself.
- BottomSheet: `inset` puts inline padding on the body Box, but Box's own contract is that it never scrolls, and the body must scroll. So the sheet owns an unnamed scroll element between `surface` and the `body` Box. The doc never mentions it, which means `partGap` is really the gap between header, that wrapper and footer. Either name the scroll element in the anatomy or state that the body part is wrapped.
- BottomSheet: the doc covers Escape, the close button, the scrim and the drag, but not a close the browser initiates on its own — a repeated Escape reaching the close watcher closes a native <dialog> with no `cancel` event at all. I mirrored Dialog: report `escape` once and re-`showModal()` unless the consumer set `open` false. Web/Lit only; worth stating since `open` is controlled-only and a silently-closed sheet would desync.
- BottomSheet: `dragSlop` says to read `--space-1` and convert rem to px, but does not say what to do if a theme resolves `space.1` to px or a unitless number. I multiply only rem/em by the root font size and take px/unitless verbatim, with 0 for an unresolvable value as documented.
- BottomSheet: the drag is unreachable in the Vitest suite — this jsdom has no PointerEvent, so `clientY` never arrives, and because every NaN comparison is false the slop check passed and the surface got `translateY(NaNpx)`. I now require a finite `clientY` before the gesture claims. The drag scenarios can only be proven in a browser; the doc should either add a browser-level scenario for the gesture or say the gesture is out of scope for the unit gate.
- BottomSheet: velocity is defined as the measurement between the last two move samples, but a drag with a single `pointermove` before release has no pair. Chose velocity 0, so distance alone decides. Same question for a release whose last two samples share a timestamp.
- BottomSheet: `dismissDistance` is a fraction of the sheet height, which is intrinsic at `height: content`. I measure the surface's live `getBoundingClientRect().height` at release rather than the configured height; say which, since for `full` the two differ by the gutter.
- BottomSheet: a release past the threshold while `open` has already gone false (a close raced the gesture) is unspecified. I treat it as a spring-back and fire neither `onDragDismiss` nor `onClose`, so a dismissed sheet never reports a gesture it did not cause.
- BottomSheet: the overrides contract does not warn that the sheet's own hooks stop applying above the breakpoint. Consumer CSS on `--ds-bottom-sheet-*` silently does nothing in the wide presentation except through the ten forwarded bindings, because the root is Dialog's `<dialog>` with Dialog's hooks. Worth one sentence in the overrides section.
- BottomSheet: `dismissible: false` reports `escape` on every press with no state change, and the doc does not say whether repeats should be throttled or announced. Not throttled.
