Build the behavior gate: turn each component's `behavior` scenarios (generated/components.json, produced by tools/parse.py — authored plus derived) into runnable tests per platform, the way tools/keyboard_tests.py turns the `keyboard` block into Playwright specs. Read tools/keyboard_tests.py, tools/checks.py, one existing *.test.tsx under packages/react/src and packages/rn/src, and the Lit test setup under packages/lit, before writing anything.

1. tools/behavior_tests.py → writes generated/behavior/<Name>.<platform>.test.ts(x). Web and RN: Vitest + Testing Library (React / React Native); Lit: the package's existing test runner. Map `given` to props (Lit: attributes/properties), `when.click: <part>` to a click on the element found by the part's role or a `data-part="<part>"` hook, `when.key` to userEvent.keyboard, `when.type` to typing into the field, `then.event` to a spy on the platform event name from events.<name>.platforms, `then.state` to aria-*/accessibilityState, `then.focusable`/`focused`, `then.text`, `then.copy` (resolved through the component's copy table with {label} substituted from given), `then.role`/`name`/`attribute`, `then.renders`. Scenarios with `platforms` are emitted only for those platforms. Emit `test.skip` with the reason for any assertion the mapping cannot express rather than a false pass.
2. Add `data-part="<anatomy part>"` to the testability conventions in prompts/conventions/{web,lit,rn}.md (RN: `testID="<Name>.<part>"`) so newly generated components expose their parts; note that older components lack it.
3. Wire a `behavior` gate into tools/checks.py (opt-in via --with behavior like keyboard) that runs tools/behavior_tests.py then `pnpm --filter @design-schema/<pkg> test -- generated/behavior/<Name>.<platform>` (add the `test` script to each package if missing, with the necessary devDependencies pinned; do not upgrade anything already installed). Add `gates:behavior` to the root package.json.
4. Unit tests in tests/test_behavior_tests.py in the style of tests/test_keyboard_tests.py: given a minimal component entry with two scenarios, the generated file contains one `test(` per scenario, the right event name per platform, `test.skip` for an unmappable assertion.

Run `pytest -q` and, for one component that already has the hooks (Checkbox on web), `node tools/py.mjs tools/behavior_tests.py` followed by the package test command, and report what passes and what fails and why. Do not modify anything under packages/*/src or generated/ by hand.
