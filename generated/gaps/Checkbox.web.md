## 2026-09-20 22:12 — round 1

- Checkbox: the Events section declares onChange with exactly one positional argument (checked: boolean), but the repo's generated behavior suite asserts onChange(checked, expect.anything()) — a trailing event argument. I followed the spec (one argument), so 6 of the 16 generated web scenarios fail. Systemic, not Checkbox-specific: Button, Input, RadioGroup, SegmentedControl, Slider, Stepper and Switch all carry the same expectation and Switch fails identically without being touched. The doc and the test emitter need to agree on whether React event callbacks take a trailing event.
- Checkbox: `disabled` says 'Cannot be toggled and is not submitted', but the same doc (and the rules) require aria-disabled rather than the native `disabled` attribute so the control stays focusable. A native HTML <form> WILL submit a disabled-but-checked box's `value`, because only the native attribute excludes it. I kept aria-disabled and preventDefault in click+change (accessibility wins); native form submission of a disabled checked box is not prevented. The doc should say so, or say to also render the native attribute.
- Checkbox: the minTarget binding describes the control's vertical placement as an offset of (labelSize × lineHeight − controlSize) / 2 from the top of the text column, which reads as a margin — forbidden by the package convention that spacing is never a margin. I realised the identical geometry without one: the box is `block-size: calc(labelSize * lineHeight)` with `place-items: center`. Worth stating the intended mechanism, since Switch (cited as the model) uses a slot element instead.
- Checkbox: minTarget is locked but labelSize, lineHeight and controlSize — all read by the row's padding calc — are overridable. An override making labelSize × lineHeight exceed minTarget produces a negative padding-block and a row shorter than the locked minimum target. The doc doesn't say to clamp; I left the calc verbatim. It should either specify max(0, …) / a max() on the row height, or lock labelSize and lineHeight.
- Checkbox: pressedOverlay's token is opacity.disabled, the same token as disabledOpacity, so a pressed unchecked box is tinted at exactly the disabled opacity. That reads like a placeholder rather than a decision — the theme has no opacity.pressed. I used it verbatim; confirm it is intended.
- Checkbox: the error-slot order is `error`, then the Form's message, then the invalid-derived copy — but the Form contract also says the Form marks a failing field only by setting `invalid`, and React's Form cannot set a prop on a child. I read the Form's message from FormContext `errors[name]`, which is the only channel that exists. The doc should name that channel rather than describing a prop the React Form never sets.
- Checkbox: with both `indeterminate` and `checked` true the doc doesn't say which glyph wins — the mixed dash or the check. I made mixed win for both the indicator and aria-checked, since the submitted value still follows `checked` regardless.
- Checkbox: the focusRing binding specifies an outline of focusRingWidth in focusRing but says nothing about outline-offset. I used outline-offset: focusRingWidth to match the rest of the package; an offset of 0 would let the ring sit on the control's own border.
