# Gaps reported while generating Accordion for lit

Each entry is a place the doc made the generator guess. Fix the doc, re-run parse, regenerate.

## 2026-09-10 10:16 — round 1

- Accordion: the `items[].content: ReactNode` shape doesn't map to Lit; per the doc's own note ('content is the panel body — a slot per item on Lit') I dropped `content` from the Lit `AccordionItem` interface entirely and instead document that each item's panel content is a light-DOM child slotted by the item's `id` (e.g. `<div slot="faq-1">…</div>`).
- Accordion: `open-change`'s `reason` enum includes `keyboard` (distinct from `trigger`), but the only signal Accordion receives is Disclosure's `toggle` CustomEvent (`{ open }`), which doesn't distinguish a keyboard-activated click from a pointer click. I always report `reason: 'trigger'` for toggles that originate from a disclosure's own trigger and never emit `keyboard`; producing it would require Disclosure to forward the activation method in its own event detail.
- Accordion: `divided` defaults to `true` and is a plain (non-negated) reflected boolean attribute, per the schema's explicit `platforms.lit.reflect: [exclusive, divided, heading-level]` list, which names it `divided` rather than a negated form. This follows the precedent already in this package (`Toast`/`BottomSheet`'s `dismissible`, also true-default and reflected as-is) rather than the general package-conventions rule that would rename true-default booleans to a negated attribute (e.g. `no-divide`) — I judged the schema's explicit reflect name and existing precedent as more authoritative than the generic rule for this one prop.
- Accordion: nothing in the schema states how `value`/`defaultValue`/`items[].id` identify a slotted `<ds-disclosure>` — I used the light-DOM element's standard `id` attribute (also used as the generated element's `id` in `items` mode), since Disclosure has no other identifying prop. Consumers must give every `<ds-disclosure>` child a unique `id` for controlled state, events and keyboard nav to work; I added a dev-mode warning for a missing one.
- Accordion: when `exclusive` and no section is open, `toValue()`/the controlled `value` type collapse to `''` (empty string) rather than `undefined`, since the doc types `value` as `string | string[]` with no explicit 'none open' representation under the single-string (exclusive) case — flagging the choice since a consumer expecting `undefined` for 'nothing open' would need to check for `''` instead.

## 2026-09-10 18:36 — round 1

- Accordion: `value`/`defaultValue` shape is `string | string[]` but the doc never states the empty/none representation for non-exclusive mode; treated an empty array (or empty string) as "nothing open" and `''` as the exclusive empty case in `toValue`/`toIdSet`.
- Accordion: the `items` prop's shape omits `content`'s Lit-specific representation beyond 'a slot per item on Lit'; implemented each item's panel content as a slot named after the item's `id`, requiring light-DOM `<div slot="id">` siblings alongside `items` — not spelled out in the schema, only inferable from the platform note.
- Accordion: keyboard spec lists Enter/Space to toggle under `from: first` but the trigger is a native `<button>`, so Enter/Space activation is free via the browser's native click synthesis — no explicit handler needed; noting this since the derived keyboard tests may expect an explicit listener to exist.

## 2026-09-16 09:00 — round 1

- Accordion: on Lit, 'Dividers are direct siblings of the items' cannot hold for light-DOM <ds-disclosure> children without inserting nodes into the consumer's markup; chose manual slot assignment (one slot per disclosure) with <ds-divider> rendered between the slots in the shadow root, so the item stays the Disclosure root but the divider is not its light-DOM sibling.
- Accordion: the Lit notes say to set 'the padding override' on each slotted ds-disclosure, and the web notes pass overrides={{ triggerPaddingBlock: 'space.md' }}, but the accordion's own triggerPaddingBlock/fontFamily/triggerFontSize/triggerFontWeight are overridable hooks; chose forwarding each into Disclosure's documented --ds-disclosure-* hooks from the accordion's hook (a TokenRef in `overrides` cannot carry a consumer's CSS override of the hook).
- Accordion: divider/dividerWidth have no `part` and no named Divider binding to forward to; mapped them to ds-divider's `color` and `thickness` hooks.
- Accordion: the doc gives no timing order for the events; chose change first, then open-change for the toggled section, then one open-change(false, 'exclusive') per section it closed, matching the web implementation.
- Accordion: Disclosure reports 'pointer' | 'keyboard' | 'controlled', while Accordion's reasons are 'trigger' | 'keyboard'; mapped pointer→trigger and ignored Disclosure's 'controlled' (it is the echo of the accordion setting `open`).
- Accordion: the doc doesn't say whether a slotted disclosure's own composed `toggle` should still reach the page; it is left untouched for light-DOM children (the consumer owns them) and stopped for disclosures rendered from `items` (internal, replaced by change/open-change).
- Accordion: with `items`, the body is a child with slot=<id>; the doc doesn't say what happens to light-DOM children that are neither a ds-disclosure nor slotted by an item id (they are not rendered), nor whether changing a child's `slot` attribute later must be observed (only childList changes are).
- Accordion: a controlled `value` that ignores a user toggle leaves the emitted set pending until the next `value` change; the doc doesn't say how long 'did not itself just emit' lasts.
- Accordion: the doc doesn't say whether arrow keys work from a focused disabled trigger (still a tab stop); they do, and disabled items are skipped as targets, including Home/End.
- Accordion: Accessibility says 'Targets meet 44px in the accordion form', but minTarget is locked to size.target.min and Accordion may not restyle Disclosure; only the space.md padding raises the row, so 44px is not guaranteed.
- Accordion: Disclosure's trigger is inline-flex, so the hit area ends at the summary text rather than spanning the row; the spec doesn't say whether accordion triggers span the row, and it would need a Disclosure prop.
- Accordion: the `list` anatomy part has no stated element; put data-part="list" (and part="list") on the shadow root's flex container.
- Accordion: toggling `exclusive` on while several sections are open silently trims the set to the first id; the doc covers only value/defaultValue, so no open-change is reported for the sections that close.
- Accordion: the scenario `click: trigger` doesn't say which trigger; tests use the first, with Default args (nothing open) expecting change({ openIds: [firstId] }) and open-change({ id: firstId, open: true, reason: 'trigger' }).

## 2026-09-17 12:04 — round 1

- Accordion: `exclusive` says turning it on 'trims the open set to the first open id' but not whether 'first' means first in item order or first in the open set (open order / the `value` array); chose the open set's order, matching the stated equivalence with several ids in `value`/`defaultValue`.
- Accordion: behavior says sections closed by `exclusive` are reported 'in item order', but no order is given for the several per-section `open-change` events of a `reason: 'controlled'` `value` change; chose item order too.
- Accordion (lit): the accordion always sets `open` on slotted `<ds-disclosure>` children, so a consumer's `open` / `default-open` attribute on a slotted disclosure is overridden by `value`/`defaultValue`; the doc does not say whether a child's own open state should seed the accordion's set. Kept `value`/`defaultValue` as the only source.
- Accordion (lit): with the accordion setting `open`, each slotted disclosure that `exclusive` or a `value` change opens or closes fires its own composed `toggle` with `reason: 'controlled'`, which the notes leave to reach the page; the doc does not say a consumer listening for `toggle` on slotted children will see these echoes as well as the accordion's `open-change`.
- Accordion: `exclusive` 'turned on later while `value` holds several ids' trims silently, but the doc only asks for the development warning when `value`/`defaultValue` itself holds several ids under `exclusive`; no warning is emitted for the toggle-on case.
- Accordion: the `divider`/`dividerWidth` bindings have no `part` (they are forwarded to Divider), and `fontFamily` has no `part` although it is forwarded to the trigger like the other three; `Style bindings` therefore lists only four of the seven overridable bindings. Implemented all seven as hooks per the Lit notes.

## 2026-09-21 14:30 — round 1

- Accordion: story parity is keyed by React export name (tools/docs_examples.ts matches `stories.lit` to the React story), so every Lit story must go through the `items` property to keep React's args — which leaves the component page with no Lit snippet of the light-DOM `<ds-disclosure>` form the Lit platform notes call the primary one. There is no way to express the slotted form as a same-named, same-args story; covered it in Accordion.test.ts instead.
- Accordion: the Lit `Keyboard` story previously used a bespoke slotted render with no args, which contradicts parity (React's is `{ args: { items: ITEMS } }`). Changed it to match, which moves the generated keyboard gate from the slotted form to `items` mode. Both modes are now tested in Accordion.test.ts, but the doc should say which form the keyboard gate is meant to exercise.
- Accordion: the emitted event name `change` collides with the composed native-style `change` that bubbles out of form fields inside panels — the doc's own `form-sections` example puts fields in panels with `keepMounted`. A consumer listening for `change` on `<ds-accordion>` also receives `<ds-input>`'s `change`, whose `detail` has no `openIds`. The doc gives no disambiguation rule; I left both to reach the page rather than swallowing a consumer's event. A Lit-specific emitted name (e.g. `open-ids-change`) would fix it.
- Accordion: Behavior says to address an item as `[data-ds="Accordion"] > [data-ds="Disclosure"]` (Lit: `ds-accordion > ds-disclosure`), but that only holds for the slotted form. With `items`, the accordion renders the disclosures into its own shadow root, so neither selector matches from the document. The doc should state the `items`-mode address separately.
- Accordion: a disabled section's trigger is `aria-disabled`, not `[disabled]` (Disclosure keeps it focusable and a tab stop, which the doc requires). The generated keyboard gate's FOCUSABLE selector is `button:not([disabled])`, so a disabled trigger still counts as a focus index there — the `from: first` / `from: last` index math in a story containing a disabled item would target it. The doc should say the keyboard story must have no disabled sections (the current `Keyboard` args satisfy this, but only by accident).
- Accordion: no React story covers `defaultValue`, so the parity rule leaves the prop without a story on any platform. I dropped the Lit-only `WithDefaultValue` story, since a Lit story with no React counterpart never surfaces on the docs page — but that also drops its Chromatic baseline. If `defaultValue` should be shown, it needs a React story first.
- Accordion: the doc does not say what happens when the `items` array is replaced while sections are open and the new array drops those ids. Stale ids stay in the uncontrolled open set (and in `renderedIds`, so a later `value` diff still sees them) until the next toggle; they simply match no section. Chose not to prune, since pruning would need an `onChange` the doc does not describe.
- Accordion: `divider` and `dividerWidth` still appear under Overridable but not under Style bindings (they have no `part`, being forwarded to Divider), and `fontFamily` has a `part` of `trigger` while `divider`/`dividerWidth` have none — so the two sections disagree on how many overridable bindings exist (5 vs 7). Implemented all seven as `--ds-accordion-*` hooks per the Lit notes.
- Accordion: `keepMounted` is implemented with `reflect: true` on the `keep-mounted` attribute, although `platforms.lit.reflect` lists only `exclusive`, `no-divided` and `heading-level`. Kept the existing behaviour (it matches Disclosure's own `keep-mounted`), but the reflect list should either name it or the reflection should go.
- Accordion (repo hygiene, not a doc gap): `packages/lit/src/AccordionTmpSlotted.test.ts` is a committed scratch file (fixed `setTimeout` sleeps, `innerHTML` setup). Its coverage is now in Accordion.test.ts's `ds-accordion with slotted disclosures` block; it should be deleted. git is read-only in this job, so I left it in place.
